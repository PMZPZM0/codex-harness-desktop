## 两仓同步要点（本轮踩到的）

1. PPcode 落后不止一轮：除本轮 93 个文件，还要补 `update-splash.ts`、`gh-mirror.ts`、
   `06-app-behavior/part-05.mjs`、`vite-env.d.ts` 手写区。
2. 目录名是品牌面：覆盖主仓文件后必须把 `.codex-harness` 回填成 `.ppcode-harness`
   （否则守卫按错目录找 `corrections.md`，报 ENOENT）。
3. `【235】` 品牌守卫的**负向**断言要写主仓品牌名（`!includes("Codex Harness")`），
   批量替换成 PPcode 会让正负两向自相矛盾 ⇒ 恒红。
4. 生成物在覆盖后必须各仓重跑 `gen:ipc`（preload / vite-env / 14-skill 的通道数不同）。
5. 行尾：PPcode 工作区是 CRLF（`core.autocrlf=true`）⇒ `git apply` 直接失败，
   必须用 `git apply --cached`（index 是 LF）再 `git checkout -- .`。
6. `execSync` 在 Windows 下会因路径含空格被 cmd 截断 ⇒ 用 `execFileSync` + 参数数组。
