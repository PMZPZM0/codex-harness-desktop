# 专家团团成员资料卡误显示主理人身份

## 背景

用户在「工作伙伴 → 专家团」成员栏点击团成员名字时，资料卡显示的是团主理人的姓名和身份，而不是被点击成员本人。当时不清楚的是：成员栏点击传出的 `team:<teamId>:<memberId>` 是合成 id，它不在 `group.members` 里；资料卡此前只按群成员槽和主理人查目录，没有把合成 id 还原为团成员，因此点击任何团成员都会回落到团槽对应的主理人。

## 结论

团成员资料必须按本人身份显示，不能复用团槽的主理人资料。成员栏、消息头像和资料卡统一通过 `createTeamIdentityHelpers()` 解析：合成 id 先在当前团目录中匹配 `memberId`（并兼容目录 key），再生成独立的成员资料；团成员显示本人姓名、岗位和头像，身份行显示「团成员 · 岗位」，不再挂「主理人」徽标。普通专家也统一显示「专家 · 岗位」。以后新增团成员入口时，必须调用同一身份解析，禁止各渲染分支自行拼接 `team:<teamId>:<memberId>`。

## 依据

- `src/features/harness-team/20-team-view-utils.ts` 的 `profileMemberOf()` 按合成 id 找到团槽和目录成员，返回 `id/name/targetKind/targetKey/targetProfession/avatar`；`04-team-group-view.tsx` 的成员行与资料卡都调用它，避免点击对象和展示对象再次分叉。
- `scripts/guards/12bw-team-profile-identity.mjs` 真跑纯函数并检查源码接线，覆盖「团成员不落主理人」「岗位 / 头像」「普通专家」「资料卡身份行」；主仓与 PPcode 均执行 `node scripts/guards/12bw-team-profile-identity.mjs`，结果 8/8 通过。
- 两仓执行 `node scripts/guards/12be-team-chat-ux.mjs`，结果均为 425/425 通过；两仓 `npm run build:vite` 均通过。
- 主仓提交 `199b60e03`，PPcode 同步提交 `80205a17`；两仓均已推送 `origin main`，提交内容只包含本轮 7 个身份修复文件。

## 影响面

影响专家团成员栏、消息头像点击、资料卡姓名 / 岗位 / 身份 / 上级展示，以及普通专家资料卡的岗位标签。成员实际派活、群消息作者 id 和团目录数据不改；团主理人仍保留自己的资料与「主理人」徽标。团成员不再出现群内改名入口，因为显示名来自专家目录，改名不会改变实际展示。

## 回滚

回滚主仓 `199b60e03`、PPcode `80205a17`，恢复资料卡只按群成员槽和主理人查目录的旧实现，并撤掉 `12bw-team-profile-identity` 守卫及 `package.json` 接线。回滚会重新出现「点击团成员显示主理人」的已知缺陷，不建议单独回退；若只需停用守卫，也必须保留 `createTeamIdentityHelpers()` 的统一解析，否则成员栏与资料卡会再次分叉。
