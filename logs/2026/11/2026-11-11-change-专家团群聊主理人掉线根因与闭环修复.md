# 专家团群聊主理人掉线根因与闭环修复

## 结论

用户在专家团群直接发消息，看到的是裸英文 `software-dev-team-lead` 署名、主理人一条消息
把成员发言全代写、出完方案链路就死、群头「任务 2/2」却显示全部完成。判定为群聊域与
专家团域两套调度机制没接上导致的**架构缺陷**，不是模型偷懒。

四个已坐实的根因：

1. `software-dev-team-lead` 就是主理人「承枢」本人（`08-software-dev-team.ts:37-38`）。
   群消息署名 `nameOf()` 只按 `kind:"member"` 反查调度目录，主理人条目却是 `kind:"expert"`
   （`dispatch-core.ts:881-890`），查不到就回退裸 id；右侧成员栏显示中文名 ⇒ 身份显示不一致。
2. 群聊链 `runTalkTurn` 的会话在 `ensureTalkThread` 只挂 `group_say/group_read/group_members`，
   `03-talk.ts:284` 明写「别调任何调度工具」；`team_member_invoke/team_phase_invoke` 只在专家团
   独立会话（`teams-ipc.ts:137`）与委派链（`delegation.ts:159`）注入。主理人拿不到派活工具，
   只能把成员产出自己代写。`harness-team-ipc.ts:1360` 的 11-08 注释已记录这个事实但未修。
3. 群头「任务 2/2」是 handoff 点名台账（`openTaskFor`/`closeTasksFor`），不是 SOP 阶段进度；
   Phase 2 实现 / Phase 3 验收 / Phase 4 汇总从不进这个台账。
4. 闭环两个结构洞：主理人一个 @ 都没派时 `asks=[]` 且团群主持人=它自己 ⇒「自己不往回喂」
   让链停在第一句；成员产出被 `classifyTurn` 判 `wrap` 时也不回喂。主持人一次 @ 多人走串行
   queue，跑完同样不回头。⇒ 没有阶段通报、没有验收、没有最终结论。

## 改动

`electron/features/harness-team-ipc.ts`：排片跑完强制回喂主理人（报阶段进度 / 验收 / 继续派 /
收口给结论）；团群成员回合判 wrap 也回喂一次（只有主理人有权收口）；主理人没派人没写收口时
一次性催办，要求按 SOP 真正行首 @ 派活、不许代写。安全阀 `leadCatchUps<=3`、
`leadSelfNudges<=1`、`chainBudget`、`canRun`，`relayInFlight` 防排片被中途冲散。只在团群生效。

`src/features/harness-team/04-team-group-view.tsx`：`nameOf` 补 `kind:"expert"` 反查与裸 lead.id
兜底；成员栏标题按实际渲染行数（含展开团成员）；「任务 N/N」改「交接 N/N」并注明不是 SOP 进度。

`scripts/guards/09-structural.mjs`：【265】按守卫净代码行口径回填 1926→1937 / 1892→1939。

## 遗留

群聊会话仍未注入 `team_member_invoke`，主理人靠行首 @ 派活；本轮修的是「派完 / 没派都要回来
推进」的闭环。给群聊装团队工具要动 `thread/start` 工具面和 `team-invoke` 执行端权限，另起一轮。
运行时行为需真机在团群再发一句话验收：主理人应回来报阶段进度、继续 @ 派活、最后写收口结论文。
