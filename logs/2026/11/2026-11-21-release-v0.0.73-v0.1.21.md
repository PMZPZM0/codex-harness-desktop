## 二、mac 恢复一起发布（本轮唯一的结构性改动）

`jobs.mac` 的条件：

```yaml
- if: ${{ inputs.with_mac == true }}
+ if: ${{ github.event_name == 'push' || inputs.with_mac == true }}
```

⛔⛔ **根因**：`push` 事件里 `inputs` 为空，所以 11-20 那版写成 `inputs.with_mac == true`
就等于「推 tag 永远不构建 mac」。上一版没有 mac 包不是忘勾选，是条件表达式在 push 下必为假。
`workflow_dispatch.inputs.with_mac` 默认同时改回 `true`。

⛔ mac 两件仍是 `pick_soft`（不阻断 Windows），但语义变了：tag 触发时走到 `MAC_MISSING`
就是**构建失败**，notice 已升为 `::warning::` 并提示去看 mac job 日志；正文追加句改成
「本版未包含 macOS 包（构建失败或手动取消）」。

⛔ PPcode 的 `release.yml` 是**单作业三端**（ubuntu 上同时出 win + 两件 mac zip），
没有 `with_mac` 门，结构不同、不必对齐。

## 四、本轮踩到的坑

1. **`indexOf("]", i)` 在 `WhatsNewEntry[]` 上命中类型括号**，插入把数组头写成
   `WhatsNewEntry[]<entries>, = [` ⇒ 语法错，守卫「子进程真跑」整组红。
   ⇒ 锚点必须用完整的 `= [` 行，或先插入再校验 `node --check`。
2. **守卫的「真跑」项读 `dist-electron`**：改完 `whats-new-notes.ts` 必须
   `npm run build:electron` 再跑 11r，否则 25 项里有 5 项恒红（真跑拿不到数据）。
3. **匿名 GitHub API 又一次在构建中段整段 403**（03:56–04:11，约 15 分钟）：
   等待脚本只能跳过重试；判「出包完成」仍以 `releases/tags` 的 `assets[].state` 为准。
