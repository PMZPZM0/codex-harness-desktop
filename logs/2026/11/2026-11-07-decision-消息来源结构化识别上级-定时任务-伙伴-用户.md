# 消息来源结构化识别（上级 / 定时任务 / 伙伴 / 用户）

## 背景
用户令：「准确区分每条消息是上级发送还是用户发送，并让调度功能在被调度场景中正确识别上级消息……不仅限群聊里，外面对话框、专家团、中枢会话也是一样」。

症状：被调度会话里上级派来的任务显示成用户气泡；群里定时任务的消息显示成「我」说的；伙伴互 @ 触发的回复也被当成用户发起。

## 结论
根因：调度链的输入里**没有「谁发的」**，只有 `originThreadId`，且空串被一律当作「本地用户」。六种真实来源（主对话模型自派 / 专家团主理人派成员 / 中枢派群成员 / 定时任务 / 群伙伴互 @ / 用户亲自打字）因此被拼成同一句「发起方交给你的任务」，消费侧只能用 `[SYSTEM TASK]` 标签白名单 + 正文正则猜。

修法：身份作为**结构化对象**沿链传，并在首任务需求体第一行写协议行 `发件人：<kind> · <name>`：
- 真相源 `src/lib/message-origin.mjs`：五种身份 + 协议行 + 任务措辞 + 解析/剥离（纯函数）。
- 生产端全部写协议行：`delegation`（模型自派 / IPC / 宿主工具）、`team-invoke`、`teams-ipc`（团队首任务=用户，成员首任务=主理人）、`boss-groups/runner`、群派活（用户 / 定时任务 / 伙伴互 @）、`send.tsx`（用户亲自在专家会话打字 = user）。
- 消费端：`parseUserRefs` 统一解析 `sender`；`UserMessageView` 优先 `sender.isSuperior`；群消息落 `senderKind` 并投影到渲染行。
- 老会话没有协议行 ⇒ 从旧标记推导（`上级：` / `发起方交给你的任务` / `主理人分配的子任务` / `用户任务`），零回归；推不出 ⇒ `user`（⛔ 不是"猜不到当上级"）。

## 依据

## 影响面
- 被调度会话里，宿主派发的首任务一律左对齐并以真实发送者署名（定时任务 / 伙伴转交 / 系统各有专属头部），不再冒充用户。
- 群里定时任务 / 系统消息不再显示成「我」；伙伴互 @ 的回复标「由 X 叫来」。
- `authorKind` 语义**保持不变**（仍管过程折叠 / 卡片 / 动作条），来源走独立的 `senderKind`。
