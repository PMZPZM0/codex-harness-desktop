# 发版 v0.0.65 / PPcode v0.1.19（差分链路四处硬缺陷）

## 背景
用户实测：「我明明选的差分更新还走完整包」（668.5MB）、「更新弹窗关都关不掉」、「镜像一分钟 1M」、
「BUG 都没修完，就发版」。审查后确认这不是环境偶发，是**差分功能从上线起就没真正生效**。

## 结论
- 主仓 `2de25d356` + tag `v0.0.65`；PPcode `1800fbf7` + tag `v0.1.19`，两仓 main/tag 均已推自己的 origin。
- 两仓 CI 均 `success`，Release `draft=false`、正文 = 发版说明、各 5 件资产 `state=uploaded`；
  `latest.yml` 的 `path` 与 `size` 与线上 exe 逐字对得上（主 701,020,091 / PP 702,072,867）。

## 修了什么（四处硬缺陷 + 一处语义）
1. `autoUpdater.autoInstallOnAppQuit` 原本显式 `false` ⇒ 下载完不点「重启安装」就白下；
   进程一关句柄丢失，安装退回 spawn（不经 updater 安装器）⇒ **配对缓存永远写不回去**。改 `true`。
2. 配对缓存坏了不会自愈（`installer.exe` 在、`current.blockmap` 不在 ⇒ 永远整包）。
   新增 `healDifferentialCache()`：缺一份就两份都删（只动 `%LOCALAPPDATA%/<app>-updater`）。
3. 镜像序把慢源排前：`ghproxy.net` 0.014MB/s（≈0.8MB/分钟）在候选里、`ghfast` 被删。
   按 11-19 实测重排：直连 → `ghfast` 0.82MB/s → `hk`（302 不可用）→ `gh-proxy` 0.42MB/s；
   守卫 12e 与 06-part05 的断言**原本钉的是 11-15 旧序**，同步按实测更新（12e 20/20、06 exit 0）。
4. 后台下载提示零关闭入口 ⇒ 右上角收起键（只收起显示，下载继续；安装遮罩不可关）。
5. 选「补丁」缺基线时静默整包 ⇒ 新增 `hasDifferentialBaseline()`，无基线时进度条明写
   「本次为完整包（本机无差分基线，装完自动建立）」，结果回传 `differential:false` + `noBaseline:true`。

## 判据（实测）
- 两仓 `npm run check` 预检通过（5 条既有告警）；`npm run build` 通过。
- 主仓 mac 审计 43 命中、PP 49 命中，逐条判读均为 Windows 专属路径 / 平台门控 / 守卫夹具，本轮新增行 0 命中。
- 资产核验走 `api.github.com`（本机 `github.com` HTTPS 不通）：
  `releases/tags/<tag>` 看 `assets[].state/size/digest`，再取 `latest.yml` 资产内容比对；
  ⛔ `gh-proxy.com` 探 `/releases/download/...` **恒 404**，用它判「有没有出包」会连续误判 50 分钟。

## 时间线（必须对用户说清）
- v0.0.65 / v0.1.19 **本次安装仍是整包**（缓存重建）；
- 装完看 `%LOCALAPPDATA%\codex-harness-desktop-updater\`：`installer.exe` + `current.blockmap` 成对 = 基线正确；
- **从 0.0.66 / 0.1.20 起**同一条安装线才只下变化块；中途手装 exe 会再次打坏配对。
