## 背景
用户令「使用发版技能，发布一下新版本，ppcode 暂时不用发布新版本」。

## 结论
- 主仓 `27c4e1b89` + tag `v0.0.64`，main 与 tag 均已推 `origin`；CI（Release 工作流）
  `completed/success`，耗时 11:07→11:56（约 50 分钟，两端构建 + publish）。
- Release `v0.0.64` 匿名可见、`draft=false`，5 件资产全部 `state=uploaded`：
  win exe 701,017,909 B / blockmap 732,261 B / latest.yml 378 B /
  mac-arm64 zip 947 MB / mac-x64 zip 953 MB。
- 正文 = `docs/releases/v0.0.64.md`（CI 的 `gh release edit --notes-file` 已执行，已核 body 含「本版主题」）。
- PPcode **本轮不发版**（按用户令）：源码停在 `d972523e`，无 `v0.0.64` tag。

## 判据（都实测，不是推断）
- 本机 HTTPS 到 `github.com` 不通（代理 502 / 直连空响应），但 `api.github.com` 直连 200 ⇒
  用官方 API 核：`/releases/tags/v0.0.64`（资产 + digest）、`/actions/runs`（运行状态）。
  资产下载探测仍走 `gh-proxy.com`（`releases.atom` 也走它，匿名）。
- `latest.yml` 与线上资产对得上：`path`/`url` = `Codex.Harness.Desktop-0.0.64-win-x64.exe`，
  `size` = 701017909 = API 里该资产的大小。
- ⛔ 踩坑：资产 URL 探测走 `gh-proxy.com` 时**恒 404**（连资产已上传后也是 404），
  用它对「有没有出包」下结论会误判 —— 正解是查 API 的 assets/state。

## 差分口径（用户问过两次，定死）
- Windows 发的是差分三件（exe + exe.blockmap + latest.yml），CI 对 `latest.yml` 的 `path` 有硬断言。
- 但「能不能只下几十兆」取决于客户端有没基线：`%LOCALAPPDATA%\codex-harness-desktop-updater\current.blockmap`
  只在**更新器自己安装**时登记。本机实测该目录只有一个 2026-10-12 的 `installer.exe`（386 MB），
  无 `current.blockmap` ⇒ 本机这版会下整包并建基线，**v0.0.65 起才差分**。
- 别的机器：0.0.63 若是应用内更新上来的就有基线，可直接差分；手装 exe / 首装则整包。
- mac 永远完整包（无 NSIS blockmap）。
