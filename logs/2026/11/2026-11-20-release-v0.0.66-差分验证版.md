# 发版 v0.0.66（差分验证版）+ CI 默认只构建 Windows

## 结论

- **v0.0.66 已发布**（`draft=false`），三件 Windows 资产全部 `uploaded`：
  - `Codex.Harness.Desktop-0.0.66-win-x64.exe` **701,118,427 B**
  - `….exe.blockmap` 732,617 B
  - `latest.yml` 378 B，`path`/`size` 与线上 exe 逐字一致（701118427）
- CI 只用了 **14 分钟**（旧三端口径 50 分钟）—— mac job 被 `if` 跳过，不再等 Intel mac 打包。
- 本版是**刻意的差分验证版**：只带两处修复（粘贴叠字 / 欢迎页彩色），整包与 v0.0.65
  仅差 **+98,336 B（≈96 KB）**（701,020,091 → 701,118,427）⇒ 有基线的机器这次差分块应极小。

## 为什么先取消再重推

1. tag 16:21 推的，指向的提交里 mac 仍会构建 ⇒ 三端并行，时长被 mac x64 拖住；
2. 匿名调 `POST /actions/runs/{id}/cancel` 返回 **401**（本机无 token）⇒ 只能用户在网页点 Cancel；
3. 取消后确认 `releases/tags/v0.0.66` 返回 **404**（Release 未创建）⇒ 删 tag 重打**没有**
   「退回草稿」风险（技能 §8 那条坑的前提是 Release 已存在）；
4. `git push origin :refs/tags/v0.0.66` → `git tag -f v0.0.66 14d1b3259` → 重推 ⇒ 新 run 的 job 列表
   实测 `win in_progress / mac skipped`。

## CI 改动（`.github/workflows/release.yml`）

- `workflow_dispatch` 新增 `with_mac`（boolean，默认 `false`）；
- `jobs.mac` 加 `if: ${{ inputs.with_mac == true }}` —— tag 触发时 `inputs` 为空 ⇒ 跳过；
- `publish` 侧 `mac-arm64` 原来是**硬 `pick`**（find 到 0 个就 `::error::` 退出，会把已经好的
  Windows 包一起挡在门外）⇒ 两行都改 `pick_soft`；
- 新增 `MAC_MISSING=1` 分支：只在 Release 正文追加「本版只构建 Windows。macOS 用户请继续使用上一版；
  需要 mac 包时在 Actions 里手动运行本工作流并勾选「同时构建 macOS」」——线上正文已实测含这句。

## 体检结论（本版故意不升）

引擎官方 `0.171.0`（本仓 0.170.0）、`lucide-react` 1.76→1.77、`dingtalk-stream` 预发布标记无差异：
均为「差分验证版保持最小改动」而留到下一版。`@xyflow/react 12→13`、`electron 44→45`、
`typescript 6→7` 跨大版本继续保留（TS 7 与 typescript-eslint 的 peer 约束冲突）。

## 待验（用户机器）

- `%LOCALAPPDATA%\codex-harness-desktop-updater\` 里 `installer.exe` + `current.blockmap` **成对** ⇒
  本次更新应只下变化块；只有一份 ⇒ 本次仍是整包（`healDifferentialCache()` 会重建配对，下一版起差分）。
- 本机（开发机）没有配对缓存，`healDifferentialCache()` 会主动清空 ⇒ **本机永远测不出差分**，只能在用户机器上验。
