本轮体检发现 9 项落后后，用户拍板「先升级再发版」。

## 版本对齐的三个坑
1. PPcode 的 `node_modules/exif-parser` 版本恰好也是 `0.1.12` ⇒ 对
   `"version": "0.1.12"` 整串替换会误改依赖；lock 必须按「根第 3 行 + `packages[""]` 第 9 行」精确定位。
2. 云助手 `electron-builder.assistant.yml` 的 `extraMetadata.version` 停在 `0.0.50`，
   与已发的 `cloud-v0.0.54` 不一致 ⇒ 包内 `app.getVersion()` 落后，更新器反复提示有新版；本轮对齐 `0.0.55`。
3. 云助手唯一发布流水线是 `release-cloud.yml`（tag `cloud-v*`，`release.yml` 已停触发），
   说明文件必须叫 `cloud-v*.md` 而不是 `v*.md`（`cloud-v0.0.53` 上传失败即此根因）。

## 门禁：链断掩盖的 5 类缺陷
`npm run check` 是 `&&` 链，任一守卫红就中断 ⇒ 链尾四项
（`check-bag-types` / `check-dead-imports` / `check-require-paths` / `check-runtime-files`）
长期不跑。本轮手动补跑后发现并修掉：
1. `check-runtime-files` 把 `app.isPackaged` 开发态分支的 `resources/media-desk` 误判为
   必须进 `build.files`（打包态走 `process.resourcesPath/media-desk`，`extraResources` 已明确带
   `{"from":"resources/media-desk","to":"media-desk"}`）⇒ 加入有理由的 `KNOWN_OPTIONAL`。
2. `11-knowledge-base` 夹具写死 `.codex-harness`；PPcode 用 `.ppcode-harness` 品牌目录
   ⇒ 向量缓存落错目录、语义档假报零召回。改从 `mod.kbRoot()` 取目录。
3. PPcode / 云助手设置页白名单缺 `component-library`（主仓有；PPcode 因链更早断在 kb 才没暴露）。
4. PPcode 一条整行死导入（⛔ 按行 splice，不用跨块正则 —— 上轮误伤过 `useEffect`）。
5. `any` 基线 / 【265】行数棘轮按实测记账。
结果：主仓 `npm run check` 0 红（末尾跑到【288】）、云助手 0 红；PPcode 仅剩 3 条历史假阳性。
