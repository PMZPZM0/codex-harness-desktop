# 撤掉草图里的组件库面板与写通道：草图改为只读

> ⚠️ 只推翻前一条结论里的**第 3、4 点（双向写通道 + 组件库融合）**；
> 「嵌第三方静态产物 + `sketch://` 协议 + 只读桥 + 独立板块」这套骨架仍然有效，别连坐删。

## 背景
组件库融合是用户 10-05 主动要的（「把我们的组件库也接入进去，看看怎么融合，这样前端开发就快」），
当天做完他亲眼看了一遍，回话：「算了，组件库，你删了吧，跟左边那些不适配，加进来没啥用」。
"左边那些"= 草图自己的 M3E 组件面板（按钮 / FAB / 导航栏 / 标签片…）。

## 结论
1. 草图弹窗里的**组件库抽屉整块删除**（含真实预览、类目切换、勾选、「送进草图」按钮）。
2. 桥改成**只读**：删掉 `load-doc` / `pushHash` 这条写通道，宿主不再往画布写文档。
3. `sketch-doc.mjs` 只留读侧：`summarizeDoc` / `describeDiag` / `buildSketchPrompt`（把画布结构 + 跳转关系
   合成给 Codex 的任务正文）。删掉 `appendComponents` / `componentNote` / `pickSpot` / `encodeShareHash` /
   `SKETCH_KIND_BY_CAT` / `PROMPT_HTML_BUDGET` —— 面板没了，这些实现留着就是死代码。
4. 「设置 → 组件库」那一页**不动**（3802 个控件照旧可浏览、可复制）；侧栏「···更多」里的「组件库」入口也照旧。

## 依据
- 用户原话（本轮）：「算了，组件库，你删了吧，跟左边那些不适配，加进来没啥用」。
- 技术上本来就不该由我们写：**上游自己有完整导入通道**（`lib/share.ts` 的 `#doc=` / `#docz=` → hashchange →
  `readShareHash` → `arrive()`，被替换的设计留在 `draftBefore` 可一键撤销），我们那条 `load-doc` 是重复建设。
- 不适配的具体形态：M3E 的画布只认它自己那 20 多个 `kind`（`lib/tokens.ts` 的 KIND_ORDER），
  Uiverse 控件只能落成"占位块 + note 里写组件 id"，画布上看不出真效果 —— 这正是用户说的"没啥用"。
- 判据同步：守卫【283】67 → 64 条（删融合相关的正向断言，**新增三条负向**：弹窗里不许再出现
  组件库 / `loadCategory` / `SkinHost`；桥不许有 `load-doc` / `pushHash`；纯函数层不许残留 `appendComponents`）；
  验收项 `ui-sketch` 9 → 8 条（去掉「送进草图」「组件预览」，换成「取回画布走通读通道」）。
- 顺手补的工具缺口：`scripts/build-sketch-bundle.mjs --bridge-only` —— 只改桥时**不需要**重装 Next 工具链
  （原地替换产物里那一段，其余一字不动）。此前改桥必须先有 `out/`，等于改不动。

## 影响面
- 草图弹窗现在只有：一行标题栏（取回画布 / 复制 JSON / 交给 Codex 实现 + 状态）+ 占满主体的 iframe + 状态条。
  iframe 实测宽 1230px（并排面板时代只有 910px）。
- `public/sketch/index.html` 内联的桥正文变了（26,003 → 25,100 字节）；`dist/sketch` 由 `npm run build` 同步。
- 「交给 Codex 实现」发出去的任务正文里不再有组件 HTML，只保留屏 / 部件 / 跳转关系 —— 空画布时仍然拦住不发。

## 回滚
`git revert` 本轮提交即可整体退回（含负向断言）。若只想恢复"送组件进画布"：
桥要加回 `load-doc`（跑 `--bridge-only`）、`sketch-doc.mjs` 恢复 `appendComponents` 一族、
面板与预览按 `d84c717` 那版抄回。**不建议**——上游的 `kind` 表限制摆在那儿，做不出真外观。
