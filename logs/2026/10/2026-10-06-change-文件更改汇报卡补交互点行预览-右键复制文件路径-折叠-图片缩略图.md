# 文件更改汇报卡补交互：点行预览 / 右键复制文件路径 / 折叠 / 图片缩略图

## 背景
- 用户（10-06，附 Qoder 效果图）：「汇总消息底部显示文件，能做成这样效果吗…这个生成文件，直接打开预览就行，和右键打开文件地址和复制文件路径，修改文件下面效果，还有生成的图片」。
- 现状勘察：回合底部**已有**「已更改 N 个文件 +X -Y」汇报卡（10-01 复刻 ZCode，`Status.tsx` 的 CompletedChanges），每行带 审查（diff 弹窗）/ 打开（资源管理器定位）；消息里也有内联文件卡 + `FileCardMenu`（打开/在文件夹中显示/编辑/另存为）。缺口：行不能点开预览、右键菜单没有「复制文件路径」、文件多时一口气铺满、图片只是文字块、生成图片没有专门展示。

## 结论
- 汇报卡补四件：① **行点击 = 直接打开预览**（文本走文件预览弹窗、图片走灯箱 —— 与内联卡片同一口径的 openPath 分流）；② **行右键复用 `FileCardMenu`**（不复制第二份菜单实现）并给菜单**新增「复制文件路径」**（写剪贴板 + toast 回执；原有「在文件夹中显示」即用户说的「打开文件地址」）；③ 超 **6 行折叠**成「再显示 N 个文件 / 收起」；④ 图片文件显示**缩略图**（imageUrl），宿主追踪的新增文件打**「新增」**徽标（与「已删除」成对）。
- 挂点：`turn-view.tsx` 把 `handlers.onOpenFile`（文件预览弹窗的统一入口）递进 `CompletedChanges`；菜单从 `features/shared`（基座层，域→基座为合法正向依赖）导出复用。
- ⛔ 行内 审查/打开 按钮各自 `stopPropagation`——否则点按钮会连着行点击一起触发（预览+弹窗双开）。

## 依据
- 守卫新增 **`11p-file-summary`（16 条）**：代码形态 + 复用关系 + 样式三组；**5 处变异全抓**，其中两处**当场暴露前缀匹配弱点**（`COLLAPSE_LIMIT = 6` 是 `= 600` 的前缀、`completed-file-thumb` 是 `-thumbX` 的前缀 ⇒ 断言收紧到带分号/带闭引号）。
- 验收新增 **`file-summary`（8 条，10-06 轮）**：e2e profile 的历史会话没有文件改动回合，改用**真事件形状驱动真组件** —— 从 DOM 取真回合 id，派发 `window` message（`channel: harness:event` / `type: turn-file-changes`，与主进程广播逐字段一致），订阅/渲染/交互全真、只注入"报告"一环：8 文件 fixture（7 文本 + 1 图片，全部真实存在）→ 卡出现（已更改 8 个文件）→ 点行开真预览（预览到 package.json）→ 右键菜单两项在 → 复制成功回执（toast 带完整路径；成功路径专属）→ 折叠 6↔8 往返 → 图片缩略图 + 新增徽标。全过。
- 全套：`accept` 19/19（ui-sketch + file-summary）、守卫 16/16、变异 5/5。
