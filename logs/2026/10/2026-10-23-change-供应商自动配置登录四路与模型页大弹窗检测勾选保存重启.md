# 供应商自动配置：登录四路与模型页大弹窗（检测→勾选→保存→重启）

## 背景
用户 10-24 要求：登录云账号 / 中转站 / OpenAI 订阅后自动生效对应供应商、旧的停止、列表明显刷新、
自动检测并提示勾选（或一键全选）、保存生效并重启；自定义 API 配好地址密钥后同一流程；
同时重做模型配置前端 UI，加大面板弹窗与逐步进度。

## 结论
- 新增自包含 `provider-setup` 弹窗（portal body、920 档、左五步右内容），编排收在
  `src/lib/provider-setup.ts`：云端检测走 `cloud-models:sync` + catalog（不走代理网关的 /models），
  勾选写服务端再 activate；其它供应商 probe + `custom-model:save`（enabled:true，主进程互斥停旧）。
- 登录页四路统一进弹窗；中转站登录新增 `deferActivation`（先解析候选并真探测，取消不落档案）；
  `handleLogin` 新增「弹窗已保存」收尾路径，不重复探测/保存。
- 模型页新增大入口；云账号页登录 / 「选择模型并启用」；OpenAI 页登录 / 启用订阅都接同一弹窗。
- 保存后 6 秒倒计时自动重启，另有「立即重启 / 稍后重启」；完成页如实写「旧供应商已自动停用」。
- `provider-activated` 后当前会话模型跟到新供应商；云端 `activateCloudProvider` 也广播同一事件。

## 依据
- `scripts/guards/12ac-provider-setup.mjs` 65 条（检测通道分源、全选、落盘通道、互斥回执、
  四路接线、preSaved 不重复保存、类型面、验收登记、单源）。
- `scripts/accept.mjs` 本地 mock `/v1/models` 真链路：`provider-autosetup` 7/7 +
  `provider-login-autosetup` 3/3。实测保存后 `listCustomModels()` 仅新供应商 enabled，
  `getCustomModel()` 指向它，composer 模型按钮显示 `mock-alpha`。
- `npm run check` 退出码 0（含 12q 云端守卫 79/79）。

## 影响面
- 登录页四条登录路径不再直接保存供应商，必须在弹窗里点「保存并启用」（或等待倒计时重启）。
- 供应商启用 / 保存后，当前会话的模型选择会跟随新供应商（原 provider-activated 只刷列表）。
- 云端「选择模型并启用」同时写服务端勾选，其它设备登录会跟随。

## 回滚
单独回滚本轮提交即可；`custom-model:save` / `cloud-models:*` 协议未改，
旧渲染层仍可按原路径保存（只是没有选模型/进度弹窗）。
