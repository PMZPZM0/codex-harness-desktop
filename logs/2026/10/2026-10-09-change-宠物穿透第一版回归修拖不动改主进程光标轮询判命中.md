# 宠物穿透第一版回归修拖不动改主进程光标轮询判命中

# 宠物「挪不动」——穿透第一版把翻转挂在页面鼠标事件上（当天回归 + 改主进程光标轮询）

## 现象

用户报「宠物现在直接挪不动啊」。这是同一天上一轮「透明罩挡桌面」修复**当场引入的回归**。

## 根因（第一版为什么必然坏）

上一版的做法：主进程默认整块 `setIgnoreMouseEvents(true, {forward:true})`，渲染层监听
`mousemove` + `document.elementFromPoint` 命中最深元素，指到宠物本体上就关掉穿透。

⛔⛔ **`-webkit-app-region: drag` 区域属于「非客户区」，Chromium 根本不往里派发 DOM
mousemove/mousedown**（这正是「drag 区里的按钮点不动」的经典现象，所以按钮才要 `no-drag`）。
而 `.pet-float` 整块都是 drag 区 ⇒ 事件永远到不了页面 ⇒ 翻转永远不触发 ⇒ 窗口永远停在
穿透态 ⇒ 宠物既拖不动也点不着。`forward: true` 只保证「把 OS 的移动消息转给页面」，
并不能绕过 drag 区的命中处理。

顺带暴露的第二个隐患（同轮修掉）：`applyPetMouseState` 原先用
`if (ignore === !petMouseInteractive) return` 做去抖，而窗口**默认是可交互**的、不等于
「穿透」——初值一比较就短路，第一帧一次 `setIgnoreMouseEvents` 都不调，窗口默认仍挡桌面。
⇒ 改成独立的 `petMouseAppliedIgnore: boolean | null`（null = 本窗口还没设过），
窗口 `closed` / `closePetWindow()` 时置回 null。

## 修法：翻转判据搬到主进程，不依赖任何页面鼠标事件

- **`electron/features/pet-window.ts`**：
  - 渲染层只在布局变化时上报「宠物本体矩形」（相对窗口左上角）；主进程按
    `screen.getCursorScreenPoint()` + 100ms `setInterval` 比对
    `win.getBounds() + rect`（±2px 命中容差防边界抖动），在/不在矩形内决定整块穿透还是可交互。
  - 轮询只在窗口可见时跑（`startPetMouseWatch`/`stopPetMouseWatch`，`unref()` 不吊住进程）；
    `ready-to-show` / `showPetWindow` 起、`hidePetWindow` / `closed` / `closePetWindow` 停。
  - **矩形未上报 = 整块穿透**（fail-safe：绝不再挡桌面）。
  - 附带好处：翻转不再需要 `forward`（它只有 Windows 有实现）⇒ **mac 一并修好**；
    拖动仍是原生 `app-region: drag`（指针在本体上时窗口已可交互）。
- **`electron/features/pet-ipc.ts` + IPC 三件套**：上一轮的 `pet:ignore-mouse`（开关）
  换成 `pet:interactive-rect`（上报矩形，参数 `{x,y,width,height} | null`）；通道总数仍是
  432、pet 域仍是 11 条，manifest → `gen:ipc` 重生成 preload / vite-env。
- **`src/features/pet/PetFloat.tsx`**：删掉整套 mousemove/elementFromPoint/`petIgnoreMouse`
  逻辑，改为 `spriteRef`/`missingRef` + `ResizeObserver` + `window.resize` →
  `getBoundingClientRect()` 取并集上报（挂载 / 换宠物包 / 帧高变化 / 窗口尺寸变化时）；
  卸载时上报 null。

## 判据（06【232】⑯ 组改写，仍 4 条；总账 3240 不变）

主进程光标轮询判命中 / 渲染层只上报矩形（`pet:interactive-rect` + `getBoundingClientRect`）/
渲染层**不许**再用 mousemove + elementFromPoint（负向，过 codeOnly 剥注释）/ 默认 fail-safe
穿透 + `closed` 处理器内重置已应用状态。

**两处变异测试暴露的假绿（都已修）**：

1. 负向断言被自己的注释顶红——注释里写着「第一版挂在 mousemove + elementFromPoint 上」，
   裸 `includes` 直接判红 ⇒ 按纪律先剥注释再匹配。
2. 第 4 条只判「字符串 `petMouseAppliedIgnore = null` 存在」⇒ 删掉 `closed` 处理器里那处
   仍绿（`closePetWindow` 里还有一处同样的行）。⇒ 改成**按 `win.on("closed"` 切片**只认该
   处理器体内的重置；复跑变异，精准红。
