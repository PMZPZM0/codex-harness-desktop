# 回合状态胶囊（步骤+文件双分区）+ 旧目标面板撤除 + 任务清单实时同步 + 输入框拖动把手

## 背景（用户对照 Qoder 截图两连 + 一条展示规则定稿）
1. 「把那个目标和任务清单也改成出成这种小胶囊形式，把原来的目标和任务清单图标和浮窗移除」——
   目标 UX = Qoder 的 `步骤 0/6 · 5 个文件已修改 +177 -8` 胶囊：左悬停展开步骤清单、右悬停展开文件。
2. 「任务清单必须有 codex 自己更新，他自己完成任务清单后就主动更新任务清单」。
3. 展示规则定稿：「步骤清单跟文件修改，都是可以独立居中展示的，只是多了另一方展示的时候，就拼接展示」。
4. 「输入框加一个图二这种上下拖动功能，最高能拖动的高度记得设置好，还有最低的」。

## 结论 / 做了什么
### ① 合并胶囊（`TurnStatusCapsule.tsx`，由 LiveEditedFilesCard 重构改名）
- 左区「步骤 N/M」= Codex 任务清单（悬停展开：todo ○ / doing ⟳ / done ✓）；右区「X 个文件已修改
  +A -D」= 运行中实时文件改动（悬停展开文件清单）。
- **两区各自独立渲染**：只有一边就只显那一边（居中）；同时在才拼「步骤 N/M · X 个文件已修改 +A -D」。
- 文件区只在运行中显示（收尾由汇总卡/冻结行接管）；任务清单区有清单就有（收尾后仍在）。
- 弹层定位（自适应选边/收窄/以胶囊中心居中/left 写相对卡片偏移）沿用前轮已验收实现。

### ② 旧「目标与进程」UI 整体撤掉（用户令）
- 删：顶栏 `tb-goals-entry` 按钮、`02-goals-bar.tsx`（goals-pop + goals-handle）、chat-search 的
  Esc `goalsOpen` 分支（否则**启动后第一次 Esc 会被无声吞掉**：goalsOpen 初值 true 且再没人置回）、
  goals/plan 相关 CSS（07 删 194 行、14 删 78 行、09 两处小覆盖）。
- ⚠️ **保留**：裸 `.plan-step` / `.plan-step.done`（PlanEditor 的 li 也命中，级联后加载者胜——
  删了会改变计划构件观感）、`@keyframes pulse`（12-settings-skills 在用）、`.rpa-task-list`（RPA 页在用）。
- bag 里 goals* 状态**暂留**（part02 声明未动，无 UI 消费者；清理要同轮动 bag-types 生成物与
  多处分发点，收口成本 > 收益，留待需要时一并做）。

### ③ 任务清单由 Codex 维护 + 实时同步
- `tasks-ipc.ts`：add/update/delete 成功后广播 `tasks-changed`；渲染层 part02c1 订阅 → `listTasks` →
  `bag.setTaskList`（胶囊即刻跟上）。原来只有工具分发处（02-request）自己手动重拉，写入口一多就漏。
- `developer-instructions.ts` 新增**第 14 条 TASK LIST**（条件式：工具在表里才管）——多步任务先建
  清单、开工标 doing、**完成一步立刻 done**、别攒最后；task_add/task_update 工具描述同步强化。

### ④ 输入框上下拖动把手（用户对照 Qoder 图二）
- 顶部细条 + 居中胶囊视觉；拖动改**输入区高度**；**下限 48px / 上限 min(55vh,560px)** 硬钳；
  localStorage 持久化（读回也钳上限）、双击复位。
- ⛔ 实现要点：拖动走 **window 级监听**（不用 pointer capture —— 合成事件下 `setPointerCapture`
  直接抛；window 监听让真拖与验收合成拖走同一条路径）；高度经 `--composer-editor-h/-max` 两个
  CSS 变量下发（未拖动 = 原「内容自适应 + min(42vh,360px)」行为不变）。

## 本轮踩到的坑（比功能更值得记）
1. **CSS 按行号删块必须两边都验括号平衡**：三处「Unexpected }」（07/14 各一）都是**边界差 1~3 行**
   —— 前一处把 `.plan-steps-body` 的收尾 `}` 留下，14 处把 `.remote-conn-left` 的头三行吞掉。
   删块脚本要**同时断言首行与尾行后一行**，删完必须真跑一次构建。
2. **合成 PointerEvent 拖拽 vs CDP mousePressed**：CDP mousePressed 在本机不产生 pointerdown
   （10-06 选区浮条排查的既有结论）⇒ 验收拖拽用合成 PointerEvent（pointerdown 打把手、move/up
   打 window），与 window 监听实现天然契合。
3. **`setPointerCapture` 不能依赖**：无活动指针（合成事件/某些合成环境）直接抛，会把整个
   pointerdown handler 打断 ⇒ 拖动实现改用 window 监听，顺带让 e2e 可测。
4. **删 UI 时同步扫「会被误吞的行为」**：chat-search 的 `if (bag.goalsOpen) close + return true`
   在 UI 撤掉后会变成「吞掉第一次 Esc」的幽灵分支——删组件要连带扫它的状态消费点。
