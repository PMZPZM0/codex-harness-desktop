# 跨仓同步硬规则：三个源码仓必须同轮同步

## 背景
产品有三个源码仓（桌面版开发主线 `D:/Codex Harness Desktop`、PPcode `D:/PPcode`、云助手 `D:/Codex Assistant`）。
历史上是「主仓 → PPcode」两仓镜像，云助手 10-12 才独立成仓（`codex-harness-cloud-src`）。
10-13 用户点名：「改动你都没有同步给 ppcode 和云助手」—— 自「引擎项目信任门禁修好」那轮起的一整批改动
（统一更新体系、网页来源条挪位等 14 个提交）只落在桌面版主线，两个副本仓都缺。

当时我不知道：副本仓缺的不只是新功能，还有**网页来源条**这类更早的改动、云助手连
`docs/FEATURE-LEDGER.md` 都还没有；也没有任何规则约束「一轮改动要同步几个仓」。

## 结论
三个源码仓 = 一体三镜像。**在任一仓完成一轮功能改动后，必须在同一轮把同一批改动同步到另外两个仓，
并各自推送 `main`**；⛔ 只改一仓就收尾 = 这一轮工作**未完成**。
规则原文落在三仓 `AGENTS.md` 同一段（`改动必须同轮同步全部三个仓`），步骤落在三仓 `docs/REPO-WORKFLOW.md` §二。

固定步骤：主仓 diff → **逐文件 `git apply --check` 预检**（⛔ 不整包 apply）→ apply（按 exclude 跳过生成物）
→ 副本侧 `npm run build` + 受影响守卫 + `check-preflight` → `feat(sync)` 提交（写明主仓区间与判据）
→ 推各仓远端（**云助手推 `cloud`**，⛔ 它的 `origin` 指向桌面版仓，推错就污染主线）。

## 依据
- 用户原话：「改动你都没有同步给ppcode 和云助手」/「在项目规则里面写一下，改动必须要同步ppcode和云助手更新」
- 规则段实测：三仓 `AGENTS.md` 第 9 行逐字一致（首段拓扑句属「品牌差异行」，允许不同 —— 整文件 md5 因此不同）
- 本轮同步批次：桌面版 `8cafc37..f07f73f`（14 提交 / 39 文件）
  → PPcode `b9ffddc` + 台账回填 `b782c0d`；云助手 `6f82026` + 回填 `aaade59`
- 收口提交：桌面版 `3b7774e`、PPcode `79f65b1`、云助手 `440b87b`
- 两仓判据：`npm run build` 绿；12j/12k/12l + `scripts/verify-update-safety.mjs` 全绿
- ⛔ 副本仓行尾 ≠ 主线：PPcode 仓库内 `AGENTS.md` 为 CRLF，用 Edit 直改会把整份写成 LF
  ⇒ 一次提交出 1317 行噪音 diff（`--ignore-all-space` 后只剩 3 行）。正解：`git checkout HEAD -- <file>`
  恢复仓库版 → 脚本按**文件自身行尾**插入（模式留在 `.workbuddy/tmp/insert-agent-rule.mjs`）

## 影响面
所有后续改动的工作量 = 1 仓 → 3 仓。生成物（`electron/preload.ts` / `src/vite-env.d.ts` /
`electron/composition.gen.ts`）**必须各仓自跑**（`gen:ipc` + `gen:domains`）；
`electron/ipc-channels.manifest.json` 与 `electron/ipc-registry.ts` 是**手写源**（gen 只提示不代写），要手工合并。
行数棘轮（守卫【265】，口径 = 净代码行）按各仓实测值分别维护（本轮：PPcode `vite-env.d.ts` 826→851；
云助手 823→866）。云助手有独立红线（与桌面版彻底拆开：独立 userData / AUMID / 安装目录 / 助手形态）。

## 回滚
规则本身无破坏性，撤掉三仓 `AGENTS.md` 的规则段与 `docs/REPO-WORKFLOW.md` §二 的表述即可。
若某轮确实无法同步（如副本仓尚未具备前置条件），须在该轮结束前说明原因与补齐计划，⛔ 不得静默跳过。
