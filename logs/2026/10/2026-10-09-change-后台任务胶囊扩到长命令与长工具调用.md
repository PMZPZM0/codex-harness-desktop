# 后台任务胶囊扩到长命令 / 长工具调用（kind = tool）

## 起因

用户报：「我让新增的那个轮询板块，在前端也没有看见胶囊条提醒」。查完整条链路后确认
**渲染层链路是通的**（主进程 `broadcastHarnessEvent` → preload → `PollBridge` → store → 胶囊挂载 → CSS 全部在位），
真实原因是**入口只有视频生成一条**：`poll` 任务只在 `video_generate` 提交与 `video_status` 查询时广播，
其它异步/长任务从来不进那张表 ⇒ 胶囊永远不出现。

追问后用户拍板范围：**只要「长命令 / 长耗时工具调用」也进胶囊**（可多选里只勾了这一项）。

## 修法（同一张表，加一个来源维度）

- `poll-store.ts`：`PollTask` 加 **`kind: "poll" | "tool"`**。
  · `poll` = 真轮询（视频那类，对话流里也有一张卡）；
  · `tool` = 长命令 / 长工具调用（**只在胶囊里**，不进对话流 —— 它在流里已经有自己的工具卡，再画一张就是同一件事两处看）。
- **阈值判定**（`SLOW_TOOL_MS = 8000`）：`read` / `ls` 几十毫秒也弹一个转圈是噪音 ⇒
  `beginToolWatch`（`item/started`）只记起点，**由看门狗每秒 tick 把跑过阈值的提升成任务**
  （`kind:"tool"`，`startedAt` 用真实起点 ⇒ 胶囊上的"已跑多久"从命令开始算）。
  ⛔ 提升放在 tick 而不是定时器：只有周期 tick 才知道"这一刻还在跑"，且空闲时一个定时器都不挂。
- `endToolWatch`（`item/completed`）收尾；`endToolWatchesOfTurn`（`turn/completed`）兜底收掉本回合残余
  （被打断的回合可能永远收不到 completed ⇒ 否则胶囊里挂一条永远在跑的幽灵）。
- ⛔ **轮询超时不作用于 `tool`**：长命令跑多久是它自己的事，别拿轮询超时上限把它掐了。
- `PollBridge` 新增监听 `window.codex.onEvent`（引擎工具项）；**不再加一条 harness:event 广播通道**
  （工具项本来就在引擎事件流里，多一处发射点就多一处会漏）。会话闸按 threadId 比对。
- 中止分两条路：**长命令 → 打断当前回合**（`interrupt` 在 app-state 的 bag 上，模块级 store 拿不到
  ⇒ 用与 `announce-bus.setAnnounceStopHandler` 同款的回调注册范式，由 `PollBridge` 从 AppView 接进来）；
  轮询 → 原有 `poll:abort`（停主进程那个等待循环）。
- 胶囊「查看」按来源跳不同锚点：轮询→`poll-<id>` 卡，长命令→`turn-<turnId>` 那个回合。

## 判据

- 守卫 `11z-poll-board` **67 → 82/82**：新增 ⑦b 组（kind 命名空间 / 对话流只渲染 poll 类 / 超时不作用于 tool /
  看门狗在"还有工具项在跑"时也活着 / 中止回调注册范式）+ 桥的引擎事件订阅与兜底收尾 + 胶囊中止分岔 +
  AppView 把 `interrupt` 交进桥。
- **真跑** 3 条：拨表（`Date.now +9000`，⛔ 必须在 `beginToolWatch` **之后**拨，否则 startedAt 一起被拨、
  差值恒 0 —— 第一版就是这么假红的）→ 看门狗 tick ⇒ 登记成 `kind:"tool"`；同一张表里它**不进** `pollTasksOfTurn`；
  `endToolWatch` ⇒ 收尾 success。
- 变异测试 3 条全抓：① 拿掉 kind 过滤（长命令会跑进对话流）② 永不提升 ③ 胶囊中止不分岔。
- `npm run check` 0 硬失败；`accept --only newbie-guide` 6/6（改了输入框区挂载，冒烟确认未崩）。

## 诚实边界

- 未加 e2e 验收项：要看见胶囊得真跑一次 8 秒以上的工具调用（验收 profile 里没有可复现的常驻长命令，
  依赖模型的实时行为会 flaky）；判据落在守卫的真跑断言与变异测试上。

  在 `poll-store` 加一个 kind 即可（拓展口已留）。
