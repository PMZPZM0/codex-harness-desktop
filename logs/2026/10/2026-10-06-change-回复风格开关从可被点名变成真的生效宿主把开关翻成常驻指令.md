# 回复风格开关从「可被点名」变成「真的生效」（宿主把开关翻成常驻指令）

现象（用户截图）：控制台「回复风格」开着，新会话第一轮仍不按该风格写，必须点名 /i-have-adhd 才生效。

根因：开关的语义只到「技能文件在不在磁盘上」。引擎对技能是**渐进披露**的（清单只给
name + description + 路径，读不读由模型自己判断），而 i-have-adhd 的 description 开头就是
"Invoke with /i-have-adhd; stays on until stop adhd mode" ⇒ 模型把它当**手动模式**，永远等点名。
「在磁盘上」≠「生效」。

定稿口径：开关 = 生效。新增 `electron/output-styles.ts`（单一真相源：风格技能登记表 +
只认技能池全局停用集的生效判据 + 下发目标含 SKILL.md 绝对路径），经 `devInstructionsInput()`
→ `buildDevInstructions` 注入 OUTPUT STYLE MODE 段（排在语言指令之后、全部工具箱说明之前），
开关变化时 `refreshDeveloperInstructions()` 重写 config.toml **并重启引擎**
（引擎只在 spawn 时读 config.toml，只改文件 = 改了没生效）。

⛔ 纠正一条被推翻的旧认知：技能的 `disable-model-invocation` 引擎**不执行**（10-06 二进制取证：
该字段只出现在技能编写规范文本 + 校验「插件内」技能的 Python 脚本，而那条规则的内容是
「必须是 false」）。技能原文仍逐字保留（【82】不动），THIRD_PARTY_NOTICES 的说明按实测改掉。

验证：守卫 11s 35 → 50 条（真跑含「开启态目标存在 / 关掉后名单为空 / 指令含转义路径」）；
`npm run check` 链路中断处（沙箱环境类 19 项）之外全绿，尾部三项手动补跑通过。
