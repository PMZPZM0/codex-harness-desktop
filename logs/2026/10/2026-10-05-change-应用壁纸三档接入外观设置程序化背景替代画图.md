# 应用壁纸三档接入外观设置：程序化背景（图案/粒子/3D）替代「画一张图」

## 背景

用户 10-05：「应用壁纸很难做，每次都做的不好看」——此前走的是"画/生成一张图当壁纸"，
对比度与留白不可控，垫在文字下必花。调研 GitHub（react-bits 48.5k / tsparticles 9k / vanta 7.1k /
Hero Patterns 等）后用户拍板：「1 2 3 一起完成，外观里加壁纸切换；**tsparticles 和 vanta 利用起来，
不要重复造车轮**」。

## 结论

外观设置页新增「壁纸」段，五档：**关闭 / 图案 / 粒子 / 3D 背景 / 自定义图片**。

- **数据面** `src/lib/wallpaper.mjs`（纯函数 + `.d.mts`）：模式白名单归一、浓度夹取 2~16%、
  6 款原创几何图案（SVG data-uri）、localStorage 持久化 + CustomEvent 广播（与主题同机制，
  ⛔ 不进 bag 不走 IPC——消费方只有设置段与壁纸层两个）。
- **图案档**：SVG 走 CSS mask（形状=alpha），颜色 = `background-color: var(--accent)` ——
  换主题自动跟随，不存在配色翻车。
- **粒子档** = tsparticles（MIT）；**3D 档** = vanta NET（MIT）+ three（model-viewer 已带的依赖复用）。
- **自定义图档**：`dialog:images` 选图 → `harness-image://` 协议显示 → 顶部压 --bg 渐变保可读。

## 依据（三条铁律，守卫【wp】13 条钉住）

1. **层**：挂在 `.timeline-wrap`（relative, no bg）内，`absolute inset-0 z-index:-1 + pointer-events:none`
   —— 壁纸只在聊天区透出，侧栏/面板保持实色（Discord 同款），永不挡交互。
2. **懒加载**：@tsparticles/react 的包装器会**静态拖进 @tsparticles/engine** ⇒ 整个粒子面板
   React.lazy 独立 chunk；vanta + three 各自独立 chunk（实测 `ParticlesPane-*.js` /
   `three.module-*.js` / `vanta.net.min-*.js` 三块，主包零增长）。
3. **降级**：vanta 对 three 版本敏感（本机 three 0.183）⇒ 初始化整体 try/catch，失败静默退回无背景；
   `prefers-reduced-motion` 下粒子/3D 自动退回静态图案；tsparticles `fullScreen.enable:false`
   （默认全屏会劫持 body）。

## 10-05 深夜追加：真机验证抓出两个「假功能」级 bug（已修）

用户实测「切换全没反应」。真机 CDP + 截图逐层排查出**两个叠加根因**：

1. **堆叠上下文穿透**：`.timeline-wrap` 是 relative+z-auto ⇒ 不是堆叠上下文，壁纸层 `z-index:-1`
   落到根堆叠上下文 ⇒ 被 `.app-shell` 的 `var(--bg)` 盖死 —— 什么模式都看不见。
   修：`isolation: isolate`（负 z 层关在聊天区内：透明背景之上、消息内容之下）。
2. **浓度语义错误**：默认 12% 的层透明度作用在**整个层** —— 粒子/3D/自定义图被一起压到 12% =
   全部隐身。修：浓度只作用于图案/自定义图，粒子/3D 满强度（粒子自带 0.55）；范围放宽 2~40%。

顺带：vanta 不支持透明背景（实测渲染成黑底、跟浅色主题打架）⇒ 背景色改取主题 `--bg`；
设置段五档按钮/图案选格/浓度行补样式（首版挤成两列）。

**验证（真实 UI 点击全链路，与用户同路径）**：设置→外观→点图案/粒子/3D 背景→关模态→截图 ——
图案档 40% 浓度下聊天区呈现清晰主题色圆点壁纸（截图 `.e2e-artifacts/shots/02-ui3-pattern-40.png`）、
粒子档 canvas 真跑、vanta NET 网格在 three 0.183 上完整渲染（`03-ui2-vanta-chat.png`）。
守卫【wp】+1=14 条（「浓度只压图案/自定义图」，变异命中），EXPECTED_CHECKS 3217→3218。
⚠️ 持久化口径与主题同源（localStorage）；harness 的 file:// 临时 profile 里 reload 会丢 ls
（主题同样丢）—— 真实应用重启行为跟随主题先例；若用户报「重启后壁纸/主题丢失」则为
系统性 file:// 存储问题，需要 app-settings 持久化方案（另行立项）。

## 10-06 追加：按用户反馈打磨（粒子可见 / 图案重设计 / 精选渐变 / 主题跟随 / 启动页语义）

- **粒子没效果**：素点无连线肉眼不可见 ⇒ 点+邻接连线（70 点 / 2~4.5px / 距离 130 / 线宽 1）；
  深色主题下发白 = 引擎画布背景不可信 ⇒ CSS `canvas { background: transparent !important }` 双保险；
  颜色跟随主题（MutationObserver 监听 data-theme ⇒ 重取 accent 并重挂引擎）。
- **图案重设计**：10 款 48px 大瓷砖（首版 24px 小瓷砖铺出来像噪点 = 「不好看」主因），
  新增 疏星 / 蓝图 / 环纹 / 等高线，线条 1.2px。
- **自定义图档内置 6 款精选渐变**（霞光 / 青柠 / 暮紫 / 深海 / 墨石 / 余烬）：mesh-gradient 风格
  多层 radial-gradient + feTurbulence 噪点，`preset:<id>` 走 CSS 渲染不过文件协议；设置段缩略图点击即用。
- **启动页语义纠偏（用户 10-06 定案）**：启动页跟真实加载阶段走、**不是硬延迟**；
  撤掉 MIN_SHOW 硬等待，保留 FAST_SKIP(300ms)；糊 logo 的真因 = index.html 呼吸动画的
  transform:scale 连续重采样 512px 大图 ⇒ 改为纯透明度呼吸（动画保留、不再发糊）。

## 10-06 二追加：铺满全应用（用户举例：侧栏 / 输入框 / 输入框上下都没背景）

- 壁纸层挂载点从 timeline-wrap **上移到 AppView 根（.app-shell 首子元素）**，fixed 铺满视口；
  `.app-shell { isolation: isolate }` ⇒ 负 z 层画在 shell 背景之上、全部内容之下。
- 真机遍历（从 .composer 向上爬到 body）抓出**三块不透明中间层**：`.app-shell` 自身、
  `.workspace`（主列容器，白底）、`.composer`（var(--bg)）⇒ `data-wallpaper` 驱动逐层放行
  （app-shell / workspace 透明、composer 55% 半透明、sidebar 72% 半透明），关掉壁纸属性摘除、一切还原。
- 守卫【wp】21 条（放行规则四层逐层钉住，漏一层 = 一块白底），全量 check 0 红。

## 10-06 三追加：拓展接口 + ？号制作教程（用户：「Codex 自己也能给自己做壁纸…支持复制提示词」）

- **免改码拓展接口 = 网关新能力 `wallpaper_set`**：pattern（10 款图案id）/ particles / vanta / custom（`preset:<id>` 或生图写入工作区后的绝对路径）。执行端校验（mode 白名单 + 图片可信根 + 扩展名）后 `sendToWindow(wallpaper:apply)`，渲染层接推送走 **saveWallpaper 同一条链路**（与设置页同源，落 localStorage）。

- **？号教程**：壁纸段标题行「? 制作教程」展开四张提示词卡（精选渐变 / 平铺图案 / 图片壁纸+wallpaper_set / 粒子调参），每卡**一键复制**（copyTextToClipboard + 已复制回执）。

- 守卫【wp】29 条（含四类提示词 / 复制按钮 / wallpaper_set 三处接线 / 可信根闸）；⚠️ 修正一处账目认知：EXPECTED_CHECKS 只统计 check-preflight 自身断言，独立守卫文件（wp/kb/mv）的条数**不在其内**——此前几轮往 EXPECTED 里加守卫条数是错的（并发会话 3204 为准）。


## 10-06 四追加：启动崩溃修复（ParticlesProvider init 引用不稳定）

- tsparticles v4 校验 `init` 回调必须跨生命周期稳定——内联箭头函数每次渲染都是新引用 ⇒ 整树抛错（错误边界兜住成「界面发生错误」卡片）。修：init 提为**模块级常量** `initEngine`（引用永稳定），真机复验：粒子档 canvas 正常、无崩溃（截图 01-ui11-particles-fixed.png）。


## 10-06 五追加：安装弹窗被关进滚动容器（12 处内联弹窗同类修复）

- 用户实测：官方插件安装弹窗出现在设置内容区里，要滚动才能看见。真机注入复测定位真因：`.settings-content > section` 的 **content-visibility:auto 会创建 containment**，把内联的 position:fixed 弹窗变成相对该区块定位（offsetParent=区块本身）。

- 修法（一处 CSS 修全部 12 处内联弹窗，含未来新增）：`.settings-content > section:has(.modal-backdrop) 等三个选择器在弹窗挂载期间放弃 containment（content-visibility: visible）`。真机复测：fixed 弹窗恢复铺满视口（0,0 → 1280×800）。受影响清单：Connectors×2 / RelayCenter×3 / SkillsMarket×4 / SshModals×2 / SearchPreview。
