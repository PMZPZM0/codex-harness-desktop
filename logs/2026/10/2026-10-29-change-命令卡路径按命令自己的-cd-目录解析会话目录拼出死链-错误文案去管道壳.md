# 命令卡路径按「命令自己的 cd 目录」解析（死链修复）

## 用户反馈

10-29 22:03 截图 + 10-30 06:03「还是这样」：右栏预览显示
`[ERR_INVOKE_FAILED] fs:read: Error invoking remote method 'fs:read': Error: 文件不存在或不可读：D:\测试\src\lib\command-display.mjs`

## 根因（截图 + rollout 双重证据）

- 会话 cwd = `D:\测试`；模型实际执行的命令是
  `cd 'D:\Codex Harness Desktop'; $f = '.\src\lib\command-display.mjs'; Copy-Item $f …`（rollout 原文可查）。
- 卡片把这条**相对**路径按**会话目录**拼 ⇒ `D:\测试\src\lib\…`。
- 实测该目录下**连 src 都没有**（`ls D:/测试` 只有 AGENTS.md / ego-test / news-tmp …）；
  真正的文件在 `D:\Codex Harness Desktop\src\lib\command-display.mjs`。
- ⇒ 不是"预览坏了"，是**卡片给的路径本身是死链**。上一轮取消可信根没错，
  但把这类失败原样暴露成了管道壳报错（`[ERR_INVOKE_FAILED] … Error invoking remote method …`）。

## 改动

1. `src/lib/command-display.mjs`
   - `commandWorkdir(command)`：解析命令**开头**的 `cd` / `chdir` / `Set-Location` / `sl` / `pushd`。
     只认**绝对**目录；`cd ..` / `cd src` 推不出来就返回空串（不猜）。只看开头那一段
     （`; cmd1; cd B; …` 里的 cd B 属于后续步骤，当基准会张冠李戴）。
   - `resolveCommandTarget(command, target)`：相对目标按 cd 目录补全；已是绝对路径 / 命令没 cd /
     含 `..`（可能逃出 cd 目录）时原样返回，交给下游兜底。
2. `TerminalPanel.tsx`：点击与 tooltip 用 `openTarget`（解析后的绝对路径），表头仍显示短名。
3. `src/lib/ipc-error.mjs` 新增 `ipcErrorMessageOf()`：剥三层壳（`[ERR_…]` 前缀 / 通道名 / Electron
   `Error invoking remote method`）只留主进程那句原因。三处预览面（右栏 `03-workspace-files` /
   居中 `useFilePreview` / 内联编辑 `Preview`）统一走它。
   ⛔ 原来各写一条只认 `^Error invoking remote method` 的正则，**对带 `[ERR_…]` 前缀的形态完全不生效**
   —— 用户截图里那串就是这么漏出来的。通道名本身带冒号（`fs:read`），第一版正则只吃到 `fs:`，
   留下的半截更难看（实测踩到，已改成按「冒号分隔多段」整体吃）。
