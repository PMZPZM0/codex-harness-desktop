# 语音播报改由 Codex 自写播报稿并配套两条工具与播报中状态条

# 语音播报：内容改由 Codex 自己写（播报稿 + 两条真工具 + 播报中状态条）

用户原话三点：①「播报语气过于平淡、缺乏表现力，改成让 Codex 根据上下文自行决定并生成播报内容」；
②「让 Codex 知道这个功能与能力」；③「增加播报进行中的实时反馈、支持随时停止」。
补刀一句最关键：**「记得配套对应工具，没工具他调用不了」**。

## 结论

**① 播报稿（内容通道）** — 新增文本层 `src/lib/voice-script.mjs`（纯函数 + 纯状态机）。
模型在回复**末尾**用 `voice` 围栏写一段口语化播报稿；同一份原文被三处消费：

| 去处 | 用什么 | 做什么 |
| --- | --- | --- |
| 结束汇总播报 | `resolveAnnounceSummary` | **优先念模型写的稿**；没写才回退本机压缩（`voice-summary.mjs`） |
| 实时正文播报 | `createVoiceScriptStripper` | 这块**整块跳过**（否则同一句念两遍，还会把围栏符号念出来） |
| 屏幕显示 | `stripVoiceScript`（挂在 `Markdown.tsx`） | 整块剥掉 —— 稿是给耳朵的，摊在对话里只是干扰 |

「平淡」的根子在本地摘要机上，所以这层的关键是：**优先念模型写的，本机压缩只做回退**。
写流式剥离器时踩到一个真 bug 并修掉：**块未闭合就 flush 会让状态永久停在块内**
（之后喂什么都当播报稿丢）—— 是守卫里那条真值表跑出来的，不是读代码读出来的。

**② 让 Codex 知晓 + 有工具** — 三件事必须同批落地，缺一件就退化成「知道但用不了」：

- **指令**：`developer-instructions.ts` 第 16 条常驻，把围栏契约**逐字**写进每轮上下文
  （它与第 11/12 条同款理由：这类通道不在任何工具/技能清单里，不写清格式模型只好继续写干巴巴的总结）；
  判据沿用第 15 条的范式 —— **只看会话里那条告知**（【语音播报已开启】/【语音播报已关闭】），不外推。
- **告知**：`voice-notice.ts` 出文案，`announce-bus` 出转发出口，AppView 处会话闸后发进会话；
  ⛔ 首次读到设置**不发**（否则每开一次窗口就往会话里塞一条「已开启」，用户什么都没干却被告知）。
- **工具**：`dispatch-core.ts` 登记 `voice_announce`（立刻念一句话，≤120 字）与 `voice_announce_stop`，
  执行端在 `dispatch-rpc.ts`。二者自动进 `harness_tools` 网关 —— 这是引擎 0.157 后**唯一**的可见通道。
  ⛔ 主进程没有扬声器出口（`voiceService.speak` 只到 PCM）⇒ 广播 `harness:event` 由渲染层的播报队列执行，**立刻返回**。
  ⛔ 通话中明确拒绝（扬声器独占 + AEC 参考环；两条一起放 = 回声 + 抢话，且停止按钮管不到通话那一路）。
  ⛔ 返回值只证明「已提交」，不证明「已听到」—— 文案里明说，不许模型据此声称「我说给你听了」。

**③ 实时反馈 + 随时停止** — `announce-bus` 加状态广播（执行端推事实：有没有在念 / 正在念哪句 / 还排几句 / 来源），
新增 `VoiceAnnounceIndicator` 挂在 composer 内（要 `closest('.composer-wrap')` 才能贴输入框，与舞台条同一套定位纪律），
显示「正在念正文 / 正在念小结 / Codex 插播」+ 当前句 + `待播 N 句` + **停止**按钮 ⇒ `requestAnnounceStop`。
「已停止」只是一句**回执**（1.6s 后自动收起），绝不能变成一条永远挂着的空提示。

## 为什么这么切（留给下一个改这块的人）

- **能力 ≠ 可用**：只发指令不发工具，模型知道也调不到 —— 用户那句「没工具他调用不了」就是这个意思。
  同理，工具面登记完还要在**渲染层 `harness_tools` 描述**里点名（不在那个清单里，模型就看不到这个名字）；
  预检里那条「渲染层描述列全了主进程的能力清单」当场抓到了这次的漏项，不是靠记性。
- **一个能力别挂两个名字 / 别两处各判一半**：`toolSpeak` 最早只声明了分支、没人发布（等于 dead contract）；
  改成「广播 → 发布进总线 → 总线订阅处唯一裁决」后，避让/串行链/状态只用维护一处。
- **告知文案里不能写真围栏**：它会作为用户消息渲染，随后被「渲染前剥离」整块吃掉 ⇒ 用户看到半截话。
  所以文案用「三个反引号 + voice」的文字描述，精确格式放在不会被渲染的第 16 条里。
