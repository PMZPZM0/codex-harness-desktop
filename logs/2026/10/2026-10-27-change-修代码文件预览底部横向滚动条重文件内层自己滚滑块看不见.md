# 修代码文件预览底部横向滚动条：重文件内层自己滚+滑块看不见

用户：「文件灯箱预览和右侧栏的代码文件预览底部的左右滑动条，你做了吗，我咋没看见你验收」
追加：「重文件走纯文本是为不卡应用，要不然很卡」——即：修滚动条不许动反卡顿通道。

## 事实（真机量出来的）

两处都**没有可用的**横向滚动条，两个独立原因：

1. **重文件分支的内层 div 自己滚**：`heavy`（>20K 字符 或有 >300 字长行）走纯文本渲染，
   内层是 `<div style={styles.pre}>`，而高亮主题的 `pre` 样式里带**内联 `overflow:auto`**。
   上一轮的规则写的是 `.file-preview-code pre { overflow:visible }` —— 选择器只认 `<pre>`，
   盖不住这个 `<div>` ⇒ 滚动条又被推到整篇代码的最末尾（长文件要滚到第 1000 行才够得着）。
2. **滑块颜色看不见**：全局滚动条滑块是 `--panel-2`，压在 `--panel` 底的代码区上几乎同色。

## 改法

- 纯文本分支的内层 div 加类名 `file-preview-code-inner`。
- 右栏（`.workspace-file-preview-body > .file-preview-code > .file-preview-code-inner`）与
  文档预览弹窗（`.file-preview > .file-preview-code > .file-preview-code-inner`）都把它改成
  `overflow: visible !important`，滚动交还**有界的外层容器** ⇒ 横向滚动条钉在可视区底沿。
- 两处代码预览的滚动条给实色滑块（`--muted` 75%）+ 浅轨道，不再用 `--panel-2`。

## 反卡顿通道（用户点名要保）

⛔ 一行没动：`heavy` 判定、纯文本渲染（单个文本节点、无行号、无 token 着色）全部原样。
实测该文件仍走 `data-lazy-highlight="plain-heavy"`、代码块内 `span` 数 = 0。
本轮的改动只换了"谁滚动"与"滑块什么颜色"。

## 验证（这次是真机量的）

右栏打开 `src/features/settings-mcp/McpSettingsSection.tsx`（最长行 2081 字符）：
- `data-lazy-highlight = plain-heavy`，`tokenSpans = 0` → 纯文本通道没被破坏
- `.workspace-file-preview-body`：`scrollWidth 14649` vs `clientWidth 277` → 真的横向溢出
- 滚动条槽位 `10px` → 底部确实有一条横向滚动条
- 内层 `overflow = visible` → 滚动条不再挂在内容末尾
- 截图 `01-code-preview-plainpath.png`

守卫 11p-file-summary 84/84（新增 3 条：内层类名 / 右栏+灯箱都不自己滚 / 滑块实色）。

## 没能驱动到的部分（如实记）

文档预览弹窗 `.file-preview` 的入口是"文件卡片右键 → 打开"，测试 profile 里没找到带文件卡的会话，
这条路径没在真机上点开（弹窗与右栏用的是**同一个** FilePreviewCode 与同一条 CSS 规则，
右栏的实测覆盖了同一段逻辑）。灯箱这条我标为"按同一规则覆盖、未单独点开"。
