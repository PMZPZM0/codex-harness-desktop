# 群汇报卡改版：成品落盘出文件卡 + 移到消息下方 + 轻卡片

## 用户诉求（10-26 原话）

> 「这个群事件展示优化一下，现在太丑了」
> 「我看不见方案内容」
> 「放到消息下面，不要放上面」
> 「其他对话框里面可以文件预览的吧」

四条其实是同一件事：**群广播被当成用户消息渲染**——右对齐、占用户气泡位置、正文几千字全铺在气泡里、外面还套三层框（粗竖条 + 面板底色 + 双层方框）。

## 做法（四件套）

| 诉求 | 落地 | 位置 |
|---|---|---|
| 看不见方案内容 | 交活正文**落盘** `群交付/<taskId>-<标题>.md`，广播文本带 `成品文件：<路径>` 行；界面出 **FileRefCard**（点开 → 文件预览） | `runner.ts:saveDeliverableFile` + `UserMessageView:GroupFileCard` |
| 太丑 | 去掉竖条/底色/双层框 → 轻卡片：成员头像（按名字取色）+ 名字 + 徽标 + 标题，正文小字灰 | `47-boss-group-view.css` `.group-msg*` |
| 放消息下面 | 群广播从「回合卡上方」移到「回合卡之后」：它是宿主注入的机器消息，不占用户气泡位置 | `03-turn-view.tsx`（`plainUserItems` / `groupUserItems` 分流） |
| 文件预览 | 复用既有 `FileRefCard`（与其它会话产物卡同一套手感） | 同上 |

## 关键取舍

1. **落盘位置**：群工作区优先（用户在自己项目里就能找到），群没有工作区才落 `<userData>/boss-groups/outputs`。落盘失败**只告警、不阻断交活**——降级成「无文件卡的纯文本交活」，不能因为写文件失败就丢掉成员的活。
2. **判据同源**：`isGroupEventText` 必须与 `parseGroupEvents` 一致（解析出块才算）。早先只查 `includes("[群事件]")` ⇒ 用户正文里提到该字样、或文案漂移解析不出块时，会出现「位置挪到下面、样式还是用户气泡」的两套判据打架。
3. **书名号幂等**：任务标题常常自带《》（`出《口播视频制作规范》`），外层再包就是 `《出《…》》`。判据不能只看首尾字符（首字是「出」、尾字是「》」仍会嵌套）⇒ 只要标题里已含一对书名号就原样返回。
4. **守卫【160】**：`--group-hue` 是内联注入（按成员名 hash，同名恒同色），登记进白名单而不是在 CSS 里硬造单一值。
