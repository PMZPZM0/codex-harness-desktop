# 输入框底栏动态状态灯：最多亮一盏、多了轮流、窄窗自适应隐藏

## 背景
用户圈出输入框底栏「完全访问」胶囊右侧的空位（对照 Qoder 截图），要求在这里动态显示后台状态图标：目标模式 🎯、后台命令挂起等，「还有其他你看着补充」；展示规则用户定稿：**最多展示一个，多了就动态轮流展示**，且要跟随窗口大小自适应隐藏。

## 结论
- 六盏灯（优先序即轮换序）：目标模式（Target，活动呼吸/暂停灰/受阻红/完成绿）→ 等待选择（Bell，agentAsk）→ 挂起消息（Clock3，有定时项走 AlarmClock + 条数徽标）→ RPA 配方（Workflow）→ 子智能体（Bot）→ 专家团（Users）。
- 展示：同一时刻**单节点**渲染 `lights[rot % lights.length]`，多盏时 3s 轮换（key 变化触发 fade-in）；无状态**不渲染节点**（不是隐藏空壳）。
- 自适应两档：≤1280px 收文字只留图标、≤1060px 整块隐藏。⛔ 用窗口媒体查询，**不给 .composer 开 container-type** —— inline-size 容器带 layout containment，会给 quick-pop 弹层造新包含块把翻转定位弄歪。
- 数据全走既有 bag 状态（goalText/goalStatus/agentAsk/queue/queueTimers/rpaRunning/subAgentRunning/expertTeamRunning），组件零 IPC（守卫钉「渲染路径不许打引擎」）。

## 依据
- 验收 `status-lights` 5/5：空闲无灯 → 真 RPC set(paused) 灯亮 tone-muted + 单盏 → CDP 视口 1000px 隐藏/1240px 只留图标/复原可见 → 点目标条删除键灯灭 + 引擎 goal 清空。
- 守卫 `12d` 15/15，7 处变异全抓（map 铺开 / 轮换删除 / 组件内 fetch / 接线断 / 位置挪到胶囊前 / 1060 档删除 / container-type 回归）。

## 影响面
- composer 底栏（`composer-left` 权限胶囊之后）新增一个元素；`Status` 域多一个导出。
- ⚠️ 同轮实测发现 **goal-bar ⑤ 为存量环境失败**（与本改动无关）：验收 profile 的模型走 `env_key = "CODEX_HARNESS_API_KEY"`，本机未设该变量 ⇒ 引擎目标一继续立刻 `blocked`、timeUsedSeconds 恒 0，「计时在跳」断言在任何代码版本下都过不了。修法 = 给该环境补 API Key 或换 profile 模型，未动。
