# 语音播报去重改句子级——修重复播放好几次

# 语音播报去重：整段比键 → 句子级比键（修「同一段内容重复播放好几次」）

## 现象

用户复报：**「codex 自己写的语音播报内容会重复播放好几次」**（上一轮（`0eb9f3a`）只按「重复两次」修过一版，未根治）。

## 根因（真跑复现，不是读代码推的）

上一版把去重键加在 `speak()` 入口，但算键的对象是**这次调用传进来的整段文本**。
三条入口喂进来的**切分粒度不同**：

| 入口 | 喂给 speak 的粒度 |
|---|---|
| 正文实时 | **逐句**（断句器已切好，一句一次 speak） |
| `voice_announce` 工具插播 | **整段**（一次） |
| 结束稿（汇总链） | **整段**（一次） |

⇒ 整段算出来的键是「好几句拼起来的串」，永远对不上逐句喂时那句单独的键。
真跑复现（`.workbuddy/tmp/voice-dedupe-repro.mjs`，走真函数的旧逻辑）：

```
① 工具插播: 出声  <- 键=都改完了可以验收了
② 正文逐句 "都改完了。": 出声  <- 键=都改完了      ← 同一句
② 正文逐句 "可以验收了。": 出声  <- 键=可以验收了   ← 同一句
③ 结束稿(整块): 出声  <- 键=都改完了可以验收了辛苦了  ← 同一句第三次
```

而「工具的返回值 + developer-instructions 第 16 条」**要求模型把插播句写进正文**（合成失败时的兜底），
所以这条路径是必然发生的，不是偶发。

## 修法

- `src/lib/voice-script.mjs` 新增纯函数 **`dedupeSpokenSentences(text, seen)`**：
  按句切开 → 逐句算 `spokenDedupeKey` → 剔掉已登记的 → 返回「仍需念的部分 + 这批句子的键」。
  同一次调用内部也去重（同段里重复的句子只念一次）。
- `use-voice-announce.ts` 的 `speak()`：查重与登记都换成它（**登记在合成成功之后**不变；
  基准仍单列在检查、`busy+1` 之前）；合成用**去重后**的文本。
- 回退路径（模型没写播报稿时的本机压缩）也一并受益：压缩稿里与正文重了的句子不再念第二遍。

⛔ 没改工具契约：删「写进回复」那句指令也能断重复，但它背着「本地 TTS 没装时静默无声」的兜底职责
（删了会让用户一个字都听不到），上一轮已判定不改。

## 判据

- 守卫 `11z-voice-call` **98 → 103/103**：新增「逐句查重 / 合成用去重后文本 / 登记每个句子的键」
  三条结构断言 + `dedupeSpokenSentences` **真跑真值表 4 条**（整段先念后逐句喂只吐新句 / 同段内去重 /
  单独再喂也拦得住 / 空与 null 安全）。
- 变异测试 2 条全抓：① 跳过条件写死 false（等于不查重）→ 红；② 纯函数退回整段比键 → 红。
- 修后真跑：同一场景变成「每句只念一遍」（重复句被拦，只多念了真正的尾句「辛苦了。」）。

## 诚实边界

- 未加 e2e 验收项：播报出声要本地语音模型（验收 profile 里没有，合成会直接失败），
  CDP 侧无可观测判据；本条的判据落在守卫的**真跑真值表 + 结构断言**上。
- 若同一句话被模型写成「前半句 + 后半句」两种不同句子（不是同一句），不算重复、不会被拦 —— 这是刻意
  （按句比键的代价），否则会把「语气略有不同」的正常播报误吞。
