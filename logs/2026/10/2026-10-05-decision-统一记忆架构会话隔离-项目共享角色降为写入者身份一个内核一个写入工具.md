# 统一记忆架构：会话隔离 + 项目共享，角色降为写入者身份（一个内核/一个写入工具）

# 统一记忆架构（会话隔离 / 项目共享）

## 结论

改造前全仓有**两套并行**的记忆实现，彼此不知道对方存在：

| | 系统 A：L0–L7 分层 | 系统 B：角色私有记忆 |
|---|---|---|
| 实现 | `memory-layers.ts` + `memory-store.ts` 碎片池 | `role-memory.ts` |
| **谁能写** | **只有主会话**（`memory_save`） | **只有角色会话**（`role_memory_save`） |
| 读 | 全体（含被委派会话） | 仅该角色自己 |
| 条目形态 | 纯 Markdown 追加行 | 纯 Markdown 追加行 |

⇒ 模型必须自己判断"这次该调哪个写入工具"。那是"两套同名能力"的变体——
项目已经踩过同款坑（`agent_invoke` 与 `subagent_invoke` 并存 ⇒ 模型只用名字最直白的那个
⇒ 专家/专家团被绕过）。

## 改造后的形态

**一个内核 + 两种作用域 + 一个写入工具**：

- 作用域只有两级：`session`（按 `threadId` **硬隔离**）/ `project`（**全局共享**）
- **角色从"存储维度"降级为"写入者身份"**（`sourceAgent` 字段）
- 工具统一为 `memory_write`（旧名只作别名，走同一 handler）
- 条目结构化（`entries.jsonl`）：内容 / 来源智能体 / 所属会话与项目 / 分类 / 权重 /
  钉住 / 创建与更新时间 / 最近使用 / 归档时间

**关键决策：为什么角色不再是存储维度。**
若保留"每角色一份记忆"，同一个专家在两个会话里的记忆就**不互通**——
而用户这次明确要求"被调度的专家智能体与主会话共用同一套记忆实现"。
⇒ 角色只回答"这条是谁写的"，写进哪个作用域由 `scope` 决定。

**关键实现：隔离靠寻址，不靠过滤。**
`session__<threadId>` 与 `session__<other>` 是两个不同的**目录**，检索在物理上
只能扫到句柄对应的那一个。⛔ 不做"读全量再按 sessionId 过滤"——漏一个条件
就是串扰事故。

## 实跑抓到的 5 个 bug（纯文本守卫全绿时）

1. **噪声召回**：`tokenize` 出「逐字 + 双字 bigram」，"蓝绿部署"会命中 `部`/`署`
   ⇒ 查一个项目里没有的词，召回了 6 条不相关内容。修：相关性双阈值
   （长 token ≥3 字命中即算；短 token 需命中 ≥34%）。
2. **`score = 0` 仍被返回**：`limit` 默认全量 ⇒ 只把不相关条目排到**后面**
   不等于过滤掉。修：带 query 时不相关的直接不返回。
3. **报数不实**：`section` 过滤后仍报全量条数 ⇒ 改报「本次注入 N / 命名空间共 M」。
4. **记账用 `appendFile`**（code review 抓出）：残缺行会被 `readNamespace` 原样返回，
   `rankEntries` 拿到 `undefined` 字段。修：必须**就地重写整份文件**。
5. **归档只是装饰**（code review 抓出）：打了 `archivedAt` 标记但检索不过滤
   ⇒ 归档形同虚设。修：归档 = 打标记 + **退出检索**（内容保留，`includeArchived` 才读）。

## 生命周期归属裁决

| 事件 | 会话记忆 | 项目记忆 |
|---|---|---|
| 角色跑完回合 | 保留 | 保留 |
| 会话归档 | 保留 + 打标记 | 保留 |
| 会话删除 | **保留内容**，清索引 + 退出检索 | 保留 |
| 角色定义被删 | 条目成孤儿（不自动删） | 保留 |
| 会话 fork | **不继承** | 继承 |
| 保留期 90 天 | 归档，不删 | — |

**核心裁决：会话记忆按"内容归属"而非"会话存活"决定去留。**
删会话删掉的只是**寻址它的索引**与**检索资格**，不是记忆本身——角色还在，
下次派出同一角色继续用它积累的经验。

## 写入闸与身份闸

- 角色写 `project` 必须 `promote=true`（需先征得用户同意）——
  `project` 是全局共享的，一个子智能体把中间结论写进去会污染所有会话。
  ⛔ 拒绝理由必须**可转达给用户**（模型要能直接念给用户听）。
- ⛔ 身份只用**引擎下发的 `params.threadId`** 反查索引，
  **绝不用 args 任何字段当身份**（那等于让模型自报家门）。
- ⛔ 角色会话的工具调用**必须在主进程应答**（`boot.ts`，排在 `filterForRenderer`
  **之前**）：被委派会话不在渲染层"正在看着"的列表里 ⇒ 事件被裁掉 ⇒ 调用挂到超时。
- 分类走**五类白名单**（⛔ 不用 `as` 断言绕过——类型断言不做运行时校验，
  模型自造词会让条目落在错误的权重档，裁剪时先被淘汰）。

## 门禁与两条假绿

守卫 `scripts/guards/11l-memory-fabric.mjs` **77 条** + **实跑 64 项** +
**变异 16/16 全部如期变红**。其中两条第一版是**假绿**：

1. 隔离只有**负向**断言（"不许出现过滤写法"）⇒ 把 `recall` 改成读别人的命名空间
   不红。⇒ 补**正向**：必须 `readNamespace(workspace, ns)` + 函数体内不出现别的键。
2. 只查"归档调用存在" ⇒ 把它藏进 `if (false && …)` 照样绿
   （**只验落地不验执行**）。⇒ 钉住触发条件本身。

## 已知边界

- 检索是**关键词式**（中文 bigram 近似），不是语义式。留 `score` 唯一注入点可替换。
- `entries.jsonl` 不做并发写锁（当前写入单主进程串行）。
- 角色写项目记忆需用户确认，多一次交互——⛔ 这是权限边界，不为方便而放松。
