# 独立弹窗补齐顶栏搜索与调度两个图标

# 独立弹窗补齐顶栏图标（🔍 搜索 + 调度开关）

用户实测报障（附对照截图）：主窗口顶栏有 🔍 搜索与 👥 调度，**独立弹窗里这两个都不见了**。

## 根因：弹窗分支把**整簇**换掉了

`src/features/app-state/parts/part09/02-seg.tsx` 的 `topbarActionsNode` 原本是：

```jsx
{bag.popoutThreadId ? (
  <button … popout-return-btn …/>        // 弹窗：只有「返回主应用」
) : (
  <>                                     // 非弹窗：🔍 搜索 + 调度 + 「独立弹窗」
    …
  </>
)}
```

⇒ 弹窗里只剩一个「返回主应用」，其余全没了。而同一份注释里写着「弹窗窗口与主窗口**同构（完整侧边栏/顶栏都带着）**」——
**注释与实现不符**：搜索是 09-24 才加的顶栏入口，加的时候被放进了「非弹窗」分支，并非有意排除。

## 性质：一个是"漏的"，一个是"有意为之"

- 🔍 搜索：**漏的**（没人说过弹窗不要搜索，它跟着分支一起被排除了）；
- 👥 调度：**原本有意不渲染**（`docs/CHANGELOG-ROUNDS.md` 明写「独立窗口模式下该按钮不渲染」，
  帮助弹窗也对用户说「会话开在独立弹窗里时该按钮不显示，回主窗口开」）。
  ⛔ 用户 10-11 决定**两个都补齐** ⇒ 这条旧口径**作废**。

## 改法

- JSX：把 🔍 与 `<DispatchMenu>` 挪到**弹窗三元之外**（两种窗口都渲染），三元里只留
  「返回主应用 / 独立弹窗」二选一 ⇒ 顺序统一为 `🔍 → 调度 → (返回主应用|独立弹窗) → ⋯ → 右栏开关`。
  ⛔ `<DispatchMenu>` 仍然**只有一处 JSX**（守卫【04】数它，必须为 1）。
- 文案同源三处：`HelpDialog`（用户看的帮助）、`electron/dispatch.ts`（给模型的拒绝语，会被原样转告用户）、
  `docs/CHANGELOG-ROUNDS.md`（旧口径标记作废）。⛔ 这类"开关在哪"的文案必须跟着行为改，否则用户照旧去找。

## 判据

- 守卫【04】新增两条：**位置关系**（`history-search-wrap` 与 `<DispatchMenu` 的 `indexOf` 必须**早于**
  `{bag.popoutThreadId ? (`）+ **三元只二选一两个按钮**（正则锚住 return→open 的形状）。
- **变异测试**：把该文件回退成 HEAD 版（= 弹窗只渲染返回按钮）⇒ 两条断言**都红**，还原后绿。
- ⛔ 踩到并记下：**聚合器 `readAppUi()` 对 `app-state/parts/**` 会剥掉 `bag.` 前缀**（历史口径），
  所以带 `bag.` 的字面量在聚合面上**永远匹配不到** ⇒ 位置类断言必须读**该文件原文**。
- `npm run check` 退出码 0；`npm run accept`（默认轮 10-12）**15/15**；
  `accept --only history-search` **7/7**（我动过那个按钮，必须真跑一遍）。

## 诚实边界

- 调度是**全局独占锁**（按 thread-runtime 记录派生，全应用只有一个持有者）。现在两个窗口都渲染这个菜单，
  **每边显示的都是自己那个会话的状态**，写入仍由主进程裁定 —— 逻辑上没变，但"两窗口同时开着这个面板"是新的
  形态，下一步真机用的时候留意一下有没有互相打架（若发现，再决定是否只读展示）。
- 弹窗里**没有**加 e2e 断言（开弹窗会多一个 page target，harness 连错窗口是本仓记过的坑）——
  判据落在守卫的位置关系断言 + 回退变异上。
