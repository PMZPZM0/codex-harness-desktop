# 播报契约删掉写进正文要求并把播报稿收成一个重点

# 播报内容契约修正：删掉「怕听不到就写进正文」+ 只挑一个重点

## 起因（用户 + Codex 自查定性）

用户指出上一轮只治了执行端（句子级去重），**病根在文案层**：

> 「我知道 summary 开着，还硬把原句复述进正文（那是照搬工具提示『怕你听不到就写清楚』），
> 等于自己给自己叠了一遍。」
> 「播报内容是要 Codex 自己挑重点播报，不是长篇大论播报，那样没有意义。」

⇒ 两件事：① 契约不该要求模型把播报句写进正文；② 播报稿要「挑一个重点」，不是复述。

## 改动（四处文案 + 一处生成物，同轮）

| 位置 | 改前 | 改后 |
|---|---|---|
| `dispatch-rpc.ts` 工具返回值 | 「回复里请照常用文字把这句话写清楚，别指望它一定被听到」 | 「这句是说给耳朵的：正文里**别再原样复述**（同一句会被念两遍）」 |
| `developer-instructions.ts` 第 16 条 TOOLS 行 | `still write that sentence in your reply text` | `do NOT also paste it into your reply text`（重复 = 会被念两遍） |
| 第 16 条写法条 | `1–3 sentences` / `under ~80 characters` / 「说回复**增加了**什么」 | `PICK ONE POINT`（只挑一个最重要的人：结论 / 代价 / 风险 / 下一步）+ `ONE short sentence` + `under ~50 characters`；⛔ 逐句复述 = FAILURE |
| `dispatch-core.ts` 工具描述 | 「要念长内容就写进回复正文」 | 追加「这句是说给耳朵的 —— 再抄进正文就会被念两遍」 |
| `gen-capability-skill.mjs`（生成 harness-api 技能） | 「那句话照常用文字写出来」 | 「正文里别原样复述」 |

⛔ 第 16 条里 **live 通话那一句没动**（`Both are unavailable while a live call is open (then just write it in the reply — the call reads it out)`）：
那是**通话**链路（通话会把回复念出来），与本条要治的「非通话播报」是两条路。

## 为什么敢删兜底（推翻上一轮的判断）

上一轮留它的理由是「本地 TTS 没装时静默无声，模型得把话写出来」。用户定性后这个理由站不住：
写进正文 = **必然被念两遍**（正文实时链也会念），代价比偶尔没声音更大；而且播报稿本来就是**给耳朵的**
（`Markdown.tsx` 会整块剥掉，屏幕上根本看不到）⇒ 「写出来」并不能兜底，只是制造重复。
⇒ 用 `supersedes` 取代上一轮那条「不改工具契约」的结论。

## 句子级去重仍然保留

执行端那层是**兜底**，不是被取代：历史会话的旧契约、以及模型偶尔仍把结尾稿写进正文的情况都还在。
两条一起才叫治本 + 治标。

## 判据

- 守卫 `11z-voice-call` **103 → 106/106**：新增三条（第 16 条要求「只挑一个重点 / 一句话 / ~50 字」；
  **三处文案都不再出现「把播报句写进正文」**（负向，`codeOnly` 剥注释后比对）；反向要求写清楚）。
- 变异测试 2 条全抓：① 文案改回 `still write that sentence…` ⇒ 两条红；② 把 `PICK ONE POINT` 改回
  「挑亮点」这样的弱表述 ⇒ 红。
- `npm run check` 0 硬失败（含生成物重跑后一致）。

## 生效条件

模型侧文案来自主进程（`developer-instructions.ts` 的常驻块 + 工具 schema），**要重启应用**才生效；
且工具描述只在 `thread/start` / `resume` 注入 ⇒ 老会话切走再切回。
