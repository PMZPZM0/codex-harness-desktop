# 手机远控 0.1.16：移除拍照 / 返回退后台 / 思考历史顺序对齐实时

## 背景
用户实测三件事：① 手机 App 的「拍照」唤不起系统相机（两个产品都要删）；② 侧滑返回会落到「重新输入配对码」页，但设备秘密还在、重启本来就能自动登录 —— 设计缺陷；③ 重新进会话时思考板块跑到回答上方（实时是追加在流尾部），且被拆成多个块。

## 结论
1. **移除拍照**：手机页删掉拍照入口/隐藏 input/`takePhoto`/读取回调；安卓删掉 `capture` 分流、`CAMERA_REQUEST`、`cameraUri`、`FileProvider` 与 `res/xml/file_paths.xml`（相册/文件选择保留，一次最多 4 张）。APK 升 **0.1.16**（versionCode 17）。
2. **返回**：页面自己的面板先收（`__remoteBack`）；到底层改为 `moveTaskToBack(true)` —— 退到后台，**不再切配对页**、不改连接状态。换电脑/换服务器走菜单「断开连接」（清秘密并回配对页）。
3. **顺带修掉的同类隐患**：`showSetup()` 现在统一恢复按钮可用并 `authGen += 1` 作废在途认证（原来 `enterChat()` 只把 busy 置 false、没恢复按钮，返回后就是两个灰按钮）；已存设备秘密时，「连接」留空 = 重试自动登录。
4. **运行过程（思考/工具）位置**：历史严格按引擎 item 原顺序回放，思考与工具步骤各留在第一次出现的位置；连续的一段收成「运行过程 · N 步」，遇到正文/用户消息先收口 —— 不合并成整回合一块、也不挪到回合末尾。工具步骤（命令/工具/搜索）由 remoteStepOf 与实时同一套文案回放。

## 依据
- APK：`mobile-remote-v0.1.16` 已发布（Codex `765ab2f6…` / PP `10803fa7…`）。
- 服务端实测：tx `http://127.0.0.1:18700/apk` → 2800095 字节、sha 765ab2f6；PP 服务器 → 2888123 字节、sha 10803fa7（两处 RELAY_APK_URL 已切 0.1.16）。
- 守卫 04：手机页「拍照入口已移除」负向断言 ✓；「安装包版本与 Release 对齐（0.1.16）」✓。

## 影响面
- 两个 Android flavor 的安装包；手机页附件面板（少一个「拍照」项）。
- 手机端返回手势行为；配对页的可点状态；自动登录重试入口。
- 手机端历史回放的思考块位置与数量。

## 回滚
回退对应提交并重新出包发布；服务端把 `RELAY_APK_URL` 指回旧版本即可（旧 APK 仍在 GitHub Release 与 `/var/lib/relay/apk`）。
