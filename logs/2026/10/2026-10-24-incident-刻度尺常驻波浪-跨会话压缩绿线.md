# 刻度尺常驻波浪 + 跨会话压缩绿线

## 现象
用户在长会话里连续报两条：
1. 截图圈刻度尺：「这个刻度线，默认不触发波浪效果，只有滚轮滚动的时候，才触发波浪效果」；随后补「现在不滚动也触发，看着不太舒服」。
2. 截图圈绿色段：「这个绿色线，我没有压缩啊，也没有触发上下文压缩，怎么有绿色线」。

## 根因
1. 波浪中心是 `activeIndex = hoverIndex ?? currentPos` —— 只要视口在某个位置，当前刻度就永远带着上下邻的波浪；程序化滚动、加载完成、贴底跟随也会触发，等于常驻呼吸。
2. 刻度尺的压缩标记用 `compactionStateOf(win.ordered, compactToast?.state)` 推导，但 `compactToast` 是**全局一份、切换会话不会清**（成功提示要留给用户看）。在 A 会话压缩成功后切到 B，B 的 `compactionStateOf` 收到 `success`、turnId 为空；B 又没有宿主压缩记录 ⇒ `resolveCompactionAnchor` 回退到最后一条用户消息之前，刻度尺凭空长出一条绿线。时间线的分隔线有 `threadId === thread.id` 过滤，所以只有刻度尺绿线、没有压缩线 —— 用户看到的正是这个组合。

## 结论 / 做法
- 新增 `wheelWave` 状态：只由 scroller 的真实 `wheel` 事件点亮，最后一次滚轮后 600ms 自动收起。`activeIndex = hoverIndex ?? (wheelWave && currentPos >= 0 ? currentPos : null)`；hover 仍优先（显式交互）。程序化滚动 / 懒加载 / 贴底 / 跳转一律不触发。卸载时摘监听并清定时器。
- 时间线推导压缩态前先按会话过滤：`threadCompactToast = compactToast && compactToast.threadId === thread.id ? compactToast : null`，刻度尺与分隔线两处 `compactionStateOf` 都用它。
- 验收 `ruler-wave`（登记 10-24）改为：② 程序化滚动后无 wave 类；③ 派发真实 WheelEvent 后中心 26 / 邻 18 / 外 15、左端对齐；④ 900ms 后波浪收起。点击刻度目标从「越界回绕 idx 0」改为「窗口内 cur±3」—— idx 0 常是窗口最旧、需要额外水合的回合，点击后 1.5s 内 group 未挂载会造成假红（本轮实测复现两次）。
- 保留原有 ⑤ 当前刻度跟随、⑥ 点击刻度贴顶、⑦ 压缩绿线跟随波浪、⑧ 点击绿线跳转。

## 判据
- 守卫 12r（compaction-anchor）32 条：新增滚轮门控三条（点亮 / 600ms 收起 / 摘监听）与 toast 按会话隔离一条；07【165】的 state 推导锚点同步为 `threadCompactToast`。
- 验收 ruler-wave 8/8（②③④ 为本轮新增口径）；主仓默认轮 46/46。
