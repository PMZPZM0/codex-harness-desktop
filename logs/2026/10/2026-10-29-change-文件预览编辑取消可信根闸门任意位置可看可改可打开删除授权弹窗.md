# 文件预览/编辑取消可信根闸门：任意位置可看可改可打开，删除授权弹窗

# 文件预览/编辑取消可信根闸门（任意位置可看可改）

## 用户令（原话）

「不用授权弹窗，文件预览联动可以直接看和编辑，不管哪里的文件，都要可以预览和编辑」。

## 根因（先定位再改，不是猜）

「项目地址外的文件预览不了 / 总是显示预览失败 / 文件也是直接显示打开失败」不是缺授权机制，
而是**只有一条链**接了它。四条越界路径、四种行为（真机 CDP 复现，见下表左侧）：

| 链路 | 改前行为 |
|---|---|
| `fs:read`（文本预览） | 抛 `OUTSIDE_TRUST:<dir>` → 应用内模态 → `fs:allow` → 重试 ✅ |
| `harness-image`（图片 / PDF 预览） | 直接 403 → 破图；渲染层连错误对象都拿不到 ❌ |
| `shell:open`（系统默认应用打开） | 一句中文「仅允许打开会话工作区…」，**没有可走通的路** ❌ |
| `image-lab:view`（模型 `image_view`） | 一句中文「路径不在可信目录内」→ 模型回「预览失败：…」❌ |

另有两套并行预览实现（右栏 `03-workspace-files` / 居中 `useFilePreview`）与两处媒体授权
（`MediaPreview.authorizeDirectory` / `Preview` 内联「允许并预览该目录」）—— 一共 **4 个预览面**，
各写一份判定，所以修一处只解决四分之一。

## 改动

**主进程（摘闸，保留最小约束）**
- `fs:read` / `fs:write` / `fs:exists` / `fs:reveal`、`shell:open` / `shell:reveal`
- `image-lab` 取图路径闸 + 显式 `output` 落盘闸
- `harness-image` / `harness-media` 两个协议的路径闸
- 保留：`fs:write` 忽略渲染层自报的 root、预览读 2MB 上限、图片/媒体 MIME 白名单、图片 128MB 上限、
  定位要求真文件

**删除授权链整条**
`fs:allow` 通道（593→592）、`allowUserPath()`、`src/lib/file-trust-ask.{mjs,d.mts}`、
`FileTrustDialog.tsx` 及其挂载、`Preview` 的内联授权按钮、`MediaPreview.authorizeDirectory`。

**`isInsideTrustedRoots` 仍在**：它继续管落盘/资产类通道（对话框另存、短剧素材、成片输出、HTML
预览源）；历史 `trusted-paths.json` 仍被读取，供这些闸门认旧授权。

## 判据（真跑，不看文案）

- 主进程契约真机（CDP，8/8）：`fs:allow` 已 `undefined`；`fs:read` 读到工作区外文本；
  `fs:write` 写入后**到磁盘核对到标记**；`image_view` 返回 ok；`harness-image` 用 `Image()`
  解码成功（1x1）；`shell:reveal` 任意路径 ok；页面无授权弹窗；授权表未被写入。
- `npm run check`：**exit=0 / 0 条 ✗**；`check-app-dist`：**PASS**（entry `index-Doc4oJ5N.js`，
  磁盘 == 运行），检查后 electron 残留 0。
- 两副本：check 只剩 2 条 `【voice-call】` 存量红（10-26 语音设置页未同步，与本轮无关）。

## 守卫口径反转（关键：防「闸被悄悄加回来」）

`03-runtime-boot`（fs 读写 / shell:reveal / harness-image）、`11p-file-summary`（shell:open）、
`12b-image-lab`、`12y-media` 原本都断言「必须收敛到可信根」。现在**全部反转**成
「不许出现 `isInsideTrustedRoots`」——因为把闸加回去会让用户重新看到"打不开"，正是本次要修的症状。

## 已知并接受的残余风险

`harness-image` / `harness-media` 注册在**默认 session** ⇒ 主文档里的任意 HTML（含模型输出的
HTML 片段）可读本机任意图片 / 音视频（仍受 MIME 白名单限制）。这是「任意位置文件可预览」的
必然代价。若要收回，正确做法是给协议加**请求方来源判定**，而不是恢复逐文件授权弹窗。

## 复审抓到两处（自审 xaction-code-review）

1. `boot.ts` 的 `isInsideTrustedRoots` deps 注入成了**死变量**，而守卫 12y 只查「字符串存在」
   ⇒ 假绿。已连同 `main.ts` 的传参一起摘除，并把 12y 断言反转。
2. `01-timeline.tsx` 注释还在讲已删除的 `OUTSIDE_TRUST` / `fs:allow` 重试流程
   ——「注释声称了不存在的能力」是最危险的假象。已改。
