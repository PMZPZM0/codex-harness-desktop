# 供应商互斥三写入者只做了两份

## 背景
用户截图（设置 → 模型）：云端管理新增的「云端模型」和原来的「豆包」**两个开关同时开着**。
用户原话：「云管理我新增的供应商，上面的豆包没有自动停用，供应商正向反向做的还不够，检查一下。」

## 结论
`enabled`（供应商是否启用）有**三个写入者**，互斥只做了两份：
- `custom-model:save` ✓ 有一段"遍历其它行置 false"的循环；
- `custom-model:set-enabled` ✓ 同样的循环**又抄了一份**；
- `cloud-provider`（`applyCloudProvider` 云端同步 / `activateCloudProvider`「设为当前供应商」）✗ **一份都没有**。

⇒ 云端同步把云端行写成 `enabled: true`，原来生效的豆包仍是 true（截图）。而且同步**每 10 分钟跑一次**，
用户手动关掉云端行，下一轮又被顶回来 —— 这就是用户说的「反向」不成立。

修法（根因，不是各补一遍）：
1. 新增 `electron/provider-exclusivity.ts`：`withExclusiveEnabled(list, id)` 纯函数（口径 `enabled !== false`、
   幂等、未变化的行原样返回）—— 全仓**唯一**互斥实现；三条写入路径全部调它，两份旧循环删除。
2. `cloud-provider.applyCloudProvider`：云端行**不再无条件 enabled** —— 只有「它是生效供应商」或
   「列表里没有任何别的供应商启用（空场）」才置 true；启用时按互斥收敛。⛔ 这条是"反向"的关键。
3. `activateCloudProvider`（用户显式点「设为当前供应商」）：先互斥收敛，再写生效档案。

## 依据
- 守卫 `12q-cloud-account` 扩到 **71 条**：`withExclusiveEnabled` **真值表**（正向 / 反向 / 幂等 /
  老档案缺字段按启用 / null 全停）+ 三条路径接线 + 两条负向（旧的本地循环不许回来、云端行不许无条件 true）。
  **5 处变异全抓**（含"把循环变量改个名再写一份回来" —— 这条第一次漏网，负向断言已改成按**代码形态**认）。
- 验收新项 `provider-exclusive`（真界面 + 真文件）：关当前生效 → 档案 0 个 enabled 且另一个开关**真解锁** →
  启用另一个 → 档案恰好 1 个 + 生效档案跟着切 + 界面只有一个开 → 反向切回。**5/5 通过**，收尾恢复到进入态。
- `npm run check` 预检 **exit 0**（全绿）。

## 影响面
- 主进程模型档案写入：三条路径都收敛到唯一实现；云端同步不再抢开关位。
- 渲染层不动（UI 的置灰逻辑原本就防"同时开两个"的直接点击）。
- ⚠️ 老用户档案里可能已经有**两个 enabled** 的残留：下一次任一写入（保存 / 开关 / 云端同步）都会自动收敛成一个，
  不需要迁移脚本。

## 回滚
- 回退 `8024fec`。只想临时止血：把 `cloud-provider.applyCloudProvider` 里 `enabled` 那行改回恒 true 即可
  （但「反向被顶回来」会复发）。
