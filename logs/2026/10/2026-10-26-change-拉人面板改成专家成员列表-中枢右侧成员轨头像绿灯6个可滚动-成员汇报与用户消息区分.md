# 拉人面板改成专家成员列表 + 中枢右侧成员轨（头像/绿灯/6个可滚动）+ 成员汇报与用户消息区分

用户现场（10-26 上午，一段话里五件事）：

1. 「你这个加入逻辑也不对，光一个名字有啥用不考虑用户手动加的问题，要对应的专家和专家团的成员列表，
    展示出来成员列表，可以用户手动选择群里成员，Codex自己拉成员保留」
2. 「而且你这个展示成员列表做的真丑，能不能做好看一点成员列表，头像+名字，运行中的绿灯」
3. 「cli成员就让Codex添加就行，帮cli成员配置好模型等等，最后能干活和派遣」
4. 「Codex要区分出来别的成员广播汇总消息和用户消息，成员消息是汇报结果的」
5. 「成员我记得专家团不是有那个右边轨道成员头像吗，那个的最好反馈成员是不是在干活的提醒，
    中枢会话右边轨道上可以放这些头像，不限制梳理，展示6个，多了就滚动展示，工作中的优先展示在轨道头像上面，
    亮着头像和光圈反馈，联动性做好一点，成员和轨道头像显示的状态，联动起来」

## 真机取证

`<userData>/expert-teams.json`：13 个专家团、**61 个专家**，但 `model`/`effort` **全是 null**
⇒ 手动拉进来的人必然是"半配置成员"（界面显示不出模型、派活只能吃全局默认）。
这正是第 3 条「帮 cli 成员配置好模型等等」缺的那块。

## 改法

### ① 拉人面板重做（`BossGroupMemberPicker.tsx`，新文件）
- 候选来自**真实专家团登记表**（`boss-groups:pool` → experts，带完整配置）。
- 按团分组（团标签 chip），成员卡 = 头像（组长带皇冠）+ 名字 + 岗位 + 模型名。
- **点一下即进群**（不用手打名字）；已在群里的标灰并显示「在群里」。
- ⛔ **CLI 成员不手动加**（用户原话：「cli成员就让Codex添加就行」）——本机外部 agent 需要
  命令行模板 + 可执行文件探测，手动加不靠谱 ⇒ 面板底部只给一行说明，让用户对中枢说「把 XX 拉进群」。
- ⛔ **Codex 自己拉成员的能力保留**（`group_add_member` 工具路径没动）。

### ② 成员列表好看（头像+名字+绿灯）
- 成员行：头像（名字首字 + 稳定色调）+ 名字 + 岗位 + 状态文字 + 移出按钮。
- **运行中 = 头像右下角一颗绿灯**（脉冲）。
- 状态色：正在做=绿、交活待审=橙、被锁=红。

### ③ 中枢会话右侧成员轨（`BossGroupMemberRail.tsx`，新文件）
- 复用专家团那条轨的样式体系（`.team-rail*`）—— ⛔ 不另写一套（两处各写一份图标/光圈很快会漂开）。
- **工作中排最前**；亮头像（放大+绿边+辉光）+ **绿色呼吸光圈**（另给动画，opacity 0.9→0.25，
  专家团那条的 `teamRailPulse` 有一半时间几乎看不见）。
- **最多 6 个可见，超出滚动**（滚动条 + 上下渐隐提示还有更多）。
- 与专家团轨 / 调度轨**互斥**（同一时刻只有一条右轨）。

### ④ 成员与轨道状态联动（`group-members-store.ts`，新文件）
- ⛔⛔ 原来顶栏成员面板**自己每 5 秒轮询** `bossGroupStatus`，轨道若也轮询 ⇒ 两处状态会不一致
  （面板说"正在做"、轨道说"空闲"）⇒ 改成**共享 store**（渲染层唯一一份快照 + 订阅中枢）。
- 真相源仍是主进程；这个 store 只是缓存 + 订阅。
- 群事件（派活/交活/拉人/移人）到达 ⇒ **立刻**重拉（不等下一个轮询周期）。

### ⑤ 成员汇报 vs 用户消息的区分
- 群消息容器加**左侧竖条 + 淡底 + 圆角** ⇒ 一眼看出"这是群里的汇报，不是你说的话"。
- ⛔ **审查结论也按成员汇报渲染**（新 `verdict` 块类型）：文案改成
  `审查结论：<成员> 的「<任务>」通过|打回（<判定方>判定）：<理由>`
  ⇒ 解析器认它 ⇒ 带头像+名字+通过(绿)/打回(红)徽标，**不再落回居中灰行**。

### ⑥ CLI 成员配齐配置 + 能干活
- 拉 CLI 成员时补齐 model（当前默认）/ effort / sandbox / approvalPolicy（原来全空）。
- 拉**专家**成员时同样补齐（登记表里 model 是 null ⇒ 落当前默认模型）。
- 派活链路本来完整（`pickReassignee` 选人 → `ensureMemberThread` 建会话 → `turn/start`），
  补齐配置后成员**能接活能干活**。

## ⛔ 教训（本轮踩到）

- ⛔ **mock 的 capturePage 会把含 transform 的合成层拍淡**（实测 running 头像
  rgb(207,219,243) vs 应有 rgb(47,107,221)，computed style 全对）⇒
  **验证真实界面必须用 CDP 连真应用截图**，不能只信 mock。
  （Bash 沙箱连不上本机调试端口 ⇒ 用 node 的 http 而不是 fetch/undici。）
- ⛔ **CSS mask 会吃掉第一个头像**：`.boss-member-rail-track` 的 mask 渐隐区必须小于
  padding-top，否则"工作中"排最前的那个头像正好在渐隐区里 ⇒ 看着像没在干活。
