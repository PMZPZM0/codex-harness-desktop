# 顶栏图标按窗口宽度自适应隐藏（补调度 + 搜索进最窄档）

用户令：「这一排图标要根据窗口大小自适应隐藏，主界面上面这一排和独立弹窗这一排都要自适应隐藏」，
追问后明确：**搜索也一起收**。

## 现状盘点（改前）

断点早已存在、且对两个窗口同样生效（同一套 class），但：

| 断点 | 收什么 |
|---|---|
| ≤980 | 右栏钮（`.tb-right-panel`） |
| ≤860 | ⋯ 任务菜单（`.tb-task-menu`） |
| ≤760 | 工作区 📁 + **独立弹窗 / 返回主应用** |
| ≤640 | 只收标题文字 |

⇒ 两个洞：**调度开关（`.dispatch-topbar-btn`）任何断点里都没有**（09-13 那套只列了当时存在的按钮，
新控件没人补进去）；**搜索（`.history-search-wrap`）被"豁免"**（10-04 用户定：「无替代入口，无条件显示」）。

## 改法

- **≤860** 补 `.topbar-actions .dispatch-topbar-btn`（调度属低频，与 ⋯ 同档收）。
- **≤640** 补 `.topbar-actions .history-search-wrap` **+ `.history-search-panel`**（面板是 portal 到 body 的，
  容器 `display:none` 藏不住它）+ part04 的 `matchMedia("(width<=640px)")` **逻辑关状态**
  （只靠 CSS 会留下「按钮没了 ⇒ 面板点不掉」的死角，与 `.ctx-menu` 同款，守卫【250】钉的范式）。

## ⛔ 推翻一条旧口径（写得清楚，别再回退）

搜索的隐藏档位改了三轮，**以 10-11 为准**：
10-03 要求 980px 藏 → **10-04 改判「无条件显示」** → **10-11 再改判「最窄档 ≤640 藏」**（本次）。
⇒ 守卫里那条「搜索**不得**出现在断点里」的反向断言**整条删除**（留着会把新实现判红），
换成正向要求：**搜索必须落在 ≤640 且与逻辑关状态成对**；豁免清单清空，
覆盖率名单扩到 4 项（`ctx-picker` / `task-menu-wrap` / `dispatch-topbar-btn` / `history-search-wrap`）。

## 判据

- 守卫【250】新增/改写：搜索进 ≤640（CSS + 逻辑成对）、调度必须有断点、覆盖率名单扩到 4 项、豁免清空。
- `npm run check` 退出码 0。
- `accept --only history-search` **7/7** —— ⛔ 必须真跑：我改的正是那个按钮的可见性，
  验收窗口是默认尺寸（1280 宽 > 640）⇒ 按钮应当仍在且可用（若哪天验收窗口被调成很窄，这条会红，
  那是**预期**，不是回归）。

## 诚实边界

- ≤640 是很窄的窗口（弹窗默认尺寸通常比它宽）⇒ 多数情况下看到的行为不变；用户实测的 640px 弹窗才会收。
- 搜索收掉后**只剩 Ctrl+Shift+F 快捷键**（用户 10-11 明确接受 —— 10-04 那条"快捷键不等于可发现性"的理由被推翻）。
- 两窗口共用同一套断点（class 相同）⇒ 不需要为弹窗单独写规则；`popout-return-btn` / `popout-open-btn`
  在 ≤760 收（09-13 定稿「放大缩小按键也跟着隐藏」），弹窗在最窄档只剩原生窗口钮与标题。
