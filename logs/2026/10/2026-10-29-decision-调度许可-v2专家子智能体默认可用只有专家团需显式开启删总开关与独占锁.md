# 调度许可 v2：专家/子智能体默认可用、只有专家团需显式开启

## 用户令（10-29 原文）

> 「将子智能体调用和专家调度改为默认可直接调用，仅专家团功能需要显式开启。」
> 「子智能体、专家和专家团都不再需要做数量或使用上的限制，每个会话都可以调度它们。」

## 结论

- **许可模型换成三类平行开关**：`DispatchConfig = { expert, team, subagent }`，默认
  `true / false / true`（`DISPATCH_DEFAULTS`＝主进程唯一真相源，`emptyDispatch()` 与它逐字同形）。
- **删掉 `enabled`**：它同时是「调度总开关」与「全局独占锁」（09-16「同一时间只允许一个会话调度」）。
  用户令要求「每个会话都可以调度」⇒ 锁与默认可用互斥，锁整体下线：`dispatchOwner` /
  `releaseDispatch` / takeover / 孤儿锁自愈 / 「释放并删除该会话」/ 两条锁通道一起删。
- **通知三条通道收敛成一条**：开启 / 关闭 / 逐类变化 → 只剩「逐类许可变化」（`agents:notice`），
  差异驱动 + 按类分段 + 新开启的类附对象名单（中途开团时模型才知道有谁）。
- **保留两道结构闸**（不是配额）：① 身份闸 —— 专家 / 专家团 / 被委派会话不许对外派人（它们有团内通道）；
  ② 深度闸 —— 被委派会话不能再往下派（防指数套娃）。配额类闸 09-25 已删。

## 权限面的四处落点（缺一处就是"开关沦为装饰"）

1. `dispatchKindAllowed`（执行端真相源，`runDelegatedTask` 里调）—— expert/subagent 默认放行、
   team/member 需 `team === true`；
2. `dispatchToolDescription`（模型读到的文本）—— 未开启的类**显式否定**，专家团写明"默认关闭、需显式开启"；
3. `agents:tool-description`（按会话许可生成）—— 取不到运行时记录时按出厂默认；
4. 面板（`DispatchMenu`）—— 三类平行开关，无总开关；顶栏圆点＝专家团已开。

## 老数据迁移

`team = old.team && old.enabled`。实测本机 45 条记录：44 条 `0111`（旧默认，专家团本来就是"没关过"）
→ 专家团关闭；1 条 `1111`（当年显式开过）→ 保留。⛔ 不叠加 `enabled` 就会凭空开团（那是花钱的那一类）。

## 会话级归属（同一角色被多个会话复用）

| 维度 | 归属键 | 隔离/共享 |
|---|---|---|
| 委派会话（专家 / 子智能体 / 团长） | 每次 `thread/start` **新线程** | 上下文天然隔离；工作区 `<project>/.codex-harness/sessions/<threadId>/`；私有记忆 `private__<threadId>` |
| 团队成员线程 | `owner|team|member`（10-29 加 owner） | **改前**是 `team|member` 全机唯一 ⇒ A 会话派过的成员被 B 会话 resume，B 带着 A 的历史（数据混淆）。现在同场团运行内仍复用（多阶段连续性），跨会话各自一条线程 |
| 角色自传（角色私有记忆） | `roleKey`（`expert__<teamId>` 等） | **同项目内共享**（同一个专家就是同一个人）；落 `<workspace>/.codex-harness/memory/roles/`，换项目即隔离；写入按文件串行（取消锁后同一角色可被并发派活，读改写会互相覆盖） |
| 产出 / 归档 | `originThreadId` | 只回传给发起会话；跨会话归档一律 `failed` |
