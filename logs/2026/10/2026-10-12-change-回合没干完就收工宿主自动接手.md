# 回合没干完就收工宿主自动接手

## 背景
用户 10-12 报障「这个运行过程总是自动中断」（截图 + 会话 `看看最近AI新闻`）。
**不是崩溃、不是被打断**：该会话 rollout（`codex-home/sessions/2026/10/12/rollout-…01a12e1b.jsonl`）逐行核过 ——
5 个回合**全部**是引擎正常 `task_complete`，零 `abort/interrupted` 记录；宿主侧也没人发过 `turn/interrupt`。
真机制是引擎的回合语义：**一条回复里没有工具调用 = 回合完成、控制权交还用户**，而 4/5 个回合的末条正文
只是「宣布下一步」——「读它的快照，同时再抓机器之心。」「改串行重跑。」「继续串行压浏览器通道。」「验证一下。」
唯一**正常收尾**的那个回合，末句是**问用户的问句**（「要不要我给你挂个每日早报？」）。
触发因素（引擎日志 + 同轮 rollout 实证）：模型被引去调**当前引擎不交给模型的 MCP 工具**（`unsupported call:
browser_navigate / desktop_windows_list`）⇒ 绕道 PowerShell 拼 `nuphus-call` ⇒ 长命令超出等待窗只拿到半截输出
（`Process running with session ID 59332`）⇒ 想读剩余输出又失败（`write_stdin failed: stdin is closed … tty=true`）
⇒ 反复换招烧掉整回合，最后宣布"验证一下"就收工。

## 结论
用户拍板「**宿主自动接手**」。两层：
1. **判据纯函数** `src/lib/turn-unfinished.mjs`：末条正文是「宣布下一步」且**不是在问用户**（问句/第二人称/明确收尾语一律不判）
   ⇒ `promise`；或本回合**最后一次工具输出**是引擎半截标记（`Process running with session ID` / `write_stdin failed: stdin is closed`）
   ⇒ `partial-command`。`voice` 播报块**先剥再判**（实证：正常收尾那个回合的播报稿里正是问用户的话）。
2. **触发与投递**：回合收尾（`07-turn-completed-settle.tsx`）判出来 → 提示条 + `maybeAutoContinueUnfinished`
   → 复用既有「截断自动续接」的投递管道（`deliverAutoContinue` 从 `maybeAutoContinueTruncated` 抽出、两处共用）
   → `thread/queue/add` 一条「立刻执行、别复述计划」的指令 → `queue/start`。
   **四道短路**：手动停止不接手 / 回合带错不接手 / **方案回合不接手**（它本就该停在等用户确认）/ 只对当前会话。
   **共用记账**：与截断续接同用 `autoContinueLogRef` ⇒ 同会话 15 分钟内合计最多 2 次（防烧钱）。

## 依据
- rollout 逐行（上面背景里的原句与时间戳）；`engine-debug.log` 的 `unsupported call` / `write_stdin … stdin is closed` 原文。
- 守卫 `scripts/guards/12f-turn-unfinished.mjs` **24 条**：真值表（4 个实测原始句判真 + 问用户/完成结论/第二人称/明确收尾/空文本判假）
  + 整条判据三态 + `voice` 剥块 + 接线/四道短路/共用记账/指令语义；**8 处变异全抓**（含「不剥 voice 块」「方案回合也接手」）。
- 对照实验：把触发那行临时改成 `const reason = ""`（等于关掉本机制）→ 同一条验收 `file-summary` 结果**完全一样**（7/20），
  证明该验收项的红与本改动无关（是旧 e2e profile 的模型配置过期所致，当日已重建该 profile）。

## 影响面
- 渲染层：回合收尾多一条判定（无命中即 no-op）；自动接手会**替用户发一条消息**（用户已知情并选择该项），带提示条。
- `bag-types.ts` 新增一项（生成器口径，非手改）；`package.json` 的 check 链登记新守卫（独立守卫，不进 EXPECTED_CHECKS）。
- 不碰主进程 / 引擎 / 打包。
