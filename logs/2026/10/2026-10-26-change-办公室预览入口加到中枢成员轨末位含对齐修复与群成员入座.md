# 办公室预览入口加到中枢成员轨末位（含对齐修复）与群成员入座

用户现场（10-26 上午，截图 + 一句话）：
· 「办公室预览图标放这里」—— 红框标在中枢会话右侧成员轨的**末位**。
· 「对齐啊」—— 办公室图标与成员头像**没对齐**（偏右）。

## 改法

· `OfficeRailNode` 改成 **export** ⇒ 三条轨（专家团成员轨 / 普通会话调度轨 / 中枢群成员轨）
  **共用同一个节点** ⇒ 图标与位置一致（⛔ 各写一份很快会漂开，10-05 用户正是为此报的）。
· 中枢轨末位渲染它，并用 `position: sticky; bottom: 0` 让它**始终贴在可视区底部**
  （成员可滚动但入口不被滚走；上方一条淡分隔线）。
· 办公室新增**第三条成员来源**（群成员）：正在干活的敲键盘、其余待机；
  标题口径改成「群成员办公室 / 群里的人实时映射成工位」——
  ⛔ 不沿用普通会话的「我的办公室 / 调度出去的子会话」（那在这里是假话）。
· AppView 侧按 bossThreadId 匹配当前会话的群 id，把群成员喂给办公室（与轨道同一份判定）。

## ⛔ 对齐踩了两轮（都是实测，不是猜）

① 办公室节点放在 track **外面** ⇒ `.team-rail` 默认是 **row** 布局 ⇒ 它被排到轨道**右侧**，
   中心差 20px（用户看到的「偏右」）。
② 移进 track **内部**（与其它两条轨结构一致）后中心差仍有 5px ⇒ 原因是
   **track 宽度是内容撑开的**（≈40px），而节点 width:100%（=92px 满宽）⇒ 两者中心不同。
   ⇒ 补 `track { width: 100% }` 后**实测中心完全相同**。

## 判据（真实应用 CDP 探针，不是 mock）

· `memberAvatarCx == officeAvatarCx == 1229`（对齐 0 偏差）、`officeBelowLast = 73`（末位）
· 办公室浮层：标题「群成员办公室」、副标题「群里的人实时映射成工位 · 正在干活的敲键盘」、
  canvas 正常、9 个群成员入座
· tsc -b 全绿；npm run build 通过；守卫 22-boss-groups / 01-build-ipc-css 通过
  （09-structural 报的两条是并行线的：shell-ipc.ts 直取 BrowserWindow + accept.mjs 棘轮，与本轮无关）

## ⛔ 本轮踩到的环境坑

· ⛔ **CDP 端口可能被别的 Electron 应用占着**（本机同时开着 UAV 终端）⇒ 挑 target 必须按
  URL 精确匹配，别用「第一个含 index.html 的」—— 否则截到的是别的应用的帧。
· ⛔ `Page.captureScreenshot` 不带 clip 时也可能抓到别的应用的表面帧 ⇒ 用
  `bringToFront` + `clip` 区域（clip 会触发该区域重新绘制）。
· ⛔ 副本 `timeline.tsx` 可能落后主仓几个提交 ⇒ 整包 apply 必失败 ⇒ 定点替换（脚本按标记改）。
