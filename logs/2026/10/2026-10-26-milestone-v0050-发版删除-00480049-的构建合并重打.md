# v0.0.50 发版：删除 0.0.48/0.0.49 的构建，合并重打

## 结论

v0.0.50 直接取代 0.0.48 / 0.0.49（两版构建均已删除，未对外发布）。

## 为什么删而不是留着

两版构建出来后都被用户实测打回：
- 0.0.48：窄档右侧整组控件被挤没（`.composer-left` 的 `flex: 1 1 auto` 增长吃满）
- 0.0.49：弹层固定宽度导致「长的被裁 / 短的留白」；点通知不打开应用

## 删除动作（可复现）

1. `POST /actions/runs/40302050653/cancel`（取消 v0.0.49 的构建）
2. `DELETE /releases/424055183`（v0.0.48 的 Release + 2.5GB 资产）
3. `git push origin --delete v0.0.48 v0.0.49` + 本地 `git tag -d`
4. 远端只剩 v0.0.47 及更早

⛔ **顺序不能反**：先删 Release 再删 tag。若只删 tag，同名 Release 会退回**草稿态**
（匿名不可见、更新器永远收不到、还要网页手工救）。

## 本版内容

= 0.0.48 + 0.0.49 的全部内容 + 第 1 节三项修复（输入框窄档降级 / 浮层按内容自适应 /
点通知唤出应用）。
