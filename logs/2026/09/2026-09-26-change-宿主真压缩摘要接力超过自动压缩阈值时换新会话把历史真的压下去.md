# 宿主真压缩「摘要接力」：超过自动压缩阈值时换新会话，把历史真的压下去

## 需求（用户 09-26）

「你不做真实压缩，有啥用，那不是分分钟爆上下文」+「按模型配置里面的压缩阈值来啊」。
→ 引擎侧压缩在自定义网关下不生效（取证见 logs 上一条：压缩上报 21,900、10 秒后实际请求 70,464），
所以改由**宿主自己实现真压缩**。

## 方案：摘要接力（宿主侧）

触发（发送消息前，线程空闲分支）：上下文占用 ≥ **设置页「自动压缩阈值」**（bag.autoCompactRatio，
09-25 起默认 0.6，不另立常量）且历史超过 4 轮。

执行：
1. 调引擎 `thread/compact` 拿摘要（等 `thread/compacted` 事件的 message 字段，最多 20 秒）；
   拿不到就退化为「【更早的对话已省略】」——**不爆上下文优先**。
2. 抓最近 4 轮原文（每条限 1500 字、总量限 2 万字符，防把新会话又撑大）。
3. `startNewThread()` 开新会话（旧会话**原样保留**，随时可切回）。
4. 把「[上下文接力…] + 历史摘要 + 最近几轮原文」拼在用户本条消息前发送 ⇒
   引擎此后每轮**实际发出**的历史就是短的，与网关无关。

## 关键取舍

- 为什么换新会话：宿主改不了引擎构造的 prompt，但「换一条历史本来就短的会话」是宿主完全可控的。
- 摘要来源用引擎压缩结果（质量最好、成本一次），失败降级为省略声明而不是放弃接力。
- 阈值复用设置页那个：两处各写一个阈值必然漂移（守卫【167】①钉死）。
- 排队分支（会话运行中发消息）不接力：那条消息进的是同一会话，接力会打乱队列语义。

## 判据

守卫【167】5 条（阈值来源 / 摘要来源 / 换新会话+保留提示 / 防重入 / send 接线）。tsc 0 错、预检 0 真红。
真机验证：需要用户实际跑到阈值（60%）触发一次，看新会话首条消息带摘要块且上下文环回落。
