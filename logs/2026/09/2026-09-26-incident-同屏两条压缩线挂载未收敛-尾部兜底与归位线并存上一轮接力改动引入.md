# 同屏两条压缩线：挂载未收敛 + 尾部兜底与归位线并存（上一轮接力改动引入）

## 现象

用户截图：同一屏**两条压缩线**（09-26）。

## 根因（我上一轮改动引入的两个来源）

1. **线程里出现两条压缩项**：`attachCompactionItem` 是「按 id 找不到就追加」，而引擎 item/started 与
   item/completed 的 id/形态可能不一致 ⇒ 追加出第二条；且 `pruneSupersededCompactions` 在
   keepId 为空时**直接 return**，多余项永远留在时间线里。
2. **尾部 settled 兜底线与归位线并存**：成功态 item 进了线程后，tail 的 settled toast 分支
   （原有的独立渲染位置）仍会渲染一条 → 与 timeline 归位渲染的那条同屏两条。

## 修复（结构性收敛，不靠时序巧合）

- `attachCompactionItem` 之后**再 prune 一次**（两处调用点都补）⇒ 线程里任何时刻只留最新一条压缩项。
- `pruneSupersededCompactions` 空 id 时不再 return：改为保留**最后一条**压缩 item（语义 = 只留最新）。
- 已完成压缩线**只有一处渲染**：timeline 归位处 `item 优先，否则 toast 兜底`（else-if 互斥）；
  尾部独立 settled 分支**删除**。进行中的转圈仍贴输入框底部（与已完成线不同态，不冲突）。

## 判据

守卫【165】新增 2 条（已完成线只有一处渲染 / prune 空 id 也收敛）。tsc 0 错、预检 0 真红。
