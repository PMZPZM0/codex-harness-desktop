# 思考直播改右下角浮窗：不占消息流，完成自动收纳（用户定稿）

## 背景

用户 10:40 后反馈：还是会把最下面的「正在运行命令」卡撑出视口。提出方案：「把思考内容做成小弹窗那种，思考完成折叠收纳，专业，不靠往下撑」，并问有没有更好的方案。

## 结论

采纳浮窗方案（它是对的）：思考是**临时、高 churn** 的内容，不该挤占消息流布局——抽出去之后，
撑高/裁切/钉顶竞争/卡内跟随被误杀这一整类几何问题**从根上消失**（浮窗不在 .timeline 流内，
bodyBottomOf 也量不到它）。评估过的替代方案：侧边栏面板（太重）、固定高度占位（不撑但白占空间）——都不如 PiP 浮窗。

## 实现

- 共享 ReasoningCard：`floating = running || revealing` 时，思考正文 **createPortal 成
  `.reasoning-float`**（fixed 右下角，宽 min(420px, 100vw-48px)，高 min(46vh, 380px)，
  主题 tokens 全套），流内只留一行「深度思考中 ›」头。
- **思考完成自动收纳**：floating 转 false（running/revealing 双 false），浮窗消失，
  流内落回「已深度思考 ›」折叠芯片（既有收纳态）；点芯片内联展开回看（done 态走 fit 限高）。
- ⛔ 浮窗**常挂到 live 结束、hidden 类切显示**（不随 open 卸载）——卡内跟随监听器与滚动
  位置都绑在元素上，卸载重挂两者皆失；监听器 effect 依赖加 floating（浮窗 ↔ 内联切换
  bodyRef 换元素必须重绑）。
- fit 在浮窗态（无 .timeline 祖先）直接跳过——浮窗高度由自身 CSS 管，裁剪边几何不适用。
- CSS 全用主题 tokens（--bg/--line/--shadow），【160】对账自动覆盖。

## 守卫

【161】+2：⑦ portal 浮窗 + hidden 类不卸载（正则锚 createPortal\( 与 reasoning-float
\$\{open…hidden\}）、fit 浮窗态跳过。⚠️ 写守卫正则时 shell 转义连吃两次（`${` 在正则里
必须 `\\$\\{`）——按纪律此类正则该用 Edit 工具写。

## 验证（真机端到端，隔离 profile 发真实思考回合）

- **思考流式期间 timeline.scrollHeight 恒定 624（单值）= 完全不撑**（上一版是持续增长）；
- 浮窗出现 9 采样、可见率 9/9、浮窗内贴底率 9/9（卡内跟随工作）；
- 回合结束：流内「已深度思考」收纳芯片出现 ✓、浮窗无残留 ✓；
- tsc 0 错、预检 0 条真红、验收 settings-pages 通过（44.5s）、变异红。

## 影响面

直播中思考卡的呈现形态（浮窗替代内联展开）；done 卡内联回看、自动折叠、接管语义全不变。
已知取舍：浮窗右下角在窄窗口会盖住输入框右缘（点头部即收起）；位置/宽度后续可按反馈调。
