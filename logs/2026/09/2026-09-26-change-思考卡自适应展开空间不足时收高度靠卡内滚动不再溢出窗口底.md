# 思考卡自适应展开：空间不足时收高度靠卡内滚动，不再溢出窗口底

## 背景

用户 09-26 两张截图：回合运行中「深度思考中」卡展开时，卡体直接被窗口底裁掉（第二张连最新一行都被切在输入框边缘），而钉顶期视口不跟随（09-26 上午定的稳定口径）⇒ 最新思考永远看不见。用户要求：思考板块自适应展开，下面空间不够要自己解决，不要靠视口移动。

## 结论

`.reasoning-body` 的 `max-height` 从**静态 260px** 改为**动态自适应**（新增 `fitReasoningBody`）：

- cap = clamp(96, 260, 「卡顶到 `.timeline` 容器底」− 12px)。⛔ 量**滚动容器底**而不是 window ——
  裁剪发生在 `.timeline` 的 client 区，composer 在容器外不算可用空间。
- 空间充裕时上限仍是 260px（行为不变）；空间不足时收小，正文靠**已有的卡内滚动**展示尾部
  （follow effect 每 tick `scrollTop = scrollHeight`），最新思考始终贴着卡底可见。
- 重算时机：追字 tick（displayed 每 16ms）+ 展开（open）+ 窗口 resize；done 卡手动展开也兜住。
- ⛔ 顺序契约：卡内跟随必须**先 fit 再贴底**（顺序反了 scrollTop 按旧 max 钳住，尾部差一行）。

## 依据

- tsc 0 错；预检 0 条新增真红（总账 19 条失败 = 记忆点名的五类沙箱假红，量级与清单逐类吻合）；
  验收 `settings-pages` 通过（43.8s）。
- 守卫【161】5 条（07-turn-fold §54）：量容器底不量 window / 先 fit 后贴底 / open+displayed 重算 /
  静态基线 260 不许删（反向绊线）/ 下限 96 不许压成缝。变异 2/2 红（删顺序、删下限各命中）。
- ⚠️ 真机探针未走通：harness eval 在 main profile 上返回结构异常（DOM 诊断空），没量到真实卡的
  inline maxHeight —— 几何假设（.timeline 底=裁剪边）由守卫钉死，运行时行为待用户下次真实思考验证。

## 影响面

仅 ReasoningCard 展开态的高度；折叠动画、自动收起、卡内接管判定（wheel/触摸）全不动。

## 回滚

删 `fitReasoningBody` 与两个 fit effect、follow effect 还原为只贴底；守卫 §54 删除。
