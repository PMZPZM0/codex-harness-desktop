# AGENTS.md 二次拆骨：66KB→39KB（-41%），历史流水外置 + 活约束速查表

用户反馈：「精简一下，一下 20600 太夸张了」。

背景：上一轮修 AGENTS.md 被 32KB 静默截断时，我抬高了 project_doc_max_bytes 到 262144，代价是每会话注入 65,775 字节（粗估 ~20,620 token）。用户认为这个成本不可接受 —— 判断正确：省 token 的正确做法是精简文档，不是抬上限。

【精简对象与判据】先摸清结构再动手，不盲目删：
- 逐节统计字节数，找出真正的大块。发现**「历史变更流水」占近一半** —— 09-24/09-25 各轮的详细修复过程记录还堆在 AGENTS.md 里。
- ⛔ 关键发现：**项目早就有承接文档 docs/CHANGELOG-ROUNDS.md**（2026-09-24 首次拆骨时建的，其头注释明确写「历史小节整体移到这里，**不再回迁**」；当时 AGENTS.md 曾达 502KB 被截断到 13%）。09-24/09-25 的新记录又堆回来了 ⇒ 本轮二次拆骨。
- ⛔ 安全边界先查：全仓只有一处守卫读 AGENTS.md 内容（【170】④，只要保留「DESIGN.md」+「改 UI 前先读」两个词）。

【四刀】66,650 → 38,965 字节（-41.5%），粗估 token 20,620 → 12,220（-41%）：
1. 6 个历史章节 → docs/CHANGELOG-ROUNDS.md（停止链路【131】/ 审计补修【143-145】/ 会话内搜索【146】/ 断环收尾【143】【147】/ Markdown 结语行【149】/ 记忆后端【150】）
2. 「排查方法论」整节（7.6KB）→ docs/TESTING.md
3. 「验证基建实现细节」（4.7KB 历史踩坑）→ docs/TESTING.md
4. 验收铁律的引述冗余（用户原话长引用、历史 bug 举例）就地压缩，规则全留

【⛔ 自己抓到的一个失误（code review 阶段）】第一刀把 6 个章节**整体**当"历史流水"搬走，但审查时逐节统计发现它们**都含仍在生效的约束**（守卫引用 + 必须/不许 措辞）——守卫只能保证"改坏会红"，而「为什么这样设计」的说明丢了，未来 agent 可能绕开守卫覆盖不到的地方。修法：在 AGENTS.md 新增 **「🔑 现行不变量速查」** 一节（6 条一行一条 + 指针），把活约束捞回来。
⇒ 教训：**拆骨前必须先分「活约束」与「历史叙述」，不能按章节整体搬**。

【完整性判据（不靠感觉）】脚本比对精简前后：26 个守卫引用 + 12 个关键术语（effectiveMemoryBackend / runtime-paths / codeOnly / 变异测试 / ROUND_OF / DESIGN.md …）**全部仍在 AGENTS.md 或 docs 里，丢失 0**。docs 内无重复（各只 1 处）。

【端到端验证】用 codex debug prompt-input 实证：磁盘 38,418 字节 → 注入 38,420 字节，**完整注入无截断**；8 个关键章节全部在位。

【效果】现在 38,965 字节，即便算上全局个性化 AGENTS.md（12,646）共 51,611 字节 —— 仍超默认 32,768 上限，所以 -c project_doc_max_bytes 保留（余量 6.73×）。
