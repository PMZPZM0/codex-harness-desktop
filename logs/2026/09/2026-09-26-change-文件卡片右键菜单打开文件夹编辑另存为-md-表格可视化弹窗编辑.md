# 文件卡片右键菜单（打开/文件夹/编辑/另存为）+ md 表格可视化弹窗编辑

## 需求（用户 09-26 两张 WorkBuddy 截图）

1. 「WorkBuddy 这种可以直接编辑和保存 MD 文件是怎么做到的，我们做出弹窗编辑可以不」——后续补充：核心价值是 **md 转可视化表格编辑**，纯文本 textarea 不够。
2. 「文件右键功能加上」——文件卡片右键菜单（参照 WorkBuddy：打开 / 打开文件夹 / 另存为）。

## 实现清单

**右键菜单**（`src/features/shared/InlineCards.tsx`）：`InlineFileCards`（消息里识别出的文件卡片）与 `UserRefsRow`（用户引用行）都挂 `onContextMenu` → 自绘浮层 `FileCardMenu`（视口边缘翻转、点外部/Esc 关闭）。四项：打开（原点击行为）/ 在文件夹中显示（`shell:reveal`，已有）/ 编辑（仅文本类文件，`openFileTextEditor` 槽位）/ 另存为…（新通道）。

**弹窗编辑（双视图）**：复用现成的 `PastedTextEditor`（关窗自动存 / Ctrl+S / Esc 全局管线）。
- 泛化出 `TextEditorTransport`（read/save 可选 props）：默认 = 粘贴文本通道（`pasted-text:read/update`，路径限粘贴文本目录）；`kind:"file"` = `fs:read`/`fs:write`（可信根校验在主进程，2MB 上限复用），GBK 解码兜底与右栏预览同源（`useFilePreview.decodeText` 导出复用）。
- md 检出 GFM 表格时出「表格」视图（新组件 `MdTableEditor.tsx`）：单元格直接改、加/删行列；保存用 `renderMarkdownTables` **只回写表格块、其余原文逐字保留**。
- `pastedText` 槽位加 `kind` 字段（bag-types 同步，【93】对齐 4 处——typeToString 联合成员顺序随 program 变化，守卫归一化按 `|` 切段排序）。

**新 IPC `dialog:save-as`**（`electron/features/dialog-ipc.ts`）：⛔ 源文件必须 `isInsideTrustedRoots`（防注入拷走任意文件）；目标由用户系统对话框选定（另存为语义本身）。manifest → `gen:ipc` → ipc-registry（dialog 5→6，全仓 337 通道）。

**纯函数基座 `src/lib/md-table.mjs`**：按行块建模（start/end 行号 + 单元格矩阵），围栏跟踪（```/~~~ 内的表格样子绝不识别）、`\|` 转义还原/回写、列宽对齐序列化。守卫【164】12 条（6 条行为 + 6 条接线结构）钉死。

## Code review 抓到的真缺陷（当轮已修）

表格视图保存/切换后 `state.content` 未同步回写后全文 ⇒ 切回文本视图显示编辑前旧文，**再保存会丢掉表格编辑**。修：save 成功后同步 state.content + 矩阵重建；table→text 切换时先落内容。

## 验收

- `tsc` 0 错；`check` 0 条真红（守卫【48】锚随泛化更新、【93】对齐 4 处、【164】新增 12 条）；`accept file-card-edit` 4/4（md-table 真值表 + saveFileAs 桥存在 + 主进程拒可信根外源文件）。
- UI 右键/表格交互本身：守卫【164】结构断言 + 用户真机验收（CDP 无法对 React 卡片合成原生 contextmenu）。

## 遗留 / 边界

- 表格判定是最小 GFM 子集：非表格行混入 `|` 可能被误吸入块（罕见；文本视图可兜底）；HTML 表格不支持。
- 2MB 上限沿用 fs:read 预览口径；超大 md 走右栏预览。
- 已知边界：同一弹窗「粘贴文本编辑窗」与「文件编辑窗」共用一个全局 Escape 槽位（同一时间只开一个，无冲突）。
