# v0.0.68 发版说明

本版主题：**差分更新真正可用** + 安装过程终于有进度窗。

## 一、差分更新为什么一直没生效（这次是源码级定论）

上一版我说「缺 blockmap 就整包」，这个判断是**错的**。我把 `electron-updater` 和 `app-builder-lib` 的源码读完了，真实机制是：

1. **差分只需要一样东西**：`%LOCALAPPDATA%\codex-harness-desktop-updater\installer.exe` ——
   它是**上一版的安装包本体**，作为差分的 oldFile。
   这个文件由**安装器自己**在安装时写回（`app-builder-lib/templates/nsis/include/installer.nsh`：
   `copyFile "$EXEPATH" "$LOCALAPPDATA\${APP_INSTALLER_STORE_FILE}"`，普通 embedded 包每次安装都执行，
   与应用内更新还是手动装无关）。
2. **`current.blockmap` 根本不是必需品**：缺了它，updater 会拿 `latest.yml` 里的地址去服务器
   下载**旧版本**的 blockmap（`AppUpdater.differentialDownloadInstaller`：
   「No cached blockmap for the old installer, downloading it from …」），只多 700KB。
3. 而且**整包下载完成后 updater 会主动删掉** `current.blockmap`（`done()` 的 else 分支，
   防止陈旧 blockmap 配上新文件）。所以「installer.exe + current.blockmap 成对存在」这个状态
   **在整包安装之后本来就不会出现**。

⇒ 于是 11-19 我加的 `healDifferentialCache()`（「缺一份就两份都删」）变成了**每次更新都先把
唯一需要的 `installer.exe` 删掉** ⇒ 差分必然失败 → 回退整包 → 整包装完又没有 blockmap → 再判一次
「配对失效」⇒ **永远整包**。用户看到的 668MB，是我们自己删出来的。

**本版修法**：
- `healDifferentialCache()` 只做一件必要的清理：**blockmap 孤零零存在、却没有 installer.exe** 时删掉它；
  **永远不删 `installer.exe`**。
- `hasDifferentialBaseline()` 判据改成**只看 `installer.exe`**（blockmap 缺了 updater 会自己下）——
  这样界面也不会再把「能差分的机器」误报成「本次是完整包」。

## 二、安装进度窗（上一版看不到的原因）

旧实现是「写 .ps1 → spawn PowerShell → WinForms 自绘卡片」。实测冷启动 **2–4 秒**：
PowerShell 本身 ~800ms，`Add-Type` 现场编译 C# >1s，再加载 WinForms/Drawing 两个程序集。
而静默安装常常 5–10 秒就结束 ⇒ **窗口出现时安装已经完了**，用户根本没看见。
更糟的是 `Add-Type` 依赖机器上的 csc.exe，精简系统上编译失败会被
`$ErrorActionPreference = "SilentlyContinue"` 吞掉 —— 那就是「压根没有弹窗」。

**本版换成独立 Electron 小窗**（`electron/splash-main.ts`，入口 `dist-electron/splash-main.js`）：

- 冷启动 ~300ms，UI 用 HTML/CSS 画（深色卡片 + 顶部流光条 + 应用图标 + 标题版本号 + 滑动进度条）；
- 不依赖 .NET、不依赖任何编译器；
- 它跑在**另一个 Electron 实例**里（入口不是 `main.ts`），所以不受单实例锁影响，userData 也改到 temp；
- 应用进程「消失过、又出现」⇒ 新版本起来了 ⇒ 自动关窗；
- 超过 240 秒没等到 ⇒ 文案改成「更新未完成 / 请手动重新打开」，不会永久挂着。

## 三、安装链的五处硬缺陷（0.0.67 已修，本版一并带上）

1. 静默安装被「旧版全机安装」提示框拦住（`MessageBox` 没人看得见，`Quit` 照常执行）⇒ 静默模式不拦路；
2. `taskkill /F /T` 后只等 0.8 秒，引擎子进程还占着文件 ⇒ 连杀两次 + 等 1.6 秒；
3. 先 `quitAndInstall` 后拉小窗 ⇒ 顺序反转（先拉小窗）；
4. 差分失败回退 spawn 安装包 ⇒ 两个 NSIS 抢同一目录 ⇒ 禁止回退；
5. `autoInstallOnAppQuit=true` 让每次退出都试装、失败后永久停更 ⇒ 改回 false + 失败只报一次。

另有 `%APPDATA%\Codex Harness Desktop\update-install.log`：安装每一步都落盘。

## 四、你现在的操作与时间线

**手动装本版**（下载 exe 双击即可）。手动装**同样会**写回 `installer.exe`
（安装器那一行 `copyFile` 对普通安装无条件执行），所以：

| 版本 | 你会看到 |
|---|---|
| 0.0.68（本版，手动或应用内） | 整包；安装完 `installer.exe` = 0.0.68 的包 |
| **0.0.69 起** | **只下变化的几十兆**（blockmap 由 updater 自己下载） |

判断依据（装完 0.0.68 之后）：

```
%LOCALAPPDATA%\codex-harness-desktop-updater\
  installer.exe      ← 必须在（701MB 左右，0.0.68 的包）
  current.blockmap   ← 可能没有，正常，下一版 updater 会自己下
```

## 五、mac 适配审计

`node scripts/mac-audit.mjs v0.0.66 HEAD` 新增行命中 0 条；本版改动集中在
`electron/updates.ts`（差分缓存）、`electron/update-splash.ts` + 新增 `electron/splash-main.ts`
（Windows 小窗，非 win32 直接 return）、`build/installer.nsh`（NSIS 专属）。**本版不构建 mac 包**。

## 六、已知问题

- 安装小窗是独立进程，关闭它不影响安装（装完会自动打开应用）。
- 若旧版是「所有用户」安装且当前非管理员：本版按当前用户装，可能留两份，建议先卸载旧版。
- `update-install.log` 只追加不轮转（每次几十行）。
