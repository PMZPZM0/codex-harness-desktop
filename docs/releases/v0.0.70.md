# v0.0.70 发版说明

本版主题：**第一次真正可验证的差分更新** —— 从 0.0.69 升上来应该只下几十 MB。

## 一、这一版为什么是"差分的验收版"

差分需要三件事同时成立，前两件在 0.0.68 / 0.0.69 才补齐：

| 条件 | 由谁提供 | 状态 |
|---|---|---|
| 本地有**上一版的安装包本体** `<updater 缓存>/installer.exe`（差分的 oldFile） | 安装器每次安装时写回（`installer.nsh` 的 `copyFile "$EXEPATH" …`） | 你手动装 0.0.69 时就写好了 ✓ |
| 我们的代码**不再把它删掉** | `healDifferentialCache()` 重写（0.0.68） | ✓ |
| 旧版本 blockmap | updater 缺缓存时自己从服务器下载（+700KB） | ✓ |

所以：**0.0.69 → 0.0.70 这一跳就是第一次真实差分**。0.0.70 本身的改动面故意很小（只有下载源顺序 + 若干守卫 + 版本文件），差分块应该只有几 MB 到十几 MB。

## 二、下载源按今天实测重排

8MB / 16MB Range 实测（11-20 18:20）：

| 源 | 吞吐 | 结论 |
|---|---|---|
| 直连 | 302（不落地） | 保留第一档，快速回落 |
| **gh-proxy.com** | **0.68 MB/s**（单次峰值到过 10.2 MB/s） | **提到第二档** |
| hk.gh-proxy.com | 302 不可用 | 第三档 |
| **ghfast.top** | **0.095 MB/s**（掉到几十 KB/s） | 降到最后一档 |

⚠️ 这已经是第二次反转：11-15 ghfast 因 Range 403 被删，11-19 复测它最快（0.82MB/s）被加回第二档，11-20 又掉到 0.095MB/s。**每次发版前必须重测**，守卫 12e / 06-part05 的断言已按今天的数据更新（它们钉的是顺序，不是结论）。

## 三、安装进度窗（0.0.69 起）

非静默安装：oneClick 安装器只有 `MUI_PAGE_INSTFILES` 一页，会显示一条真实进度条，装完自动关闭并拉起新版本。守卫 12h 钉住「两条安装路径都不许带 `/S`」。

## 四、你该看到的

点「检查更新」后：

1. 横幅应该显示 **几十 MB**（不是 668MB）；
2. 下载完 → 「更新已就绪」→「立即重启」；
3. 应用退出 → **安装器进度窗口** → 自动打开 0.0.70。

如果横幅还是 668MB，说明 `installer.exe` 不在缓存里（手动装也会写，但如果安装时被拦/中断就不会）。判据：

```powershell
Get-ChildItem "$env:LOCALAPPDATA\codex-harness-desktop-updater" -Force | Select Name,@{n='MB';e={[math]::Round($_.Length/1MB,1)}}
```

必须有 `installer.exe`（≈700MB）。没有就说明那台机器还得再整包一次（装完它会自己写回）。
