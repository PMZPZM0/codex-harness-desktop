# v0.0.52 发版说明

本版主题：**把「装完打不开」那条路堵死，并把侧栏 / 播报 / 定位这三处日常手感修到位。**

> 版本号说明：**v0.0.51 的安装包不要装** —— 双击只弹一句 `Cannot find module`，进不了界面。
> 根因已定位并修掉（见 §一.1），直接装本版。0.0.48~0.0.50 从未打过 tag、未对外发布。

## 一、修了什么

按用户感知排序，每条写「现象 → 根因 → 修法」。

### 1. 上一版装完打不开（本版存在的主要理由）

- **现象**：装完双击，只弹一句 `Cannot find module '…/scripts/lib/tools-versions.cjs'`，界面完全不出现。
- **根因**：`build.files` 打包白名单漏了这一项。开发机上路径能解析（文件就在仓库里），
  但 asar 里没有 ⇒ **主进程顶层的 `require` 在启动第一秒就抛**，应用连窗口都建不起来。
  这是「开发机能跑 ≠ 装完能跑」的典型缺口。
- **修法**：① 白名单补 `scripts/lib/*.cjs`；② `check-require-paths` 增加**第二段判据** ——
  逃出 `dist-electron` 的相对 `require`，目标文件必须被 `build.files` 覆盖。
  反向自证过：删掉白名单那行，守卫立刻报 `features/runtime-ipc.js → 缺 scripts/lib/tools-versions.cjs`。

### 2. 会话名统一成「笔名」

- **现象**：侧栏显示「未命名任务」、顶栏显示引擎名、子会话不知道上级是谁；新建会话还会撞名。
- **修法**：两字笔名体系落地 —— **笔名即会话名**（不再在名字前挂「主管」标签），
  侧栏 / 顶栏 / 子会话上级三处联动；并发建会话不再撞名；
  删除会话会**先级联删掉它派出去的子会话**（先子后父，否则子会话成孤儿行、按自己 cwd 挂到别的项目下）。

### 3. 插队消息的位置

- **现象**：运行中插一条消息，它出现在**整轮最下面**，后面还在流式输出的内容跑到它上面去了。
- **根因**：分段门判写成「首条用户消息之前已有响应项」，而回合以用户消息开头 ⇒ 判据在真实数据上恒为假，
  上一版等于没生效。
- **修法**：分段只在**运行中**生效，按消息在流中的真实位置切开；回合结束回到整轮形态（消息全在上、过程折叠在下）。

### 4. 播报中心（悬浮窗）

- 群成员任务以「上一级」身份展示，不再伪装成用户自己的发言；
- 同一条播报不再重复出现、只敲一次字、可单条删除；
- 面板最多露出 4 条（88px × 4），再多在列表内滚轮，不再一条长事件铺满整屏；
- **打开设置 / 确认框等任何模态时，播报图标整体隐藏**。原来它会浮在弹窗上压住正文；
  只把层级降到遮罩之下也不行 —— 遮罩半透明，会透出一块残影。

### 5. 消息定位放大镜（刻度尺镜头）

用户两次反馈「看不清楚」，本版按**可读**重做：

| 项 | 原来 | 现在 |
|---|---|---|
| 行文字 | `--muted` 灰 + 12.5px | 正文色 + 13px |
| 远近透明度 | 每格降 0.16、下限 0.08（第 6 格几乎隐形） | 每格 0.08、下限 0.55 |
| 上下渐隐 | 18px（首尾整行被糊掉） | 10px（只作边缘提示） |
| 边框 | `--line`（白底上等于没有） | 正文色 18% 的可见边框 + 贴边描边阴影 |
| 滚轮 | 去重标记残留 ⇒ 监听指向旧闭包，滚了没反应 | 随挂载 / 卸载自动绑解绑 |

### 6. 通知提示音

主进程改为 `silent: true`（不再响系统默认音），提示音由渲染层用 WebAudio 合成：
完成是上行五度、失败是下行；不打包音频文件、不加包体积；只在通知**真的弹出去**之后才响。

### 7. 新增「直击本质」回复风格

设置 → 个性化多一档：先一句话说清你的**本质目标**，把你点名的手段当作候选方案之一；
发现明显更省事 / 更上游的做法时先给对照（含代价），你坚持就照做；没找到更优解就直接做。
配套 `essence-first` 技能同批下发。

### 8. 其它

项目图标分色（普通项目蓝、含指挥中枢的琥珀色）；标签列宽按簇自适应；会话行可自选底色；
任务监控面板；内置 CLI 智能体管理；右栏细线与顶栏 6px 外圈等一批手感修正。

### 9. 引擎升级到 0.166.0

内置引擎 `@openai/codex` **0.162.1 → 0.166.0**（三仓同步）。判据不是「装上就算」：
按 app-server 协议做了 `initialize` + `thread/list` 实际握手，`userAgent` 回 `0.166.0`；
应用实机启动无错误边界、会话列表与调度器正常拉起。

### 10. 三个仓的守卫换代（工程侧，用户看不到但影响能否装）

副本仓（PPcode / 云助手）的预检守卫长期停在**旧一代**（06/07 还是未拆分的单文件），
与主线源码已经对不上，导致它们的预检分别积了 32 / 26 条红 —— 这些红里**大部分是守卫过时，不是代码坏**。
本轮把守卫整代对齐，并逐条按「守卫过时 / 代码落后」分流处理：

- **守卫过时**（改守卫，不动产品代码）：`【152】` setPath 已改两步写、安卓 APK 断言在无 `android/`
  工程的仓按「本仓不含该工程」跳过、`【103】`/`【226】` 的项目工作目录名按各仓自己的
  `.codex-harness` / `.ppcode-harness` 认、`【2】` AUMID 按各仓自己的身份值认。
- **代码落后**（补实现）：`electron/tools/session-tools.ts`、`electron/bots/bot-pairing.ts` 的目录落位、
  记忆分层 `memory/{fabric-rank,layers-budget}.ts`、技能保护名单 `PROTECTED_SKILLS`、
  记忆审计/召回脚本、发布工作流（`pick artifacts/…` 分架构取件、`--clobber`、草稿转正兜底）。
- **本仓不含**：安卓远控工程只在主仓 ⇒ 相关 5 条断言在这两仓显式标注「跳过」，不再长期假红。

## 二、mac 适配审计结论

`node scripts/mac-audit.mjs v0.0.51 HEAD` 扫本版全部新增行，命中 **105 条**（分布于
`exe` / `win32` / `darwin` / `ctrl-key` / `backslash` / `powershell` 六类），逐条判读结论：

- **真缺口 0 条**。命中项全部落在三类安全区：① 平台门控内（`process.platform === "win32"` 分支：
  自绘窗口钮 `frame:false`、PowerShell 清遗留引擎、7-Zip 解压）；② 断言夹具（守卫里比对代码字符串的正则）；
  ③ 中文文案里提到 `.exe` / `pwsh`。
- **本版新增行集中在引擎升级与随包工具版本表**（`tools-versions.cjs`、`build-mac.yml` 的 nuphus ref、
  ponytail 插件目录），不含平台分叉逻辑 ⇒ 不引入新的 mac 风险。
- **本版实际修掉的 mac 硬伤 2 处**（属 0.0.51 漏项）：
  1. mac 的 `extraResources` 是空数组 ⇒ `src/lib/video-providers.mjs` 等**文件级映射**从来没进过 `.app`，
     表现为「Windows 正常、mac 上视频生成找不到厂商适配代码」。改成 afterPack 按 package.json 逐条复制。
  2. `bundledNodePath()` 按 `node` 硬拼 ⇒ mac 得到 `tools/node/node`，实际是 `tools/node/bin/node`
     ⇒ mac 上本地记忆后端永远装不上。已按平台拼接。
- 窗口 chrome：win32 走 `frame:false` 自绘三钮，**mac 保持 `titleBarStyle: hiddenInset`**（红绿灯由系统画），
  品牌行按顶栏锚点下移 —— 两平台是同一套几何，不是两套值。

## 三、mac 首次打开（三步，必须带路径）

1. 在「下载」里解压；
2. 把 `Codex Harness Desktop.app` 拖进「应用程序」；
3. 打开「终端」，**把 App 图标直接拖进终端窗口**（会自动填好路径），回车：

```
xattr -cr "/Applications/Codex Harness Desktop.app"
```

提示「已损坏」或错误 640 都是**未公证**导致的，上面这条命令放行一次即可，属预期行为。

## 四、已知问题

- 无 GPU 的远程桌面会话下动画可能降帧（属渲染层降级，不影响功能）。
