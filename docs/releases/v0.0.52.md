# v0.0.52 发版说明

本版主题：**修「装了打不开」—— 0.0.51 的安装包少了运行时文件；本版把「装完到底能不能跑」
做成可执行的判据，并补掉同一类的其余三处缺口。**

> 版本号说明：**0.0.51 的包不要装**（mac 与 Windows 都会在启动时崩）。直接装本版 0.0.52。

## 一、修了什么

### 1. 启动即崩：`Cannot find module '../scripts/lib/tools-versions.cjs'`（本版重点）

现象：双击应用，弹一个 JavaScript 错误框，主进程直接退出。

根因：`features/runtime-ipc.ts` 顶层 `require("../../scripts/lib/tools-versions.cjs")`（开发工具
版本表的单一真相源），但打包白名单 `build.files` 里没有 `scripts/**` ⇒ 这个文件根本没进 `app.asar`。
开发机仓里文件都在，所以本地跑得好、`npm run check` 全绿 —— 只有**装完的用户**会崩。

### 2. 同一类缺口的另外三处（本轮一并补掉）

| # | 缺的东西 | 症状 | 修法 |
|---|---|---|---|
| 2 | `electron/declared-plugins/**`（6 个内置插件清单） | 读不到 ⇒ 内置插件静默消失，无报错 | 进白名单 |
| 3 | `build/icon.png` / `build/icon.ico` | 窗口与任务栏图标回落 Electron 默认 | 进白名单 |
| 4 | mac 侧 `src/lib/video-providers.mjs` | **只有 mac** 缺：视频生成的 CLI 通道找不到厂商适配代码 | `afterPack` 按 `extraResources` 的文件级映射逐条补齐 |

### 3. mac：本地记忆后端找不到随包 node

两个平台的随包 node 是**两种解包布局**（Windows `tools/node/node.exe`，mac `tools/node/bin/node`），
而记忆后端按 `"node"` 硬拼 ⇒ mac 得到 `tools/node/node`（不存在）⇒ 安装命令直接 no such file，
本地记忆 MCP 在 mac 上装不上。已按平台拼。

### 4. 云管理页面的 mac 首次启动指令是错的

网页给的是 `xattr -cr "/Applications/Codex Harness.app"`，而应用包实际叫
`Codex Harness Desktop.app`。根因：把「产品名」当成了 **App 包名**。现在包名从**下载资产文件名**推
（资产就是按 productName 命名的）。云端页面已更新并部署。

### 5. 调度会话的记忆跟主会话对齐（独立 id + 归档/删除同款）

被派出去的会话（子智能体 / 专家 / 专家团主理人 / 团成员）此前**读的记忆不是自己的**：
读端拿的是**发起方**的会话 id（团成员建会话那条更是空串），而写端用的是它自己的 id
⇒ 自己写下的记忆永远读不回来，还会看到主会话 / 主理人的私有记忆。

现在：读、写、归档、删除**全部按这个会话自己的 id**（就是它的 threadId，自动就有，不用额外生成）：
- 私有层 = 它自己（跨轮累积；团成员是常驻会话，同样按会话隔离）；
- 团内层 = 团 id（此前这一层永远是 null，等于没这功能）；
- 项目层 = 工作区共享（与主会话同口径）。
- `thread/start` 的唯一钩子里补登记了会话工作目录 —— 顺带修好委派会话的**文件变更追踪**与
  **记忆捕获**（此前因为拿不到 cwd 直接静默跳过）。


## 二、这次怎么防复发（两道新判据，都已反向自证）

- **【96】②**：凡是从 `dist-electron` **逃出去**的相对 `require`，目标文件必须被 `build.files` 覆盖。
- **【288】运行时文件打包守卫**（新增）：源码里所有 `app.getAppPath()` / `__dirname` 的字面量路径
  必须进包；`process.resourcesPath` 的引用必须两端都带；另加图标、mac `afterPack` 的四条显式断言。

反向自证（把白名单那行删掉，守卫立刻报红）：

```
✗ features/runtime-ipc.js → 缺 scripts/lib/tools-versions.cjs
✗ electron/declared-plugins  ← features/declared-plugins-ipc.ts:39
✗ build/icon.png + build/icon.ico 都进包
```

**实证（不是推断）**：本机真打了一次 `electron-builder --dir`，用 `@electron/asar` 列出 asar 里
30,600 个条目，逐项核对 11 个关键文件全部存在；再**真启动**打出来的 exe —— CDP 有 page target
（标题 `Codex Harness Desktop`），UA 显示 `CodexHarnessDesktop/0.0.52`，主进程与渲染层都活着。

## 三、mac 首次打开自救（带路径）

```bash
xattr -cr "/Applications/Codex Harness Desktop.app"
```

打开「终端」，**把应用图标拖进终端窗口**会自动补全路径，不用自己猜。只需一次，升级后不用重复。
若提示 **错误 640**，是同一个 quarantine 属性，执行上面的命令后重开即可。
