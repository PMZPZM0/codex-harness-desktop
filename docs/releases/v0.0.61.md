# v0.0.61 发版说明

本版主题：**更新链路修通并做成全自动** —— 点一次能装上、之后连点都不用点。

> 版本号说明：直接 0.0.60 → 0.0.61，无跳号。上一版（0.0.60）的修复在本版继续有效。

## 一、修了什么

### 1. 「重启安装」只关了应用，没装上（用户实测）
- **现象**：点「重启更新」→ 应用关闭、弹出一次安装提醒（引导界面）→ 再打开还是旧版本。
- **根因**：差分包是 electron-updater 下到 `pending` 的安装包，原实现对任何来源都
  `spawn(安装包, [])` + 立即退出应用。本仓 `nsis.oneClick=false` ⇒ 不带 `/S` 启动的是
  **交互式 NSIS 向导 + UAC 提权框**；应用同时退出，向导被挡在后面或被当成垃圾关掉 ⇒ 什么也没装。
- **修法**：差分包交给下载它的 updater 自己装（`quitAndInstall(true, true)` = 静默安装 + 装完自动拉起新版本）；
  完整包/回退路径改为 `spawn(安装包, ["--updated", "/S"])`——`/S` 免向导，`--updated` 让安装脚本
  认作覆盖更新并在装完自动启动。安全口径不变：只接受主进程刚校验过的那个包。

### 2. 卸载确认弹窗点了不关（用户实测）
- **现象**：点卸载确认框里的「卸载」，弹窗一动不动；期间卡片还写着「正在安装（5–10 分钟）」。
- **根因**：关闭弹窗的 `setUninstallOpen(false)` 写在 `await 卸载()` **之后**，而删 5GB 要几十秒；
  同时卸载期间主进程也置了「安装中」的全局锁，卡片据此把卸载显示成安装。
- **修法**：五张开发工具卡统一改成「点卸载立刻关窗，再做卸载」；卸载期间卡片如实显示
  「正在卸载…」+ 删除进度；主进程删除前先报「正在统计要删除的文件」，删除由逐个等待改 32 路并发
  （分钟级 → 秒级）。

### 3. 更新全自动（本版新增能力，默认开）
- 后台自动检查 + 差分下载（只拉变化块）；
- 下载完成并校验通过后，**满足五条判据即自动静默安装并重启**：① 自动开关开着 ② 包已就绪
  ③ 没有回合在跑 ④ 没有工具安装/卸载在跑 ⑤ 你 90 秒没碰键鼠；
- 每 15 秒重判一次，条件不全就一直等，绝不打断正在干活的人；
- 位置：账号菜单 →「检查更新」→「自动安装：自动 / 手动」；切「手动」即回到「提示 + 点一下重启」；
- 提示条文案改为「更新已就绪，将自动安装 · 不用你操作」，按钮退化为「立即重启 / 稍后」；
- 「稍后」在自动模式下只延后 30 分钟（不会因为误点一次就永远装不上）。

⛔ **本版自身仍会走一次旧流程**：你现在装的旧版本里是旧逻辑，升到 v0.0.61 这一次仍可能弹一次向导
（点完即可）。从 v0.0.61 往后的版本，才享受「完全不用点」。

## 二、mac 适配审计结论

`node scripts/mac-audit.mjs v0.0.60 HEAD`：**命中 12 条**，逐条判读后**无真缺口**：

| 命中 | 位置 | 判读 |
|---|---|---|
| winpath / backslash | `electron/toolchain.ts:22` | 在 `process.platform === "win32"` 分支内（Windows 自带 bsdtar 的兜底路径），mac 走 `/usr/bin/tar` 分支 ⇒ 平台门控内，无害 |
| darwin | `electron/toolchain.ts:21` | 这是本版**新增的 mac 正确做法**（`/usr/bin/tar` 优先，避免 launchd 最小 PATH 落空） |
| darwin / exe / win32 | `scripts/guards/07-turn-fold/part-01.mjs` | 断言夹具（判据文本），非运行代码 |
| backslash | `scripts/guards/12l-component-update.mjs` | 断言夹具里的正则字面量 |

本版改动集中在更新链与开发工具卡片（渲染层 + 主进程），无跨平台新增缺口。

## 三、mac 首次打开自救（带路径）

1. 在「下载」里解压 zip；
2. 把 app 拖进「应用程序」；
3. 终端里先输入 `xattr -cr `（注意结尾有空格），**把 app 图标拖进终端自动填路径**，回车；
   例如：`xattr -cr /Applications/Codex\ Harness\ Desktop.app`
4. 若仍提示「已损坏，无法打开」（错误 640），就是上述命令没执行成功，重试第 3 步。

## 五、已知问题

1. **旧版本的这一次升级仍会弹向导**（原因见第一节第 3 条的说明）——从 v0.0.61 起消失。
2. **源码运行态（`npx electron .`）不适用自动更新**：它没有安装目录，自动更新会把打包版装到默认位置。
   日常使用请用安装版。
3. 自动安装只在「空闲」时执行；如果你一直有任务在跑或频繁操作，它会一直等（这是刻意的，不会掐断工作）。
