# v0.0.28 发版说明

> 发布日期：2026-09-25　|　基线版本：v0.0.27

**这是一次修复版**：0.0.27 的安装包存在一个打包环节的严重错误 —— **所有设置页都打不开**（点任意设置项都报「界面发生错误」）。本版修复该错误，并带来 MCP 记忆服务的一键安装与「设置 → 记忆」页的排版升级。macOS 与 Windows 同步发布。

## 修复

- **⛔ 0.0.27 安装包「设置页全废」**（打包环节事故）。根因：打包期的安装包瘦身逻辑用「index.html 里是否引用」来判断陈旧文件，而**所有懒加载页面 chunk 都不在 index.html 里** —— 于是被整体当成死重删除，装出来的包点任意设置页都报 `Cannot read properties of undefined (reading 'default')`。修复：改用**可达闭包**分析（从入口出发跟随产物内部引用，只有真正不可达的才算陈旧），并加安全阀 —— 闭包算出的文件数异常偏少时一律不删。发版前已在本地按 CI 同条件真打过安装包并对包内产物做完整性断言。

## 新增

- **MCP 记忆服务一键安装**（设置 → 记忆 → 页面底部「记忆后端」）：
  - 「内置记忆金字塔 / MCP 记忆服务」二选一，选择卡片式切换；**不会双写** —— 选了 MCP，内置金字塔停止捕获，不会记两份。
  - 一键**安装 / 检测连通性 / 重新安装 / 卸载**：用**应用自带的 node 与 npm** 执行，**新电脑不需要预装 Node.js**，也不需要任何编译工具链（原生绑定自动下载对应 ABI 的预编译包，下载直连失败自动换加速镜像）。
  - 装完自动做一次真实握手校验，只有服务真正应答才算装好；没装好时记忆**不会丢** —— 自动回退内置金字塔并明确提示原因。
- **「设置 → 记忆」页排版升级**：总览卡片固定 2×2 等高（此前 3+1 换行、窄卡文字被挤成竖条）、记忆后端改为选择卡片、状态徽章化、按钮统一样式。

## 已知限制（如实列出）

- 随包 Python 已在 0.0.16 移出（减重），需要本地 Python 的自动化场景仍走「桌面与浏览器自动化」的按需安装。
- 上一版列出的引擎侧限制不变：账号供应商 id 由域名首段推导；引擎「工具级审批 prompt 档」实测未生效。

## macOS 说明

- 安装包**未签名**，首次打开请**右键 → 打开**（不要直接双击）。
- ⛔ **在「下载」里解压，别把 zip 拖进「应用程序」再解压** —— 归档实用工具会报
  「无法将 … 解压缩到“应用程序”（错误 640）」：那是受保护目录，而且解压还要再占一份空间。
  报 640 就用（`ditto` 是 mac 解 `.app` 最可靠的方式，符号链接与权限都保住）：

  ```bash
  cd ~/Downloads && ditto -x -k "Codex.Harness.Desktop-0.0.28-arm64-mac.zip" .
  ```

- 若提示「已损坏」/「无法验证开发者」，终端执行：

  ```bash
  xattr -cr "/Applications/Codex Harness Desktop.app"
  ```

  **路径不用手打**：把 App 图标从访达**拖进终端窗口**，路径会自动填上。
  若报 `xattr: No such file: /Applications/Codex Harness Desktop.app`，意思是**这个位置没有 App**
  （还没把它拖进「应用程序」，或者放在了别处）—— 先 `ls -d /Applications/Codex*Harness*.app` 确认位置。

- **磁盘空间**：mac 包约 578 MB（x64 约 590 MB），解压再占一份，首次启动还要按需下载运行时与工具链 ⇒ **建议留 10 GB 可用空间**。只剩 1~2 GB 时的典型症状就是解压报 640、更新下载失败、工具装到一半出错。

## 发版前 mac 适配审计（v0.0.27..HEAD 全部新增行）

扫描器 8 条正则自证通过（正例命中、反例不命中）后，对本版全部新增行扫描：**命中 20 条**，逐条判读**全部无害，0 真缺口**：

| 模式 | 条数 | 判读 |
|---|---|---|
| `.exe` 字样 | 12 | 全部在**注释**里（解释为什么不能用 electron.exe 跑 MCP 服务），或位于 `process.platform === "win32"` **门控内**且带 `"node"` 非 Windows 分支 |
| `win32` 平台判断 | 5 | 全部在平台门控内，且每处都有对应 darwin 分支（如 MCP 安装器的 userData 路径：win 取 `%APPDATA%`、mac 取 `~/Library/Application Support/`） |
| `darwin` 平台判断 | 1 | 命中的**就是 darwin 分支本身**（MCP 安装器的 mac 路径），恰说明该链路支持 mac |
| 反斜杠路径 | 1 | 技能文档注释里的转义说明文案，非运行时路径 |
| `APPDATA` | 1 | 带 `|| os.homedir()` 兜底且 darwin 分支在前 |

另对本版新增功能的关键跨平台点逐一实测核对：MCP 原生绑定下载 URL 由**运行时真实 ABI + `process.arch`** 组成（mac arm64 自动取 `darwin-arm64` 预编译包，无写死 x64）；mac 包自带 node 由 `prepare-mac-tools.cjs` 按 CI 构建机的 arch 现造进 `tools/node`，与应用取「自带 node」的路径约定一致。
