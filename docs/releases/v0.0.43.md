# v0.0.43 发版说明

本版主题：**修压缩线永远钉在最新消息下面。**

> 版本号说明：v0.0.42 已发布，本版只含一个缺陷修复，因此递增到 0.0.43。

## 一、修了什么

### 压缩线锚点：单位不一致导致位置恒错

**现象**：对话里那条标出"自动压缩从哪里开始"的分隔线，无论上下文实际压缩到哪，**永远贴在最新消息下面**。看起来像压缩位置算错了，其实是显示位置取错了。

**根因**：锚点比较时两边的**时间单位不同**——

| 来源 | 单位 |
|---|---|
| 回合（turn）时间戳 | **秒** |
| 记录（item）时间戳 | **毫秒** |

差 1000 倍 ⇒ 比较结果恒定偏向一侧 ⇒ 锚点始终落在末尾。

**修法**：比较前统一单位。

> 这个 bug 不会丢数据，但会让"上下文用到哪了"这个判断完全失效——用户以为自己还有大量余量，实际可能早就压过了。

## 三、mac 首次打开自救（带路径）

未做 Apple 公证，首次打开会被 Gatekeeper 拦下。

1. 在「下载」里解压 zip；
2. 把应用拖进「应用程序」；
3. 打开「终端」，**把应用图标直接拖进终端窗口**（自动填出真实路径）；
4. 在路径前加 `xattr -cr `，回车：

```bash
xattr -cr "/Applications/Codex Harness Desktop.app"
```

5. 重新双击即可。**只需执行一次**，升级后不用重复。

**提示错误 640**：当前用户对该 app 无写权限，改用 `sudo xattr -cr <路径>`。

**不想用终端**：在「系统设置 → 隐私与安全性」底部点「仍要打开」，效果相同。
