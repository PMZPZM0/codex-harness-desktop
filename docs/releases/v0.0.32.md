# v0.0.32 发版说明

> 发布日期：2026-10-07　|　基线版本：v0.0.31　|　提交范围：`v0.0.31..HEAD`（215 个提交，其中 24 个为日志记账）

这一版是**跨度最大的一版**：主进程做完了「一切皆插件」重构（83 个功能域），记忆体系重做成一个内核 + 三种作用域，
新增项目知识库、扩展面插槽、桌面自动化通道升级，并把消息区、专家团办公室、主界面壁纸等一批体验问题一次清掉。

同时修掉一个**长期潜伏的大 bug**：你改的设置从来没进过引擎（见「二、重要修复」第 2 条）——
以前"改了设置、重启也不生效"这类毛病的锅都在它。

**Windows 与 macOS 功能完全一致，没有阉割**：两个平台走同一份 `build.files` 与同一套域组合表，
mac 侧随包工具由 `build/copy-mac-tools.cjs` 整体铺开（缺件直接**中止打包**，不静默跳过）。
本版发布前在本地用 **CI 同条件**真打了一次 Windows 包并逐项断言包内产物（见「六、本版怎么验的」）。

## 一、新增

### 1. 功能可以单独关掉了（架构：一切皆插件）

- 主进程被拆成 **83 个功能域**，每个域是一个可独立装载/卸载的插件：`electron/features/*.ts` 一个文件 = 一个域。
- 设置 → 插件（域启停）：**用不到的功能可以直接停用，立即生效、不用重启**；
  有一份 `essential` 名单保护内核必需项（壳、窗口、IPC 底座）。
- 域组合表是单一真相源（`electron/composition.json`），生成物由 `npm run gen:domains` 出，守卫【253】比对。
- 效果：`main.ts` 里「纯副作用 import」从 14 行降到 5 行；跨域符号必须走 barrel（守卫【130】）。

### 2. 统一记忆架构

- **一个内核 + 三种作用域**：`private`（本执行体独有）/ `team`（团内共享）/ `project`（全员共享）
  —— 谁能看到谁写的东西，现在是**结构性保证**，不再靠约定。
- 会话按 `threadId` 硬隔离；**被委派的子智能体 / 专家 / 团成员各有自己的私有记忆空间**（可读可写）。
- 写入只有一个工具（`memory_write`，旧名作别名），读/写都过同一套作用域校验。
- 前端 **记忆中心**按七类记忆给差异化视图（界面纯只读，写只能由模型/用户显式动作触发）。

### 3. 项目知识库

- 会话里模型可以直接 **查 / 写项目知识库**（`knowledge_search` / `knowledge_add`）。
- 两级检索：**全文分块**（零依赖、默认可用）+ **语义向量**（本地 ONNX 后端，**按需下载**，不占安装包体积）。
- 设置页内可安装/查看状态/卸载；文档支持全文预览弹窗、可滚动的列表与搜索结果。

### 4. 扩展面（插槽）+ 声明式插件

- 渲染层插槽 **2 → 10 个**：标题栏、全局浮层、侧栏上/中/下、会话行操作、输入框工具条下方、回合内容之下……
- **声明式插件**：外部 JSON 就能往这些位置挂东西 —— **不含代码、无需重启**（`electron/declared-plugins/*.json` 有 6 个内置样板）。
- 插件市场新增「已安装」独立入口 + 本地卸载闭环（删目录走三道防御）。

### 5. 桌面自动化升级

- **Windows**：新增 `harness-uia` 原生控件清单通道 —— 可以按「元素序号」精确操作控件，不再只靠 OCR 坐标；
  拉起 PowerShell 一律参数数组、不开 shell（注入面收敛，守卫【273】钉住）。
- **macOS**：换成随包内置的 `open-computer-use`；同一时刻只保留**一条**真实键鼠通道。
- 两个平台各有一套「该不该注册」的真值表（win32 / darwin 分派），守卫【272】【274】跑真值表。

### 6. 消息区：运行中就能看见「我在改哪些文件」

- **运行中实时「编辑 \<文件\> +N −M」行** + 文件类型图标。
- 输入框上方「**N 个文件已修改 +X −Y**」胶囊：鼠标悬停展开文件清单（类型图标 + 每文件 `+N −N` / 已删除），
  回合结束自动消失、由汇总卡接管。它是输入框卡片栈里的**普通一行**（与排队消息、询问卡、审批卡上下排序），
  **刻意没做成浮层** —— 那样遮挡问题从形态上就不该存在。
- **回合状态胶囊**：左区「步骤 N/M」（Codex 自己维护的任务清单，悬停展开）、
  右区「X 个文件已修改 +A −D」；**两区各自能单独居中，同时在才用「·」拼接**。
- **收尾不再清场**：运行中的编辑行在回合结束后**定格保留**（用最终报告的准确数字）。
- **汇总卡**：点行直接预览（图片走灯箱）、行右键复用文件卡菜单（含新增的「复制文件路径」）、
  超 2 行折叠收纳、已修改行悬停出 **diff 预览**（两轴滚动、带行号槽、面板内滚动不关窗）。
- 汇总卡报告**按会话落盘**（`<数据目录>/turn-file-changes/<会话>.json`），重启/切回会话后卡片与冻结编辑行都能复活。
- 选中文字浮出「复制 / 添加到对话」操作条（不再随拖选闪烁）。
- **任务清单生命周期**：步骤区与文件区同款 —— 只活在回合运行中，跑完/被停止/切走会话整卡即消失；
  新回合开工自动清上一轮旧清单（新通道 `tasks:clear`）。

### 7. 专家团像素办公室

- 显示器接入**真实事件面**：打开浏览器 / 写文件 / 搜文件 / 看文件 / 改文件 / 跑命令 / 调服务 / 深度思考……
  各有专属画面（20 种），屏保重做成 9 档轮播 + 交叉溶解。
- **主会话（主理人）也接上事件状态**（此前恒显示「待机」）；派单时有一张任务卡沿弧线飞过去。
- 修了行走穿模、走位卡死、站位不对着物件、名牌离角色太远、下排显示器屏面偏低等一串问题。

### 8. 主界面壁纸

设置 → 外观：**图案 / 粒子 / 3D / 自定义图片** 四档，浓度与预设可调（减动效偏好下自动回退静态）。

### 9. 上下文自动压缩，看得见

- 引擎做压缩时**不发任何事件**（压缩记录只落在会话原始记录文件里），且**自动压缩是在你那条消息内部完成的**。
  所以改成**宿主侦测**：每回合结束增量扫描会话记录文件、按记录自己的回合号认领 → 落盘 → 实时广播 → 重启重放
  → 界面上画出压缩线。
- 压缩线**常驻**：显示「✓ 上下文已自动压缩」，位置在**上一条**用户消息正上方；来新消息时线不动、随历史一起上移
  （旧实现会一直黏着最新消息往下跑）。**重启后线仍在**。
- 压缩比例可选下限从 50% 放宽到 **10%**（档位 10%~95%）。

### 10. 新手引导 + 首启弹窗收敛

- 侧栏底部常驻「新手引导」入口（在会话列表**之外**、账户行**正上方**、不会被滚动内容压住）；
  点击弹**迷你设置弹窗**（左选项 / 右内容）。
- 五节：快速上手（默认）/ 配置模型 / 开发工具 / 人格市场 / **更新日志（置底）**；三个映射点进去直达真设置页。
- 拓展接口：节是数组注册表，以后加一节 = 加一项；版本日志数据走单一真相源（`whatsnew:history`），渲染层只画不抄。
- **首启「环境体检」弹窗整体删除**（组件、自动弹出、相关状态与样式全下线）—— 现在有新手引导了。

### 11. 内置技能与风格开关

- **内置技能可以单独关掉了**（控制台 / 回复风格），并修了「关掉的技能重启后自己又开」。
- 「回复风格」从「可被点名」改成「**真的生效**」：宿主把开关翻成**常驻指令**注入给模型。
- 新增**输出风格**域；风格段会自证「这是输出设置、不是技能调用」，避免模型把它当成技能调用去报技能台账。
- 通知浮层只留最新一条（此前上下叠加），开关切换补上回执。

### 12. 其他

- 知识库、前端开发画布（44 种组件）、界面草图（只读）、Laya 增强、3D 模型预览、语音三态管理（启用/停用/删除）。
- 启动画面（ZCode 风格大 logo）、429 自动重试封顶（放弃时明确提示额度用尽）。
- 图标色相补齐（设置入口换齿轮、标题栏那一排、侧栏项目/分类行、面板 tab、账号菜单）；
  主题/代码高亮切换加过渡与完成后回执；顶栏标题定长 300px + 最多 6 字 + 📁 工作区挪到最前（新增「打开项目地址」）；

## 二、重要修复

| 现象 | 根因 |
|---|---|
| **改了设置、重启也不生效** | 组合层在数据目录重定向**之前**读设置文件，读失败的空对象被缓存了一整个进程（自动压缩比例 0.9 / 0.6 从未进过引擎） |
| 语音通话自 09-19 起**完全无法启动** | CSP 的 `script-src` 漏了 `blob:`（AudioWorklet 受 `script-src` 管，不是 `worker-src`） |
| 思考浮窗盖住办公室预览 / 设置页 / 画布 | 壳内浮层挂到 `body` 参加**根层** z 竞争，把整个 `isolation` 壳压住 |
| 办公室「屏面画到桌子上」 | 屏面坐标是从**缩放过的截图**反推的，y 偏 91px |
| 办公室「显示器内容被椅背盖掉」 | 判据扫到的是椅背（椅背颜色也满足「暗且偏蓝」） |
| 办公室「有人卡在走廊里一直走」 | 回工位时**回放陈旧路线**（头是出发地）+ 盲侧移把步进原地顶回 ⇒ 无限震荡 |
| 「调度了一个专家，办公室里没人」 | 成员源按 `running` 过滤，而委托 3.7 秒就跑完了 |
| 「调度工具用不了」 | 引擎 0.157 起内置 MCP 工具整批**延迟暴露**，模型侧不可达 ⇒ 改回宿主 dynamicTools 注册 |
| 「开启的对象类别：（无）」 | manifest 声明了参数却漏写 `invokeArgs` ⇒ preload 层**静默丢参** |
| 记忆板块白屏 | 跨进程契约两边出自同一份想象（56/56 全绿但字段名对不上）⇒ 加跨进程归一化层 |
| 侧栏「正在运行的会话消失」 | 成员收编累加留下残留 id（`memberIds` 不是派生量） |
| 「运行中有记录、收尾汇报卡却没出现」 | 收尾结算依赖单一路径 ⇒ 按回合 id **反查快照**做双保险 |
| 文件改动卡片收不到数据（三处静默缺陷） | ① 监听的广播通道全仓库没有发送方（死信道）② 追踪器广播用线程 id、卡片按回合 id 取 ③ 工作区遍历深度优先、大目录烧光文件预算，根目录新文件进不了快照 |
| 任务清单跑完不消失 / 跨回合残留 | 生命周期只覆盖「全部完成」一种状态 ⇒ 整类改为「只活在回合运行中」+ 新回合清旧清单 |
| 顶栏工作区菜单**关不掉** | 遮罩挂在**顶栏拖拽区**里，真实鼠标点击被系统当成「拖窗口」拿走（CDP 自动化测不出、真机一按就中）⇒ 改非阻塞式关闭 |
| 顶栏弹窗被裁 / 图标压在原生窗口钮下 | 缺溢出裁剪（不是缺断点） |
| 知识库「语义档永远召不回」 | 模型写入没补语义向量索引 |
| 思考输出完不折叠 / 深度思考浮层不自动展开 / 折叠动画在回合折叠重挂时重播 | 折叠状态机与重挂时序 |

## 三、macOS 适配审计（发版清单第 0 步，本版逐条判读）

用 `node scripts/mac-audit.mjs v0.0.31` 扫 `v0.0.31..HEAD` 的**新增行**，共 **123 条命中**，
分布在 `exe(9) / win32(13) / darwin(13) / ctrl-key(11) / backslash(67) / powershell(9) / appdata(1)`（`winpath` **0 条**）。

扫描器内置**正则自证门禁**（8 条正则的正/负人造样本都必须符合预期，否则直接失败退出）
—— 本版自证**通过**，所以上面不是"0 命中式"的假通过（0 命中与"正则写错了"在输出上完全一样）。

**判读结论：无 macOS 真缺口。** 三处「需人工确认」已逐条落到代码里核过：

| 命中 | 判读 |
|---|---|
| `electron/features/runtime-ipc.ts:60` 探测 `docker.exe` | **无害**。整段在 `if (IS_MAC) { … return false }` 之后 —— mac 走自己的分支（`/usr/local/bin/docker`、`/opt/homebrew/bin/docker`、`/Applications/Docker.app`），`docker.exe` 那行 mac 上**不可达** |
| `apps`/`Ctrl+N`、`Ctrl+K` 等快捷键 | **无害**。文案经 `src/lib/hk.ts` 渲染，mac 上走 `macHotkeyLabel()` 自动转 Cmd |
| `electron/features/kb-embed-backend.ts:71` 的 `"\\n"` | **无害**。该行位于**生成 worker 源码的模板串**内，求值后是正确换行；宿主侧读回调（`:291`）本就是 `"\n"` |
| `clipboard-ipc.ts:104`、`app-diagnostics.ts` 的反斜杠 | **已修**。前者改 `fileURLToPath`、后者改 `path.join`（见下方说明），此处是描述**旧实现**的注释 |
| 其余 | 平台门控内（`automation-policy` / `capability-registry` / `toolchain` / `kb-embed-backend` 的异平台清理）/ 断言夹具（`scripts/`）/ 文案命中 —— 均无害 |

**mac 打包链路复核（照做，未改动）**：

- `build/electron-builder.mac.cjs` 的 `artifactName` 是 `${productName}-${version}-${arch}-mac.${ext}` ⇒
  arm64 / x64 两个包名都自带架构名。这是**更新器契约** —— 应用内按「`mac` + `.zip` + 架构名」匹配资产，
  名字错了用户端会**静默**显示「已是最新」，不报错。
- `afterPack` = `build/copy-mac-tools.cjs`：缺 `expert-skills` / `voice-presets` / `install-runtimes.cjs` /
  `install-automation.cjs` 时**直接 `throw` 中止打包**（不是静默跳过）。
- mac 侧随包工具整体铺开进 `Contents/Resources/tools`，**开箱即用**（不走 `automation-tools.zip` 那条路）。
- mac 侧 ONNX Runtime 上游**只在 `osx-arm64` 提供**（Intel 已放弃）⇒ 脚本降级为警告：
  **Intel Mac 缺语音/OCR 能力，其余功能正常**。

## 四、macOS 首次打开（安装包未签名，Gatekeeper 会拦）

1. **在「下载」里解压**（别在「应用程序」里解压，会报错误 640）；
   报 640 就用终端：`cd ~/Downloads && ditto -x -k "<zip 文件名>" .`
2. 把 App **拖进「应用程序」**（别在「下载」里直接双击运行 —— 那样会被挂到只读的临时卷上跑）
3. **右键 → 打开**（不要直接双击）
4. 仍提示「已损坏」时，终端执行（**把 App 图标拖进终端窗口，路径会自动填**）：

```bash
xattr -cr "/Applications/Codex Harness Desktop.app"
```

> 若终端回 `xattr: No such file`，说明该路径下没有 App —— 用 `ls -d /Applications/Codex*Harness*.app` 自查。
> 建议留 **10 GB** 磁盘空间（解压占一份，首次启动还要按需下载运行时/内核）。

## 六、本版怎么验的（防「打包版缺功能」）

0.0.27 出过一次事故：打包期裁剪把懒加载 chunk 全删了，安装版设置页整片崩。所以本版在推 tag **之前**
在本地用 **CI 同条件**真打了一次 Windows 包（`CI=1 electron-builder --win nsis`），并解包 `app.asar` 逐项断言：

- asar 内 `package.json` 版本 == `0.0.32`；
- **懒加载引用闭包 == 全部资产**（0 陈旧、全可达）—— 这是 0.0.27 事故的直接判据；
- 包内**相对 `require` 全部可解析**（0.0.29「启动即炸」事故的直接判据）；
- `src/lib/*.mjs` 纯函数模块**逐个在包内**（`build.files` 是目录通配，以后新增自动随包）；
- 随包工具链逐项非空；
- **本版功能特征串全部命中**（用**用户可见文案**而不是变量名 —— 生产构建会压缩变量名，用它判会误报"没打进"）。

macOS 侧由 CI 的 `macos-14`（arm64）与 `macos-15-intel`（x64）两个 runner 产出，走同一份 `build.files` 与同一套域组合表，
**功能与 Windows 一致**。
