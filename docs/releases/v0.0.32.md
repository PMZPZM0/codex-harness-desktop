# v0.0.32 发版说明

> 发布日期：2026-10-06　|　基线版本：v0.0.31

这一版是**跨度最大的一版**（v0.0.31 以来 168 个提交）：主进程做完了「一切皆插件」重构（69 → 85 个功能域），
记忆体系重做成一个内核 + 三种作用域，新增项目知识库、扩展面插槽、桌面自动化通道升级，
并把消息区、专家团办公室、主界面壁纸等一批体验问题一次清掉。

---

## 一、新增

### 1. 功能可以单独关掉了（架构：一切皆插件）

- 主进程被拆成 **85 个功能域**，每个域是一个可独立装载/卸载的插件：`electron/features/*.ts` 一个文件 = 一个域前缀。
- 设置 → 插件（域启停）：**用不到的功能可以直接停用，立即生效、不用重启**；
  有一份 `essential` 名单保护内核必需项（壳、窗口、IPC 底座）。
- 域组合表是单一真相源（`electron/composition.json`），生成物由 `npm run gen:domains` 出，守卫【253】比对。
- 效果：`main.ts` 里「纯副作用 import」从 14 行降到 5 行；跨域符号必须走 barrel（守卫【130】）。

### 2. 统一记忆架构

- **一个内核 + 三种作用域**：`private`（本执行体独有）/ `team`（团内共享）/ `project`（全员共享）
  —— 谁能看到谁写的东西，现在是**结构性保证**，不再靠约定。
- 会话按 `threadId` 硬隔离；**被委派的子智能体 / 专家 / 团成员各有自己的私有记忆空间**（可读可写）。
- 写入只有一个工具（`memory_write`，旧名作别名），读/写都过同一套作用域校验。
- 前端 **记忆中心**按七类记忆给差异化视图（界面纯只读，写只能由模型/用户显式动作触发）。

### 3. 项目知识库

- 会话里模型可以直接 **查 / 写项目知识库**（`knowledge_search` / `knowledge_add`）。
- 两级检索：**全文分块**（零依赖、默认可用）+ **语义向量**（本地 ONNX 后端，**按需下载**，不占安装包体积）。
- 设置页内可安装/查看状态/卸载；文档支持全文预览弹窗、可滚动的列表与搜索结果。

### 4. 扩展面（插槽）+ 声明式插件

- 渲染层插槽 **2 → 10 个**：标题栏、全局浮层、侧栏上/中/下、会话行操作、输入框工具条下方、回合内容之下……
- **声明式插件**：外部 JSON 就能往这些位置挂东西 —— **不含代码、无需重启**（`electron/declared-plugins/*.json` 有 6 个内置样板）。
- 插件市场新增「已安装」独立入口 + 本地卸载闭环（删目录走三道防御）。

### 5. 桌面自动化升级

- **Windows**：新增 `harness-uia` 原生控件清单通道 —— 可以按「元素序号」精确操作控件，不再只靠 OCR 坐标；
  拉起 PowerShell 一律参数数组、不开 shell（注入面收敛，守卫【273】钉住）。
- **macOS**：换成随包内置的 `open-computer-use`；同一时刻只保留**一条**真实键鼠通道。
- 两个平台各有一套「该不该注册」的真值表（win32 / darwin 分派），守卫【272】【274】跑真值表。

### 6. 消息区

- **运行中实时显示「编辑 <文件> +N −M」行** + 文件类型图标。
- 回合结束给**文件改动汇报卡**：点行直接预览、右键复制文件路径、可折叠、图片给缩略图。
- 选中文字浮出「复制 / 添加到对话」操作条（不再随拖选闪烁）。
- 修了一批真缺陷：思考输出完不折叠、深度思考浮层不自动展开、折叠动画在回合折叠重挂时重播。

### 7. 专家团像素办公室

- 显示器接入**真实事件面**：打开浏览器 / 写文件 / 搜文件 / 看文件 / 改文件 / 跑命令 / 调服务 / 深度思考……
  各有专属画面（20 种），屏保重做成 9 档轮播 + 交叉溶解。
- **主会话（主理人）也接上事件状态**（此前恒显示「待机」）。
- 修了行走穿模、走位卡死、站位不对着物件、名牌离角色太远、下排显示器屏面偏低等一串问题。

### 8. 主界面壁纸

设置 → 外观：**图案 / 粒子 / 3D / 自定义图片** 四档，浓度与预设可调（减动效偏好下自动回退静态）。

### 9. 其他

- 知识库、前端开发画布（44 种组件）、界面草图（只读）、Laya 增强、3D 模型预览、语音三态管理（启用/停用/删除）。
- 启动画面（ZCode 风格大 logo）、429 自动重试封顶（放弃时明确提示额度用尽）。

## 三、macOS 适配审计（发版清单第 0 步，本版逐条判读）

用 `node scripts/mac-audit.mjs v0.0.31` 扫 `v0.0.31..HEAD` 的**新增行**，共 **109 条命中**，
分布在 `exe / win32 / darwin / ctrl-key / backslash / powershell / appdata`（`winpath` 0 条）。
扫描器内置**正则自证**（8 条正则的正/负样本都必须符合预期，否则直接失败退出）⇒ 下面不是"0 命中式"的假通过。

**判读结论：2 处真缺口，均已修。**

| 缺口 | 现象（mac 上） |
|---|---|
| `electron/features/clipboard-ipc.ts` 把 `file://` 转成本地路径时**手写 Windows 规则**（`/`→`\`、去掉前导 `\`） | 粘贴文件得到 `Users\x\y.png`（丢了根、分隔符还是反斜杠）⇒ 该功能在 mac 上直接失效。改用 `node:url` 的 `fileURLToPath`（平台正确 + 处理百分号转义） |
| `electron/features/app-diagnostics.ts` 诊断面板里展示路径写死 `\\` | mac 上显示 `/Users/x/.codex-home\config.toml`（正斜杠目录 + 反斜杠文件名）。改用 `path.join` |

**其余 107 条判为无害**，分类如下：

- **平台门控内**（`process.platform === "win32" / "darwin"` 分支里的 `.exe`、PowerShell、UIA 脚本）：
  `automation-policy.ts`、`capability-registry.ts`、`runtime-ipc.ts` 的 mac 分支（git/openssl/docker 各自探测
  `/usr/bin`、`/usr/local/bin`、`/opt/homebrew/bin`、`/Applications/Docker.app`）、`toolchain.ts`（非 darwin 直接返回空串）、
  `kb-embed-backend.ts`（只删**异平台**的 onnxruntime 目录）。
  ⛔ 特别注意 `connectors-ipc.ts` 的 `spawn(process.platform === "win32" ? "npx.cmd" : "npx")` —— 这是**正确**写法。
- **断言夹具**（`scripts/` 下的正则/路径样本，纯字符串不碰文件系统）：`07-turn-fold.mjs`、`09-structural.mjs`、
  `11d/11e/11h/11l-*.mjs`、`11f-dispatch-integrity.mjs`（用 `APPDATA || homedir()/AppData/Roaming` 兜底）。
- **文案命中**：`Ctrl+Z 撤销`、帮助文本里的「Windows」、`developer-instructions.ts` 的工具包说明。
- **新增随包资源**：`resources/tools/desktop-uia.ps1`、`harness-uia.mjs` 属 Windows 桌面通道，已进 `extraResources`
  （预检【29】逐条比对）；mac 侧由 `build/copy-mac-tools.cjs` 整体铺开，多带这两个文件无害。

**mac 打包链路复核**：`build/electron-builder.mac.cjs` 的 `artifactName` 含 `${arch}` ⇒
arm64 / x64 两个包名都自带架构名（更新器是按「`mac` + `.zip` + 架构名」匹配资产的，名字错了用户端会**静默**显示「已最新」）；
`afterPack` 会 `throw` 而不是静默跳过 —— 缺 `expert-skills` / `voice-presets` / `install-runtimes.cjs` /
`install-automation.cjs` 直接中止打包。mac 侧 ONNX Runtime 在 Intel 上**上游已放弃**（只有 `osx-arm64`），
脚本降级为警告：Intel Mac 缺语音/OCR 能力，其余功能正常。

合并前另修了一处**工具链自身的坑**：`scripts/mac-audit.mjs` 的 `execFileSync` 没显式给 `stdio`，
在受限环境里子进程直接 `EBUSY`（报错位置在 `spawnSync` 内部，看着像"git 不在 PATH"或"脚本坏了"）
⇒ 补 `stdio: ["ignore","pipe","pipe"]`（与仓库其它真跑子进程的脚本统一）。

## 四、macOS 首次打开（安装包未签名，Gatekeeper 会拦）

1. **在「下载」里解压**（别在「应用程序」里解压，会报错误 640）；
   报 640 就用终端：`cd ~/Downloads && ditto -x -k "<zip 文件名>" .`
2. 把 App **拖进「应用程序」**（别在「下载」里直接双击运行 —— 那样会被挂到只读的临时卷上跑）
3. **右键 → 打开**（不要直接双击）
4. 仍提示「已损坏」时，终端执行（**把 App 图标拖进终端窗口，路径会自动填**）：

```bash
xattr -cr "/Applications/Codex Harness Desktop.app"
```

> 若终端回 `xattr: No such file`，说明该路径下没有 App —— 用 `ls -d /Applications/Codex*Harness*.app` 自查。
> 建议留 **10 GB** 磁盘空间（解压占一份，首次启动还要按需下载运行时/内核）。
