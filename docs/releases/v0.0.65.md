# v0.0.65 发版说明

本版主题：**更新体验的三处硬缺陷**（提示关不掉 / 镜像龟速 / 差分永远不生效）。

## 一、修了什么

### 1. 更新提示关不掉

现象：后台下载时左下角常驻一张进度卡，**没有任何关闭入口**（`UpdateFlowBanner` 88 行里 `关闭/取消/dismiss/onClose` 一处都没有）。

修法：右上角加收起键。收起只影响显示，**下载继续跑**；下载结束 / 换版本 / 进入安装阶段会自动恢复显示。安装遮罩（全屏那层）不受影响 —— 那一层是「正在安装，别重复启动」的保护，不该被关掉。

### 2. 镜像下载龟速（实测一分钟 1M）

按实测 4MB Range 吞吐重排候选序（`electron/gh-mirror.ts`，仍是全局唯一真相源）：

| 通道 | 实测吞吐 | 处置 |
|---|---|---|
| 直连 GitHub | 本机不可用（空响应） | 保留第一档，失败即快速回落 |
| `ghfast.top` | **0.82 MB/s** | 提到第二档（11-15 因 Range 403 删过一次，现已恢复 206） |
| `gh-proxy.com` | 0.42 MB/s | 第三档 |
| `hk.gh-proxy.com` | 302 后不可用（跳 objects 被挡） | 第四档 |
| `ghproxy.net` | 0.014 MB/s（≈0.8MB/分钟） | 已在候选外，不再使用 |

### 3. 差分更新永远不生效（用户原话：「我要的是用户差分更新」）

根因不是「没有基线」这么笼统，而是**缓存配对坏掉且不会自愈**：

- electron-updater 的 NSIS 差分靠成对缓存：`<updater 缓存目录>/installer.exe` + 同目录 `current.blockmap`；
- 实测本机缓存里只有 2026-10-12 的 `installer.exe`（386MB），**没有 `current.blockmap`** —— 配对失效，updater 只能下整包，而且这个状态**永远不会自己修好**；
- 于是每一版都整包，用户看到的「差分更新」形同虚设。

**审查还发现第二处（更致命）**：差分下载那段的 `autoInstallOnAppQuit` 原本被显式设成 `false` —— 意思是「下载完只等用户点重启安装」。用户中途关掉应用，那个 updater 句柄就没了，下次点安装只能走 spawn 老路（不经 updater 安装器），配对缓存永远写不回去。已改为 `true`：不点按钮、直接退出也由 updater 装完并写回配对缓存。

修法：`electron/updates.ts` 新增 `healDifferentialCache()`，在差分入口调用前自愈 —— **缺任一份就两份都删**（只动自家 updater 缓存目录，⛔ 不碰安装目录、不碰用户数据），让 updater 重新拉一次完整包并写回**成对**的缓存。

**必须说清的口径**：NSIS 差分没有「从安装目录反推基线」的能力，基线只能来自「上次由 updater 完成安装」。所以自愈后 **本版仍是整包**，从 **v0.0.66 起** 同一条安装线才会只下变化块。本机与所有用户的判定方法一致：`%LOCALAPPDATA%\codex-harness-desktop-updater\` 里 `installer.exe` 与 `current.blockmap` 同时存在 = 已具备差分基线。

### 4. 选「补丁」不再装作能差分

现象（用户原话）：「我明明选的差分更新还走完整包」。根因：那个「补丁 / 完整包」开关**只影响文案**，
真正决定走哪条通道的是「本机有没有成对缓存」；缺基线时 updater 静默下整包，界面照旧写「正在下载更新」。

修法（用户拍板方案 A）：
- 新增 `hasDifferentialBaseline()`（`electron/updates.ts`）：`installer.exe` 与 `current.blockmap` 成对才叫有基线；
- 选了「补丁」而本机无基线时，进度条直接写 **「本次为完整包（本机无差分基线，装完自动建立）」**，
  不再用「后台进行中」糊过去；下载结果里回传 `differential: false` + `noBaseline: true`；
- 「补丁」选项的说明也改成事实：需要上一次的差分基线，没有就下整包。

## 二、mac 适配审计结论
`node scripts/mac-audit.mjs v0.0.64 HEAD`：本轮改动集中在 `electron/updates.ts`、`electron/gh-mirror.ts`、`src/features/app-view/AppView/UpdateFlowBanner.tsx`、`src/styles/37-update-ready.css`。差分与镜像逻辑均在 `process.platform === "win32"` 门控内（mac 直接抛 `differential_unsupported_platform` 走完整包），无平台敏感新增行。

## 三、mac 首次打开自救（带路径）

1. 在「下载」里双击解压；
2. 把 App 拖进「应用程序」；
3. 首次打开若提示"无法验证开发者"：右键 →「打开」；或把 App 图标拖进终端自动填好路径后执行：
   ```bash
   xattr -dr com.apple.quarantine "/Applications/Codex Harness Desktop.app"
   ```
4. 错误码 640 表示系统仍在隔离态，重复上一步即可。

mac 更新：**每次都是完整包**（无 NSIS blockmap，不是漏做）。

## 五、已知问题

- 本版新装/升级仍是整包（缓存重建）；差分的「几十兆」从 v0.0.66 起可见。
- 若中途手动装 exe（不经应用内更新），配对缓存会再次缺失，下一版又回整包。
- 收起键只作用于后台下载提示；全屏安装遮罩不可关闭（防止安装期间重复启动）。
