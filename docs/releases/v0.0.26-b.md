# v0.0.26-b 发版说明

> 发布日期：2026-09-21　|　基线版本：v0.0.26-a

**这是 v0.0.26 的第二个修订版（`-b`）**：主要解决三类实测问题 —— **账号卡片的「当前生效」说假话**、**生图结果把 3 MB base64 塞进对话历史**、**调度开关的提示把用户指向不存在的入口**；另新增「计划可编辑」「新鲜上下文评审」「当前能力链路」「配置安全扫描」四项能力，并内置 3 个第三方写作技能。macOS 与 Windows 同步发布。

## 修复

- **中转站 / OpenAI 账号停用了却还显示「当前生效」**。根因是**读取路径带副作用**：401 自动重登时会把被写账号无条件设成「生效」，而中转站页面一打开就会对**每个账号**发一次请求 —— 于是「只是打开页面」就可能把停用账号顶成生效账号（还会连带改写引擎模型配置）。现在「写凭据」与「写谁生效」是两个动作，读取时自愈（生效账号指向停用/不存在的条目 → 清空），且自愈**只改这一个字段**、不会顺手动你的其他数据。
- **账号删除入口看不见、且点了就删**。此前删除按钮是纯图标（容易被读成「进入」），只有悬停才有说明，且**没有二次确认**；OpenAI 卡片根本没有删除入口。现在三处均为**带文字的「删除」+ 二次确认**（写明会失去什么、不影响什么）。同时**移除隐藏的第二条删除入口**：旧的「退出登录」按钮不接参数、按「当前生效账号」删除 —— 你看着 A 的面板可能删掉 B。
- **点账号卡片的「管理」会直接切换生效账号**（顺带重写模型配置、重启引擎）。现在只打开面板；面板数据改为**按被点开的那个账号**读取（密钥也建在它身上），非生效账号的操作按钮会禁用并提示先「设为当前」。
- **生图结果被内联进对话**。生图网关常只回 base64，此前被拼进工具返回文本 ⇒ **单条消息 3 MB、每轮对话都要重发一次**。现在图片一律落盘到本机目录，工具只返回路径。
- **调度开关的提示把你指向错的地方**。权限拒绝语原文写「请在**输入框**的调度开关里重新开启」，而那个面板**早已不在输入框旁**（唯一入口是会话**顶栏右上角**的图标）—— 模型会把这句话原样转告你，于是你去输入框找不到。文案已改正，帮助文档也补了「在哪开」。
- **深色模式下独立窗口的系统按钮看不见**（用户实测）。
- **回滚「别的会话待审批」浮层**（观感不对，已撤回）。
- 工具安装的**验证步骤不再连坐整个安装**（验证是收尾快照，任一条失败曾被当成「整个安装失败」）。

## 新增

- **计划可编辑**。计划卡片里的每条都可以勾选完成 / 改文字 / 删除 / 新增，改完点「交给 Codex」把改后的计划**作为一条消息发回**。⚠️ 说明一个语义边界：计划的权威状态在模型那边，所以这里的含义是「我改了计划 → 让模型按新的执行」，**不是**直接改引擎里的计划。编辑内容按会话保存，交回后清空。
- **「评审（新鲜上下文）」子智能体**（内置）。它**看不到你和 Codex 之前的对话**，只按你给的材料挑问题 —— 这正是它的价值：写的人不审自己。用法：在会话顶栏打开「调度」→ 勾选子智能体 → 让 Codex 交付前先送审。
- **「当前能力链路」**：多个后端（本地 / 中转站 / 官方订阅 / 第三方）同时存在时，「现在到底走哪条」有唯一来源，不再靠猜。
- **配置面安全扫描**：把 agent 自己的配置（技能文件、MCP、指令、hook）当攻击面扫一遍，命令行 `npm run scan:config` 可单独跑。
- **内置 3 个第三方写作技能**：`humanizer`（去 AI 腔）、`no-ai-slop`（去空话套话）、`i-have-adhd`（结论先行、说短）。内置内容逐字保留上游并带 sha256 防漂移断言，来源与许可记在 `THIRD_PARTY_NOTICES.md`。
- **文档转换（`document-convert`）改为按需下载**：PDF / Word / PPT / Excel 互转所需的依赖不再随包塞满，按需拉取（实测：全量 273 MB，按需子集 120 MB）。

## 已知限制（如实列出）

- 账号的供应商 id 由**域名首段**推导 ⇒ 同一主机上放两个中转站会撞同一个 id。现实用法是域名，**本版未改**（改规则会让存量绑定失效）。
- 引擎侧的「工具级审批（`approval_mode=prompt`）」经实测**不会真的发出审批请求** ⇒ 该档目前在引擎内等于未生效，不是我们的界面漏接。
- 「架构改造（按域拆文件）」已立项并出清单（`docs/archive/REFACTOR-PLAN-2026-09-21.md`、`docs/REFACTOR-COMPARE-2026-09-21.md`），**本版不含代码改动**，后续版本分批进行。

## macOS 说明

- 安装包**未签名**，首次打开请**右键 → 打开**（不要直接双击）。
- ⛔ **在「下载」里解压，别把 zip 拖进「应用程序」再解压** —— 归档实用工具会报
  「无法将 … 解压缩到“应用程序”（错误 640）」：那是受保护目录，而且解压还要再占一份空间。
  报 640 就用（`ditto` 是 mac 解 `.app` 最可靠的方式，符号链接与权限都保住）：

  ```bash
  cd ~/Downloads && ditto -x -k "Codex.Harness.Desktop-0.0.26-b-arm64-mac.zip" .
  ```

- 若提示「已损坏」/「无法验证开发者」，终端执行：

  ```bash
  xattr -cr "/Applications/Codex Harness Desktop.app"
  ```

  **路径不用手打**：把 App 图标从访达**拖进终端窗口**，路径会自动填上。
  若报 `xattr: No such file: /Applications/Codex Harness Desktop.app`，意思是**这个位置没有 App**
  （还没把它拖进「应用程序」，或者放在了别处）—— 先 `ls -d /Applications/Codex*Harness*.app` 确认位置。

- **磁盘空间**：mac 包约 578 MB（x64 约 590 MB），解压再占一份，首次启动还要按需下载运行时与工具链 ⇒ **建议留 10 GB 可用空间**。只剩 1~2 GB 时的典型症状就是解压报 640、更新下载失败、工具装到一半出错。

| 模式 | 命中 | 判读 |

| `exe` | 1 | **无害** —— `scripts/install-runtimes.cjs:475` 是平台三元表达式（darwin 取 `bin/python3`、其他取 `python.exe`），正是 mac 分支本身 |

| `backslash` | 3 | **误报** —— 全是正则转义与字符串样本（`\\\$\{` 反转义、`replace(/\\/g,"/")`、markdown 样本里的 `\\n`），不是路径 |

**结论：真缺口 0 处，本版无需 mac 适配修复。** 命中 16 条全部属「平台门控内 / 断言夹具 / 文案」，逐条判读如上。
