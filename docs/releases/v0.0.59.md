# v0.0.59 发版说明

本版主题：**开发工具大扩 + 远控配对安全加固 + 输入法修复**。

## 一、修了什么（按用户感知排序）

### 1. 开发工具页「装得齐、更得动」

**现象**：开发工具里缺一批常用工具；已有卡片的更新入口分散，Laya 更是完全没有更新按钮（用户实测「这里没有更新功能啊，这个好久没更新了」）。

**根因**：`runtime:update-check` 只有两条清单 —— `UPDATEABLE_TOOLS`（npm 包）与 `GITHUB_UPDATEABLE`（GitHub release 直下）。Laya / 手机控制 / markitdown 都是 **pip 包**，两条链都不认，查询直接抛「该工具不支持在线更新」，所以卡片从来接不上更新行。

**修法**：
- 新增 pip 型更新链（`PIP_UPDATEABLE`）：查 PyPI（官方 JSON + 清华镜像同构接口）与 `pip show` 已装版本对比，升级复用 `layaInstall` 的 `pip install -U`（带多镜像回落、装后复核）。实测本机 0.4.20 → 最新 0.4.31。
- ⛔ pip 型**不进后台自动更新清单**：laya 带 PyTorch 依赖，不能无人值守重装。
- 更新行加 `cancellable`：pip 子进程没有中断钩子，界面显示「更新中」而不是一个点了没反应的取消键。
- 新增 Husk（iPhone 跑 Android，含 TrollStore 专用 .tipa）、ApkStart（安卓运行器）、OpenMAIC（互动课堂）三张卡，均带「检查更新」。

### 2. 远控配对：假设备伪造不了「已批准」

**现象**：公网中转上出现过测试假隧道，不校验配对码就直接回 `ok:true`，手机被秒批、真正的电脑端收不到请求、永远不弹「允许」框。

**修法**：
- 配对应答加 HMAC 签名（键由隧道令牌派生，盐与网关逐字一致），签名不对的应答一律丢弃；
- 根配对改**按码定向**（只问上报了同一 6 位码的那台电脑），不再广播；
- 设备 ID 收紧 + 只认电脑端应用的应答形状；
- 根配对限流取 `X-Forwarded-For` **最后一跳**（第一跳客户端可伪造）；
- 新增「禁止新设备配对」开关：开启后只允许已批准设备凭设备秘密重连，新手机与新 Bot 渠道一律拒绝，同时作废在途请求并轮换配对码。

### 3. 群聊工作伙伴（Pachat 模型）

先读再说、去掉自由催办；每成员每日预算 + 失败隔 5 分钟重试一次；群模板可复用；群治理增加活跃度与群规矩。

### 4. RPA 键鼠录制 + 定时执行

Windows 原生录制与回放；mac 走系统授权（Swift/CoreGraphics）；可挂到定时任务调度器上跑。

### 5. Agent Desktop 无障碍树后端

新增随包内置的桌面自动化后端（默认主），Windows / mac / Linux 提供 npm 包自带二进制；指令语法与默认值已修。

### 6. 输入法两个真 bug

- **中文打不了**：空输入框用中文输入法组字时被清空（打数字正常）——组字期间不再重建受控值。
- **假光标**：删空后占位提示后面跟着真光标，看着像提示是已输入的字。

### 7. 其它修复

- OpenFilm 安装完状态停在「安装中」、连接 Studio 报 `node ENOENT`；
- ApkStart 状态卡打开时逐端口扫描导致卡片长时间转圈；
- 组件更新行在取消后永远停在「正在更新」；
- 安装旧版本时按 `latest` 的 digest 校验 ⇒ 误报 SHA256 失败（改为按目标版本 tag 查）；
- 镜像停滞时等待 write drain 造成下载死锁（实测卡在 105MB）。

## 二、mac 适配审计结论

`node scripts/mac-audit.mjs v0.0.58 HEAD`：**命中 232 条**，分布 `exe / win32 / darwin / ctrl-key / backslash / winpath / powershell / appdata`。逐类判读：

| 分类 | 判读 |
|---|---|
| `apkstart-ipc.ts` / `ApkStartCard.tsx`（主体） | ApkStart 是 **Windows-only** 功能（安卓模拟器 + adb），安装函数内有 `process.platform !== "win32"` 显式拒绝，属平台门控内 |
| `powershell` | Husk 的 iPhone 连接检测在 `process.platform === "win32"` 分支里，mac 分支走 `system_profiler` |
| `appdata` / `winpath` | 全是 ApkStart 运行时目录文案（`%APPDATA%\apkstart`）与其卸载说明，同样是 Windows 专属 |
| `darwin` | 均为平台门控参数（`platform: "win32" \| "darwin"` 分支、`platforms: [...]` 白名单），不是硬编码 |
| `exe` / `ctrl-key` / `backslash` | 可执行名常量与快捷键标签真值表；`ctrlKey \|\| metaKey` 是正确跨平台写法 |

**结论：逐条判读后，本版新增逻辑无 mac 真缺口。**

## 三、mac 首次打开自救（带路径）

1. 在「下载」里解压 zip；
2. 把 app 拖进「应用程序」；
3. 终端里先输入 `xattr -cr `（注意结尾有空格），**把 app 图标拖进终端自动填路径**，回车；
   例如：`xattr -cr /Applications/Codex\ Harness\ Desktop.app`
4. 若仍提示「已损坏，无法打开」（错误 640），就是上述命令没执行成功，重试第 3 步。

## 五、已知问题

1. `koffi` 无预编译二进制（既有状态）⇒ Windows 窗口圆角不生效，其余功能不受影响；修复需要能跑 koffi 构建脚本的环境（本机 `reg.exe` 被安全策略拦截）。
2. `@tsparticles/*` 停在 4.5.3，等镜像补齐 4.6.0 全量包后升级。
3. 远控中转仍是**开放注册**：配对应答签名只能防「同一设备 ID 被冒用」，不能阻止攻击者新建一台假设备；设备注册准入需产品侧决策。
4. pip 型更新当前只登记 Laya；新增 pip 工具时必须同时补 `performRuntimeUpdate` 的安装器分派（代码里是显式 `throw`，不会静默走错安装器）。
