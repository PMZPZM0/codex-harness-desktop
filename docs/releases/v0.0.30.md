# v0.0.30 发版说明

> 发布日期：2026-10-02　|　基线版本：v0.0.29

## 本版重点：开发工具「装不上」修好了

外部用户反馈：点**任何**开发工具（Git、PowerShell 7……）都报同一句
`解压失败 [fail] "tar"`，下载明明跑到 100% 却装不上，反复点也没用。查到两个叠加的真缺陷：

- **解压器路径写死**：原来只认 `C:\Windows\System32\tar.exe`。系统盘不是 C: 的机器、
  精简版系统上取不到它，就回落到裸 `tar`，而多数机器的 PATH 上并没有 tar ⇒ 凡是走压缩包的
  工具**全部**安装失败，报错还被截成两个字的 `"tar"`，根本看不出是缺解压器。
  现在解压器跟随真实系统盘、并从 PATH 兜底解析；解压按 **系统 tar → 7-Zip →
  Windows 自带 PowerShell** 三级降级 —— 那台机器**不需要装任何解压软件**。
- **坏掉的下载缓存无法自愈**：缓存的压缩包校验不过时，旧逻辑仍走「断点续传」——
  续传只补尾巴，「体积对、内容坏」的文件永远修不好，于是每次都是「进度瞬间 100% → 解压失败」，
  重试多少次都一样。现在校验不过会**先删掉再完整重下**，下载完还会再校验一次、坏包自动重下。

另外修了两处配套问题：

- **随包 7-Zip 是空壳**：原来下的是 `7zr.exe`（**精简版，只认 7z 格式**）还改名成 `7z.exe`，
  实测它连普通 zip / tar.gz 都打不开。现换成完整版 `7za.exe`（zip / gzip / tar / 7z 全支持）。
- **报错信息可读**：解压失败时会写清「用哪个解压器、找过哪些路径、压缩包多大」，
  不再出现只有两个字的 `"tar"`。

## 本版其余修复

- **未配模型时点发送会报错**：模型配置引导删除后漏改了一处调用，点到未配置模型的分支会拿到
  undefined 直接抛错。现在改为「人话提示 + 直达设置里的模型页」，并保留已输入的内容。
- **清理两处死导入**，补齐 `bag-types` 类型漂移（共 11 项残留 / 9 项漏登记 / 4 项类型过期）。
- **发布链路兜底**：删 tag 重建会让同名 release 退回草稿态（草稿对匿名 API 不可见、
  用户永远收不到这一版），现在发布流程会自动转正，并同步重写发布说明正文。
