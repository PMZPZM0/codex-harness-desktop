# v0.0.58 发版说明

本版主题：**群聊编排真正闭环 —— 逐个拉人建的群派活跑通，重复派单 / 假回执 / 验收被吞 / 侧栏透出四类问题清零。**

> 版本号沿既有 `v0.0.x` 线递增（0.0.57 → 0.0.58），未跳大版本。PPcode / 云助手同轮同步同源改动，
> 品牌与版本线各自独立。

## 一、修了什么（按用户感知排序）

### 1. 逐个拉人建的群，主理人拿不到派活工具（本轮主根因）
- **现象**：主理人在群里写「这一轮派给：显影」+ 整段任务书，成员零反应、连工具调用卡都没有。
- **根因**：编排判定只认「整团槽」（`targetKind === "team"`）。用户从 @ 面板**逐个拉人**建的群——
  群里坐着的是 expert 座位的团主理人——被判成"非团群"，主理人工具面只剩
  `group_say / group_read / group_members` 三个，催办 / 回交 / 收口整套编排全部不激活。
- **修法**：新增 `resolveGroupTeamSeat`（单一真相源）：整团槽 / 主持人座位 / 群里唯一主理人座位
  同一口径，判不准返回 null 不猜；发言链路与启动预升级两处同源解析。
- **真机验证**：重启后存量会话首行工具面 **3 → 8 个**（含 `team_member_invoke / team_phase_invoke /
  team_plan / team_status`），不用重建群。

### 2. 同一件活被派三次
- **现象**：群日志三条几乎一样的派单回执，成员自己回「这是第三次收到同一任务」。
- **根因**：派单幂等签名取任务正文**原文**前 240 字——主理人重派时改个标点、多加半句，签名就变。
- **修法**：签名先归一化（去全部空白与标点）再取前 120 字；回喂文案加
  「同一件活不要重派 / 没有下一阶段就写收口」。

### 3. 真派活后甩「没有实际派活」假回执
- **根因**：核验函数收到的工具调用恒为空（调用处漏传）⇒ 真派活也判"无证据"。
- **修法**：团队工具按次记录 `{时刻, 工具名}`，按回合取真实工具名传入核验；
  查询类工具（`team_status`）不算派活证据。

### 4. 验收结论被吞（上一版修复引入的回归，当轮已修）
- **现象**：成员交回后，主理人核验产物并写了「验收通过 ✅」，群里却没有这条消息。
- **根因**：防重复判据用 `[系统]` 宽前缀当语义标签，把「催办」（要它派活）与「回喂 / 定时任务」
  （正文就是验收结论）混为一类，后者被当成复述不落盘。
- **修法**：判据收窄到两种催办 ask；回喂 / 定时任务一律落群。判据真跑五例（2 催办 / 3 非催办）。

### 5. 伙伴会话透到主侧栏
- **现象**：成员互相 @ 时，外面主侧栏（项目 / 任务 / 分类）出现挂着「调度」标签的伙伴会话。
- **根因**：侧栏隐藏集只收 BOSS 群成员（上一笔修复的口径），工作伙伴群（`grp_*`）成员一个不收。
- **修法**：隐藏集并入主进程群聊台账 `talkThreads.byId`（权威判据，不按标题猜）并订阅其变化；
  过滤仍收在 `visibleEntries` 一处，三视图共用。

### 6. 群聊编排机制沉淀为纯函数
- 借鉴 Cumora / AgentChat / MetaGPT 落地四条机制：① 执行与汇报分离（自报进度必须有真实
  派活或产出证据）② 显式发言权 ③ 宿主判定终止 ④ 编排主体按座位解析——全部离线真跑可测。

## 二、mac 适配审计结论

`node scripts/mac-audit.mjs v0.0.57 HEAD`：**命中 15 条**（win32 5 / darwin 5 / ctrl-key 1 /
backslash 4），逐条判读：

| 分类 | 命中 | 判读 |
|---|---|---|
| `win32` | 5 | 全是守卫断言夹具（acceleratorLabel 真值表传 `"win32"` 当参数） |
| `darwin` | 5 | 断言夹具 + `composer-form.tsx` 的 `isMacPlatform() ? "darwin" : "win32"`——正是平台门控的正确写法 |
| `ctrl-key` | 1 | 守卫夹具；`ctrlKey \|\| metaKey` 是正确跨平台写法 |
| `backslash` | 4 | 3 条守卫正则夹具；`image-src.mjs` / `resolve-image-path.ts` 的 `/^\/[a-zA-Z]:[\\/]/` 是剥 `file:///C:/` 前导斜杠的跨平台兼容逻辑 |
| `winpath` / `powershell` / `appdata` | 0 / 0 / 0 | 无硬编码 Windows 绝对路径、无 PowerShell 依赖、无 APPDATA 直取 |

**结论：逐条判读后，本版新增逻辑无 mac 真缺口。**

## 三、mac 首次打开自救（带路径）

1. 在「下载」里解压 zip；
2. 把 app 拖进「应用程序」；
3. 终端里先输入 `xattr -cr `（注意结尾有空格），**把 app 图标拖进终端自动填路径**，回车；
   例如：`xattr -cr /Applications/Codex\ Harness\ Desktop.app`
4. 若仍提示「已损坏，无法打开」（错误 640），就是上述命令没执行成功，重试第 3 步。

## 五、已知问题

- `tsparticles` 生态 4.5.4 子包仍未发齐，本版继续保留 4.5.3（不影响功能）。
- `electron` 45 / `typescript` 7 的跨大版本升级需另起一轮做 ABI 与真机验证。
- 群聊跨团派活：`team_member_invoke` 执行端按团队 id 硬校验，只能派**本团**成员；
  群里其它团的成员走 `group_say(to=名字)`（同样是真派活，他会动手并把结果发进群）。
- 主理人被催办后仍不派活的极端情况：现在只保证「不重复刷屏」并记失败，没有再上一层强制投递。
