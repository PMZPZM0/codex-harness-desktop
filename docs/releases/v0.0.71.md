# v0.0.71 发版说明

本版主题：**差分缓存的 oldFile 改为我们自己保证** —— 不再依赖「安装器会写 installer.exe」这个假设。

## 一、先给数字：差分到底该下多少

用 electron-updater **官方算法**（`computeOperations`，不是估算）对 0.0.69 → 0.0.70 两份 blockmap 跑了一遍：

```
DOWNLOAD 段 = 528 段，合计 69.71 MB
COPY   段 = 540 段，合计 598.92 MB
整包        = 668.64 MB
实下占整包  = 10.4%
加两份 blockmap ≈ 71.11 MB
```

所以「几十兆」是成立的：**约 71 MB**。你每次拿到 668MB，说明客户端没走成差分，问题不在差分能不能做。

## 二、重做了什么（三件套，闭环）

以前整条链依赖一个假设：安装器会在安装时把安装包写回 `<updater 缓存>/installer.exe`。
这个假设在 0.0.69 之前**从来没被验证过**，一旦不成立，就是「不管怎么选都是完整安装包」。

现在不依赖它了：

| 时机 | 动作 |
|---|---|
| ① 检查更新 / 下载前 | `ensureInstallerCache()`：缓存里没有 `installer.exe`，就去 `pending/` 找**当前已安装版本**的安装包复制过去（手动装过之后包往往还在），并写 `installer.version` |
| ② 下载完成 | `rememberDownloadedInstaller()`：把这次下到的包复制成 `installer.exe` + 记版本 —— 装成功后它就是下一版的 oldFile |
| ③ 启动 / 下载前 | `pruneStaleInstallerCache()`：`installer.version` 与当前版本不符 ⇒ 上次没装成 ⇒ 删掉，避免 next 差分拿错基准导致 sha512 必失败 |

每一步都写进 `%APPDATA%\Codex Harness Desktop\update-install.log`（前缀 `[cache]`），下次能直接看到「oldFile 就绪 / 缺失 / 清理错配」。

⛔ 只动自家 updater 缓存目录，不碰安装目录、不碰用户数据。

## 三、你这一版会遇到什么（说清楚）

- 如果那台机器的 `pending/` 里**还留着 0.0.69 的安装包** ⇒ ①②③ 会立刻把它补成 oldFile ⇒ **这一版就可能只下 ~71MB**；
- 如果那个包已经被清掉 ⇒ 本版仍整包一次，但**下载完会被登记成 oldFile** ⇒ **下一版起稳定几十兆**，不用再折腾。

判断依据（装完本版后看一眼）：

```powershell
Get-ChildItem "$env:LOCALAPPDATA\codex-harness-desktop-updater" -Force |
  Select-Object Name, @{n='MB';e={[math]::Round($_.Length/1MB,1)}}
```

有 `installer.exe`（≈668MB）+ `installer.version` 就说明闭环成立。

## 四、判据

- `npm run build` ✓；`tsc -p electron --noEmit` ✓；
- 守卫 12h / 12e / 06-part05 全绿；`npm run check` 预检通过（5 条既有告警）。

- 本版仍没有 mac 包（CI 默认只构建 Windows）。
- `installer.exe` 是 668MB 的副本，会额外占一份磁盘（可接受；比每次多下 600MB 划算）。
