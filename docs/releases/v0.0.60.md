# v0.0.60 发版说明

本版主题：**修好音色克隆模型下载卡在 53% 的 HTTP 403**（补丁版，只含这一个修复）。

## 一、修了什么

**现象**：设置 → 语音通话 → 音色克隆，下载 ZipVoice 模型（109 MB）到 53% 报「HTTP 403」，之后反复点下载都停在同一位置。

**根因有两条，第二条是修复失效的关键**：

1. **续传请求被镜像拒绝**。下载断流后会按镜像顺序换源，换源后的第一个请求就是带 `Range` 头的续传请求。实测三个源：

   | 源 | 无 Range | 带 Range |
   |---|---|---|
   | GitHub 直连 | 302 | 302（跳转目标本机不可达） |
   | `ghfast.top` | 连不上（000） | **403** |
   | `gh-proxy.com` | 200 | 206（正常） |

   旧顺序把 `ghfast` 放第一位 ⇒ 一旦换源就 403；旧代码把 403 当终态直接失败，`.part` 原样留着，用户每次重试都死在同一个百分比。

2. **`received` 清零的判据少了 `response.ok`**：

   ```ts
   // 旧：任何非 206 响应都当成「服务器不支持续传」
   if (received > 0 && response.status !== 206) received = 0;
   ```

   403 / 5xx 也会命中这一行把 `received` 清零，于是「403 就丢掉半截重下」的分支条件永远不成立——降级逻辑写了也进不去（探针首轮实测 `range_hits=1 / plain_hits=0`，说明压根没走降级）。

**修法**：
- `downloadOnce` 增加 `rangeFallback`：已下过一部分却收到 403 ⇒ 删 `.part`、以无 Range 重来一次（只降级一次，不对真没权限的地址死循环）；
- 清零判据补 `response.ok`；
- 镜像顺序改为 `gh-proxy` 优先、`ghfast` 殿后。

**用户侧**：更新后重新点「下载音色克隆模型」即可，**不需要手工清缓存**——已有的 `.part` 会先尝试续传，被拒则自动丢掉半截从头下。

## 二、mac 适配审计结论

`node scripts/mac-audit.mjs v0.0.59 HEAD`：**命中 0 条**（脚本先跑「正则自证」，证明 0 命中是真 0，不是正则写错）。
本版只改主进程下载逻辑（`electron/voice/model-store.ts` 的 HTTP 响应码判断）与一个守卫文件，不涉及任何平台分支。**无 mac 缺口。**

## 三、mac 首次打开自救（带路径）

1. 在「下载」里解压 zip；
2. 把 app 拖进「应用程序」；
3. 终端里先输入 `xattr -cr `（注意结尾有空格），**把 app 图标拖进终端自动填路径**，回车；
   例如：`xattr -cr /Applications/Codex\ Harness\ Desktop.app`
4. 若仍提示「已损坏，无法打开」（错误 640），就是上述命令没执行成功，重试第 3 步。

## 五、已知问题

1. `ghfast.top` 目前对本机完全不可用（无 Range 连接失败），本版只是把它排到最后、未移除；若长期不可用可考虑整条删除。
2. 同类「镜像对 Range 不友好」的风险也存在于走同一条 `downloadUrlToFile` 的其它资源（如 Kokoro 语音包），本版的 403 降级对它们同样生效，但未逐一实测。
3. `koffi` 仍无预编译二进制（既有状态）⇒ Windows 窗口圆角不生效，其余功能不受影响。
