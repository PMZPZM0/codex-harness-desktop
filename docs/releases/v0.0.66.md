# v0.0.66 发版说明

本版主题：**差分更新验证版** —— 只装两个看得见的修复，用来确认 Windows 更新真的只下变化的几十兆。

> 这一版是特意做「小」的：改动只有一处样式与一处输入框状态修复，安装包与 v0.0.65 几乎没有差别。
> 如果你的 v0.0.65 是**应用内更新**装的，更新到本版时下载总量应该只有几十兆（而不是 600 多兆的整包）。

## 一、修了什么

### 1. 粘贴长文本后，提示语与「粘贴文本」标签叠在一起

- **现象**：粘一段长文本 → 输入框里出现「粘贴文本-…」标签，但占位提示「向 Codex 提问，使用 / 选择命令…」还压在标签左边，打一个字才恢复正常。
- **根因**：占位提示由 `.composer-editor[data-empty="true"]::before` 控制。长文本变成标签是**命令式插 DOM**（`insertComposerAttachments` → `range.insertNode`），插完只回写了 `value`，而回写函数 `syncComposerFromDom()` **不维护 `data-empty`** ⇒ DOM 里已有标签、空态标记却还是 `"true"`。渲染层的 `useLayoutEffect` 本该纠正，但它的前置判断 `domValueRef.current === value` 已被回写函数改成相等，直接 return ⇒ 谁也修不回来，直到下一次真实输入。
- **修法**：回写函数按与真实输入**完全相同**的判据维护 `data-empty`（无文字 + 无图 + 无文件 = 空）；重建路径原来只判 `value` 真值（纯空白串被当成"有内容"），改成同一判据。守卫 `11s` 补两条断言钉住。

### 2. 指挥中枢欢迎页整块发灰

- **现象**：皇冠、标题「指挥中枢」、主句「我和我的小伙伴们都准备好了」、下面轮播的情绪句，全都偏灰。
- **根因**：11-18「图标去彩色」那次把身份色板 `--ic-*` 六色统一改成 `color-mix(in srgb, var(--text) 76%, var(--accent))`（暗色 84%、曜石 80%），等于深灰。而欢迎页标题渐变引 `--ic-amber`、主句是 `color: var(--text)`、胶囊只给 62% 语气色 —— 三处叠起来就是一片黑灰。
- **修法**：**只改欢迎页这一块**，全局色板与「图标中性」的决定保持不动 ——
  - 皇冠 → `--amber`（不再引 `--ic-amber`），不透明度 0.55 → 0.72；
  - 标题 → 三段真色渐变 `--amber → --orange → --purple`，删掉末尾落到 `--text` 的那一段（那正是"看着是黑的"的直接原因）；
  - 主句 → 同一套 `--orange → --amber → --purple` 走 `background-clip:text`。⚠️ 由此父级的 `-webkit-text-fill-color: transparent` 会被子元素继承，后半句会只剩底纹、字看不见 ⇒ `.boss-hero-strong` 显式还原实色；
  - 情绪胶囊 → 文字 62% → 86% 语气色、边框 40% → 52%、底染 8% → 12%；五类语气全部换真色板（「哄老板」的粉 = `--red` 混 `--purple`）。
- **三个主题**都各自有 `--amber / --orange / --purple` 定义，浅色 / 暗色 / 曜石自动跟随，没有硬编码色值。

## 二、mac 适配审计结论

`node scripts/mac-audit.mjs v0.0.65 HEAD`：新增行**命中 0 条**（exe / win32 / darwin / ctrl-key / backslash / winpath / powershell / appdata 八组全为 0）。

本轮改动是渲染层 CSS 与输入框 DOM 状态维护，没有平台判断、没有路径拼接、没有 shell 调用 —— 0 命中是真结论（脚本自带正则自证，避免"正则写错"与"真 0 命中"混淆）。

## 三、mac 首次打开自救（带路径）

1. 在「下载」里双击解压；
2. 把 App 拖进「应用程序」；
3. 首次打开若提示"无法验证开发者"：右键 →「打开」；或把 App 图标拖进终端自动填好路径后执行：
   ```bash
   xattr -dr com.apple.quarantine "/Applications/Codex Harness Desktop.app"
   ```
4. 错误码 640 表示系统仍在隔离态，重复上一步即可。

mac 更新：**每次都是完整包**（无 NSIS blockmap，不是漏做）。

## 五、已知问题

- **差分只在「上一版是应用内更新装的」机器上生效**：NSIS 差分靠成对缓存 `%LOCALAPPDATA%\<name>-updater\` 下的 `installer.exe` ＋ `current.blockmap`。缺任一份 ⇒ 本次仍是整包（会重建配对，下一版起才有差分）。手工装 exe / 第三方下载器装，都不建立配对缓存。
- **mac 无差分**：每次完整包。
- 情绪句轮播 60 秒一条；系统开「减少动态效果」时不自动翻。
