## 一、结论先说

> ⛔ **本节 10-17 修正过一次**。初版诊断说「本地缺入口闸门」——**说重了**。
> 实读 `electron/memory-lessons.ts` 后发现：本地**早就有**清晰区分（`shouldCapture` /
> `buildLessonLine` 只在命中「纠错 / 失败」信号时才产出一条纪律行）⇒ **本地不是"什么都记"**。
> 真正的缺口窄得多，见下表。

| 层面 | 实读现状 | 判断 |
|---|---|---|
| **L4 日志** | `buildLogEntry` **每轮都写**（需求 / 结论 / 失败标记） | ✅ **正确** —— 日志就该是流水 |
| **L2 记忆（自动链）** | `buildLessonLine` 只在 `correction.hit \|\| failure.hit` 时才产出 | ✅ **已经有明显区分** |
| **L2 记忆（直接写入路径）** | `appendLesson(workspace, line, dedupeKey, category)` 的 `dedupeKey` **只去重**；收藏 / 引擎手写 / 记忆工具**绕过了** `buildLessonLine` | ❌ **缺口 ①**（本次已补：`shouldRememberLine`） |
| **云端** | `tdai-proxy` 配 `memory.writeL0: true` ⇒ **每轮对话写 L0**（流水），L1/L2 异步抽取 | ⚠️ **缺口 ②**：L0 全量本身没错（它是流水），但**没有等价于 `buildLessonLine` 的抽取判据**，只有数量上限 `maxMemoriesPerSession: 20` |
| **四类对象边界** | 概念散在代码与注释里，**没有一处成文规范**（尤其"云端优先于本地"） | ❌ **缺口 ③**（本文档补） |
| **淘汰** | L7 有 TTL + 容量 + 分类权重；L4 超预算按天丢最旧 | ✅ 有下游兜底 |

⇒ **真实结论**：不是"什么都记"，而是
**「自动链管住了，手写路径没管住；边界没有成文，云端抽取没有判据」**。
（初版"先全收再靠蒸馏擦屁股"的说法对本地自动链**不成立**，对云端 L0→L1 成立。）

## 二、现状（实读）

### 2.1 八层金字塔（真相源 `electron/memory-layers.ts`）

| 层 | 落点 | 预算 | 谁写 | 满了 |
|---|---|---|---|---|
| L0 | `USER.md`（userData，跨项目） | 4000 | 用户手写 | 人工精简（不自动删） |
| L1 | `project/MEMORY.md` | 12000 | 蒸馏 | 同层压缩 |
| L2 | `lessons/<分类>.md` | 8000 | 捕获链 + 引擎 | 先升级为技能再压缩 |
| L3 | `project/BACKGROUND.md` | 6000 | 用户/引擎 | 稳定项升格进 L1 |
| L4 | `logs/YYYY-MM-DD.md` | 40000（8000/天 × 回灌 5 天） | **捕获链自动** | 沉 L5 |
| L5 | `rollup/YYYY-MM.md` | 12000 | 蒸馏 | 沉 L1 |
| L6 | `archive/*.md` | — | 蒸馏（移动） | 终态，不进注入 |
| L7 | `memory.json` | — | **捕获链自动** | TTL 淘汰 → `pruned.jsonl` |

注入顺序：**① L2 纪律 ② L0 ③ L1 ④ L3 ⑤ L4（最后，超预算按天从最旧丢）**。

### 2.2 四类分类（`electron/memory-lessons.ts` 实读）

```
用户纠错（corrections，注入最前、永不淘汰） > 任务经验（坑） > 工作流/SOP > 用户偏好
```
分类是**有的**，注入顺序也是**按价值排的**。缺的是「一条内容该不该进这个体系」。

### 2.3 云端记忆（本轮接通后）

`memory: { capture: {enabled:true}, extraction: {enabled:true, maxMemoriesPerSession: 20},
pipeline: { everyNConversations: 5, l1IdleTimeoutSeconds: 600, l2Min/MaxIntervalSeconds: 900/3600 },
recall: { enabled: true, maxResults: 5, scoreThreshold: 0.3, strategy: hybrid } }`

它自己的分层（L0 原始 → L1 抽取 → L2/L3 沉淀）**与本地金字塔同构**，但：
**L0 是无条件写入的**（`writeL0: true`）⇒ 云端目前就是"流水账"，只是它有 `scoreThreshold: 0.3` 在**召回**端把关。

## 三、重设计：日志与记忆的边界

### 3.1 一句话判据

> **日志记「发生了什么」，记忆记「下次该怎么做」。**
> 一条内容如果**不能改变未来的行为**，它就只是日志，不该进记忆。

| | 日志 | 记忆 |
|---|---|---|
| 回答的问题 | 发生了什么 | 下次怎么做 |
| 形态 | 时间序流水 | 无时间序的纪律 |
| 例子 | "10:32 改了 cloud-provider 的 baseUrl 解析" | "⛔ 上游地址只许一个决策点，两处各写会互相覆盖" |
| 淘汰 | 按天丢最旧（L4→L5→L6） | 按价值长期留存（纠错**永不淘汰**） |
| 谁看 | 复盘时查 | **每轮都注入** |
| 成本 | 便宜（不注入） | 贵（吃预算、干扰注意力） |

### 3.2 写入闸门（**新增**，四问全过才写）

写入前必须能回答「**是**」的问题，任一为「否」就不写：

1. **未来还会遇到吗？**（一次性事件 → 日志，不写记忆）
2. **不知道这条会不会犯错？**（知道了也只是"哦" → 不写）
3. **能写成一句可执行的约束吗？**（写不成句 → 说明还没想清，写日志里待蒸馏）
4. **现在不记，下次能自己推出来吗？**（能推出来 → 不写）

**明令不写**（对应你担心的流水账）：

- ❌ 进度播报、耗时、token 数、命令回显
- ❌ 代码能表达的东西（函数签名、目录结构、配置项取值）
- ❌ 一次性的排查过程（**过程进日志**，只把结论写记忆）
- ❌ 临时路径、临时 ID、本次会话的中间产物
- ❌ 已经有技能承载的流程（**记忆记「是什么」，技能记「怎么做」**；同现象出现第二次 ⇒ 升级成技能）
- ❌ 重复：同一条已存在（按 `dedupeKey` + 语义）⇒ 不写，改为**强化计数**或升级措辞

### 3.3 四个分类的写入口径

| 分类 | 收什么 | 不收什么 | 淘汰 |
|---|---|---|---|
| **用户纠错** | 用户明确纠正我的**理解/做法** | 用户随口改需求（那是需求变更） | **永不淘汰** |
| **任务经验（坑）** | 踩过、且**下次会再踩**的坑（含判据） | 一次性的环境故障 | TTL |
| **工作流/SOP** | 本项目**稳定的做法**（谁在什么时机做什么） | 通用最佳实践（那是模型常识） | TTL |
| **用户偏好** | **本项目**的口味 | 跨项目偏好（走 L0 USER.md） | TTL |

## 四、四类对象的边界（记什么 / 存什么 / 何时更新 / 优先级）

| | **本地记忆** | **云端记忆** | **本地知识库** | **云端知识库** |
|---|---|---|---|---|
| **记什么** | 本机工作方式、项目纪律、用户纠错 | **同一批账号上下文**，跨设备延续 | 项目内可检索的**资料** | 用户上传/沉淀的**云端资料** |
| **存什么（形态）** | L1/L2/L3/L7 文本 + `memory.json` | Memory Hub：`chc-<账号>` 的 L0–L3 | 工作区文件 + 检索索引 | WeKnora 库 `u-<账号>` + 只读 MCP 端点 |
| **归属** | 这台机器 / 这个项目 | **这个云账号**（跨设备） | 这个项目（随仓库走） | 这个账号（跨项目、跨设备） |
| **更新时机** | 每轮捕获 → 蒸馏 → 分层 | 对话即写 L0，每 5 轮抽 L1 | 手工放入 / 抓取 | 用户上传 / 勾选同步 |
| **注入方式** | 常驻四层（L2/L0/L1/L3）+ L4 尾段 | 由 `memapi` 在**请求层**注入 | 模型按需检索（工具） | 模型按需检索（MCP 工具） |
| **容量** | 90000 字符（四层 60000 + 日志 30000） | 由 Memory Hub 管（服务端配额） | 磁盘 | `quotaMb`（默认 1 GB）+ 次数 |
| **优先级** | 低 | **高（与知识库同时生效时，云端优先于本地）** | 低 | 高 |
| **失败时** | 降级到内置金字塔 | 回退纯模型端点（已实现） | 报错 | 报错 |

### 4.1 优先级规则（**新增，需写进注入与工具语义**）

```
① 云端记忆  >  ② 本地记忆        ← 同一事实两边都有 ⇒ 以云端为准（它是跨设备的最新口径）
① 云端知识库 > ② 本地知识库      ← 同一文档两处都有 ⇒ 以云端为准
云端记忆 / 云端知识库 之间不设优先级（一个是"怎么做"、一个是"资料"）
```

**冲突处理**：若云端某条与本机实测**直接冲突**（例：云端说 API 是 A，本机实测是 B），
⇒ **以实测为准，且必须立即写一条「用户纠错」到本地 L2**，把冲突显式留痕。
⛔ 覆盖是**按条目**的，不是"整份以云端为准"——那会让本机实测结论被远端旧值盖掉。

## 五、金字塔 ↔ 云端分层的映射

| 本地 | 云端 | 语义 |
|---|---|---|
| L0 USER.md | —（云端无跨项目层） | 云端按账号，不按项目 |
| L1 MEMORY.md | L2（抽取后的记忆） | 稳定事实 |
| L2 lessons/ | L1（抽取）+ L2 | 纪律与纠错 |
| L3 BACKGROUND | — | 项目背景（云端不承载） |
| **L4 logs/** | **L0（原始）** | **流水，双方都不进注入的"记忆"位** |
| L5 rollup / L6 archive | — | 本地归档 |
| L7 memory.json | —（云端自己做 TTL） | 会话级临时记忆 |
| — | L3 | 云端独有：persona/scenes |

⛔ **关键对齐**：**云端的 L0 与本地 L4 是同一个东西（流水）**。
现在云端 `writeL0: true` 没问题——**问题是没有等价于"L4 不进记忆注入位"的显式约定**，
导致「L0 写了 = 记住了」的错觉。**规范要在文档与技能里把这条写死。**

## 六、配套工具：更新与新增

### 6.1 需要**更新**的

| 对象 | 改什么 | 判据 |
|---|---|---|
| `electron/memory-lessons.ts` | 加**写入闸门**纯函数 `shouldRemember(text)`（四问合成的启发式 + 黑名单） | 预检【97】跑真值表：进度播报/回显/路径 ⇒ false；纠错/坑 ⇒ true |
| `MemoryLayers.appendLesson` | 落盘前过闸门；被拒时**记一条日志**说明为什么拒（可审计，⛔ 不静默吞） | 守卫：闸门被调用 |
| 云端写入 | 由 `tdai-proxy` 侧 `writeL0` 保留（它是流水，正确），但**召回端**要显式声明 L0 不外泄 | 文档 + 技能 |
| 记忆注入 | 注入头加一行「**四类优先级**」摘要（云端记忆优先于本地） | 守卫：注入串含优先级行 |
| `docs/MEMORY-LAYERS.md` | 补「日志 vs 记忆」判据 + 四类对象边界表 | 人工 |

### 6.2 需要**新增**的

| 对象 | 作用 | 为什么需要 |
|---|---|---|
| 内置技能 `记忆写入规范` | 让 **Codex 每轮都按判据决定记不记**（含四问 + 黑名单 + 四类口径） | ⛔ **机制要生效，必须进引擎的指令面**，光有代码闸门不够 |
| `AGENTS.md` 一段「记忆纪律」 | 项目入口就声明「日志≠记忆」与会话收尾动作 | 引擎进项目即读 |
| 守卫【新】`memory-gate` | 断言闸门存在 + 黑名单样例被拒 + 真值表 | 防回潮 |
| 守卫【新】`memory-boundary` | 断言四类对象边界文档存在且含优先级规则 | 防文档漂移 |
| 元技能 `memory-audit`（可选） | 定期扫 `lessons/`，把流水账条目揪出来降级到 logs | 存量清理 |

### 6.3 让 Codex「完整掌握并熟练执行」的三层

1. **代码闸门**（`shouldRemember`）——⛔ 最后一道，不是第一道
2. **指令面**：内置技能 `记忆写入规范`（每轮可见）+ `AGENTS.md` 摘要段
3. **收尾动作**：每轮结束时明确分流——「过程 → 日志」「结论 → 记忆」「可复用流程 → 技能」

⛔ **一条纪律**：**同现象第二次出现 ⇒ 升级成技能**（已有出边 L2→技能库），
不要第三次又写一条记忆——那正是"越记越乱"的起点。

## 七、落地顺序（建议）

1. `shouldRemember()` 纯函数 + 真值表（**先有判据**）
2. 接进 `appendLesson`（**闸门生效**）+ 拒绝原因写日志
3. 内置技能 `记忆写入规范` + `AGENTS.md` 段（**让引擎知道**）
4. 两个守卫（**防回潮**）
5. 存量审计：扫一遍现有 `lessons/` 与 `MEMORY.md`，把流水账降到 logs

⛔ 第 5 步别省：**判据只挡新增，存量要靠审计**——否则"越记越乱"的历史负担还在。
