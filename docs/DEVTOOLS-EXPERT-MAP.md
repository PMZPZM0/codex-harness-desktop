# 开发工具 ↔ 专家：四个大类（2026-11-18 定稿）

> 用户 11-18 两次定调：① 「以后往里面加东西，都要配套联动已有或者新建专家；专家要技能齐全、专业工具齐全」；
> ② 「分的太细了，大类就行」。
>
> ⇒ 工具按**四个大类**归口，每类对应一位专家；新增工具先归大类，不新增第 N 位专家。
> 代码里的同款表在 `src/features/settings-devtools/DevtoolsSettingsSection.tsx` 文件头，两边同步。

## 一、四个大类

| 大类 | 覆盖的工具/卡片 | 专家 | 状态 |
|---|---|---|---|
| **A · 开发与环境** | 基础运行时 · 开发工具链（Git/PS7/Miniconda/MinGW）· 系统级安装（Docker/OpenSSL）· 工具自检 · 当前能力链路 · Laya | **筑基**（新建） | 待建 |
| **B · 自动化与设备** | 桌面与浏览器自动化（Nuphus / ponytail / Ego Lite）· 手机控制 · ApkStart · Husk | **掌控**（新建） | 待建 |
| **C · 办公与文档** | 飞书 CLI · Filee · markitdown · 知识库语义检索（kb-embedding）· 精选技能包 | **通译**（新建） | 待建 |
| **D · 创作与媒体** | FFmpeg · Craft 全家桶 · OpenFilm · MoeKoe · OpenMAIC | 剪承团（视频）· 画意（生图）· 呈象（演示）· 文枢团（内容）+ **造物**（视觉体系，新建） | 部分已有 |
| （E）· 逆向 | REA | 洞见（已有） | 已联动 |

**结论**：开发工具 22 项 → **4 个大类**；需要新建 **4 位专家**（筑基 / 掌控 / 通译 / 造物），
其余由已有专家覆盖。

## 二、四位新专家的清单（技能 + 工具 + 第一任务）

### A · 筑基（开发与环境）
- **工具**：`bundled-tool`（Git/Node/Python/MinGW）、`engine`；诊断面板（工具自检 / 能力链路 / Laya）
- **技能**：`codex-engine-config-probe`（版本与配置探测）、环境诊断、依赖修复
- **第一任务**：「把这台机器的开发环境体检一遍：缺什么、怎么装，给可直接执行的命令」

### B · 掌控（自动化与设备）
- **工具**：`computer-use`、`nuphus`、Ego Lite、`phone-harness`、ApkStart、Husk
- **技能**：`ego-browser`、`computer-use-acceptance`、adb 截图、侧载流程
- **第一任务**：「在浏览器里把这件事走通（打开→操作→截图），并把每一步耗时报给我」

### C · 通译（办公与文档）
- **工具**：飞书 CLI（`@larksuite/cli`）、Filee、`markitdown`、`kb-embedding`
- **技能**：`lark-im` / `lark-doc` / `lark-sheets` / `lark-calendar` / `lark-task` / `lark-approval`、文档转换、知识库构建
- **第一任务**：「把这批文档转成 Markdown 建库，并把待办同步到飞书任务与日历」

### D · 造物（视觉体系）
- **工具**：Craft 全家桶（19 App）、`image-lab`、FFmpeg
- **技能**：`frontend-ui-design`、`buddy-image-processing`
- **第一任务**：「按这个品牌词做 3 套视觉方向 + 落地页首屏」
- **分工**：画意 = 电商单品主图；造物 = 品牌/版式/动效体系；剪承 = 视频成片

## 三、落地顺序

1. **筑基**（覆盖最高频的"装了不会用"：环境 + 自检 + 能力链路）
2. **通译**（办公侧日常刚需，且 `lark-*` 技能已齐）
3. **掌控**（桌面/手机自动化）
4. **造物**（视觉体系，与画意/剪承分工需先对齐）

每建一位，必须同时做三件（缺一不算完成）：
- `expert-teams.json` 写入专家（岗位 + 技能 + 工具）；
- 专家卡显示「已具备 N 工具 / M 技能」，缺的可一键安装；
- 对应工具卡加「交给 X 专家」按钮（开会话 + 预填第一任务）。

## 四、结构性前提（还没做）

专家数据里目前**没有 `tools[]` / `skills[]` 字段** ⇒ "技能齐全、工具齐全"无从校验。
第一步要先把这两个字段加进专家定义，并在专家卡上呈现"齐/缺"，否则上面四位专家只是文案。
