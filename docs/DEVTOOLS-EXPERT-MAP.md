# 开发工具 ↔ 专家：五个大类（2026-11-18 定稿）

> 用户口径三次收敛：① 「以后加东西都要配套联动已有或新建专家，专家要技能齐全、工具齐全」；
> ② 「分的太细了，大类就行」；③ 「自媒体还要联动自媒体工作台，深度联动」。
>
> ⇒ 工具按**五个大类**归口，每类一位专家；自媒体工作台属于 **D**，且要求**深度**联动（不是"能装"）。
> 代码同款表在 `src/features/settings-devtools/DevtoolsSettingsSection.tsx` 文件头，两边同步。

## 二、自媒体工作台：要"深度"联动（用户点名）

### 现状（已连上的部分）

- `media_desk` 工具已存在，能力覆盖整条链：`state`（看板）· `capture`（采集）· `draft`（成稿）·
  `produce`（生产）· `schedule`（排期）· `metric`（数据）· `insights`（复盘）· `style`（风格）·
  `delete` / `undo`；
- 专家在群聊派活时读写的是**同一份** `state.json`（`<userData>/media-desk-host/media-desk/`），
  不是复制一份数据 —— 这点是对的，别改。

### 四条缺口（这就是"不深度"的地方）

| # | 缺口 | 后果 |
|---|---|---|
| ① | 工作台排期（上游 `schedule_item`）与系统排期（`scheduler-ipc`）**不互通** | 用户以为"排了就会发"，到点什么都不发生 |
| ② | 成稿后没有出口：不能「交群评审」、不能「派剪承团做视频」、不能「按设计参考改视觉」 | 稿子写完就断在界面里 |
| ③ | `metric` / `insights` 不喂给观澜团、不回写下一轮选题 | 复盘数据只是数字，不产生下一轮 |
| ④ | 界面里没有专家入口（只有 Codex 工具能调） | 用户不知道"这件事该找谁" |

### 深度联动要做的四件事

1. **排期合一**：工作台 `schedule` 落一条系统排期（带 `source: "media-desk"`），到点由调度器开跑并回写状态；
2. **成稿出口三连**（工作台详情页底部一行按钮）：
   - 「交群评审」→ 选一个群，把稿子作为产物卡发进群（走 `team-run` 投群流）；
   - 「做视频」→ 派给剪承团（预填：把这篇稿子拆成分镜）；
   - 「按设计参考改」→ 打开设计参考库，选中风格后回到工作台写入 `style`；
3. **复盘回流**：`insights` 一键「让观澜团看看」→ 出 3 条下一轮选题建议 → 直接写回台历；
4. **专家入口**：工作台顶部一句「这件事可以找：文枢团 / 剪承团 / 知微」，点开即开会话并带上下文。

**判据**：一条稿子从「成稿」到「排期」到「到点自动跑」到「复盘出选题」全程**不离开应用、不手工搬数据**。

## 三、前端与设计：三处要通，但别塞

现状（11-18 检查）：设计参考库（84 份 DESIGN.md，工具 `design_md`）、前端开发画布（`ui-sketch`，
工具 `frontend_get_doc` / `frontend_apply_doc`）、组件库（皮肤/组件复制）——**三处互不相通**，
而且都没有专家入口（画布只有「交给 Codex」）。

要点：

- **设计库 → 画布**：「用这套风格开始画」→ 把 DESIGN.md 的色彩/字号/圆角写进画布初始 spec；
- **画布 → 组件库**：「把选中的卡片存成组件」→ 落条目，附来源与截图；
- **组件库 → 画布**：「用这个组件」→ 以插入片段的方式带过去（⛔ 不是把组件库面板塞进画布）；
- **专家**：执矩团（问俗/明断/织流/造境）负责评审与推进，造物负责视觉方向。

⛔ **禁忌**：画布内**不许**再嵌组件库面板（用户 11-15 已否："跟左边那些不适配，加进来没啥用"）。
联动一律「跳出去 / 带过去」。

## 五、落地顺序

1. **先给专家加 `tools[]` / `skills[]` 字段** + 专家卡显示"齐/缺"（前提，否则全是文案）；
2. **筑基**（A：环境 + 自检 + 排期 + 产物 + 任务监控，一次覆盖 5 处无主）；
3. **自媒体深度联动**（D：排期合一 + 三条出口 + 复盘回流）——用户点名，收益最直观；
4. **前端三处互通**（E：设计库 ↔ 画布 ↔ 组件库）；
5. 掌控（B）、通译（C）、造物（D/E 的视觉体系）。

每步都带判据；⛔ 缺口只允许变少（本表条目数只减不增）。
