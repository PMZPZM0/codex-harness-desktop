# 功能联动方案（2026-11-17）

> 背景：用户反馈「功能太分散，关联性不强，前端也没有引导和提示」。
> 本文 = 抽检结论 + 五条联动主轴 + 引导体系 + 实施顺序。**光扫不改代码**。

## 一、抽检结论（可复核的事实）

| 项 | 实测 | 判据 |
|---|---|---|
| 渲染层功能目录 | **100 个**（`src/features/*`） | `ls src/features \| wc -l` |
| 主进程功能域 | **156 个**（`electron/features`） | 同上 |

| 功能 | 现状 | 证据 |

## 二、五条联动主轴

设计原则（沿用项目既有纪律）：**不新增全局 store**、**新能力独立成板块**、**联动走「数据已有的那一份」而不是复制一份**（前几轮反复踩：两处各算一份必然漂）。

### 主轴 1 · 会话即总线（P0）

**现状**：会话里产出的图/文档/代码，用户要自己找路径；产物档案（`artifact-archive`）与导入记录（`import-records`）各是一个孤立页面。

**联动**：
1. 回合结束自动把产出登记进产物档案（现在依赖模型显式调工具）；
2. 会话内的文件卡加两个按钮：**「归档到产物库」**、**「在文件管理器中定位」**（`artifact:add` / `fs:locate` 已有通道）；
3. 产物档案里每行加 **「回到原会话」**（`openThread(threadId)` 已有）。

**判据**：新会话产出 1 个文件 → 产物档案 10 秒内出现该条 → 点「回到原会话」能跳回并定位到那条消息。

### 主轴 2 · 记忆贯穿（P0）

**现状**：知识库/记忆只靠模型主动调工具才用上；用户在界面上看不到"这次回答用了哪条记忆"。

**联动**：
1. 会话头部加一枚**记忆命中徽标**：本轮注入了几条偏好/纠错/知识库片段，点开看具体条目（`memory_write` / 知识库检索已有事件）；
2. 记忆中心（`memory`）每条加 **「用这条记忆开个会话」**；
3. 知识库检索结果卡片加 **「存入长期记忆」**。

**判据**：命中徽标数字 = 注入条数（主进程返回什么就显示什么，⛔ 不许前端自己估）。

### 主轴 3 · 任务—排期—触发同轴（P1）

**现状**：任务监控（`task-monitor`）、自动化（`settings-automation`）、排期（`settings-schedule`）、`polling` / `relay` 各自为政，用户不知道"这个任务为什么会自己跑"。

**联动**：
1. 任务卡显示**触发来源**：手动 / 排期（哪条规则） / 群聊派活 / 子智能体；
2. 排期条目加 **「看最近一次运行」**（跳任务监控并过滤）；
3. `polling` 的后台胶囊接进任务监控（现在无入口），并允许「以后都别再提示」写入排期规则。

**判据**：任一自动运行的任务，卡片上能看到触发它的规则 id。

### 主轴 4 · 群聊 / 专家团 ↔ 产物 ↔ 办公室（P1）

**现状**：群聊能派活、办公室能看谁在忙，但**成员产出的东西落在各自的会话里**，群里只有一段文字。

**联动**：
1. 成员交回时，若产出里有文件 → 群消息里带**产物卡**（复用会话里的卡组件，⛔ 不新写一套）；
2. 办公室点角色 → 打开的会话里带「只看本轮产出」筛选；
3. 群资料卡加 **「本群产物」** 一栏（按 group 过滤产物档案）。

**判据**：群内一条消息能点开产物并回到产出它的会话。

### 主轴 5 · 内容生产链收口成「产物中心」（P2）

**现状**：`image-lab` / `media` / `media-desk` / `drama-canvas` / `ui-sketch` / `graph` 六处都能出产物，但**没有一个统一的"我的东西在哪"**。

**联动**：把「产物中心」作为独立板块（`artifact-hub`）：
- 左侧按来源分栏（会话 / 画布 / 工作台 / 图像实验室）；
- 统一操作：预览、定位、归档、**「用 X 继续改」**（image-lab 重新打开、drama-canvas 续写、ui-sketch 再生成）；
- 各域只负责**登记**（一条 `artifact:add` 带 `source` 字段），⛔ 不再各自造列表页。

**判据**：任一来源新产出 1 件 → 产物中心 3 秒内出现，且「继续改」能回到对应工具并带上源 id。

## 三、引导与提示体系（三层，按出现时机）

| 层 | 位置 | 内容 | 现状 |
|---|---|---|---|
| ① 首次 | 新建会话空态 | 三个"一键开始"卡：写代码 / 做内容 / 建群派活；各卡点开即预填 prompt | 空态有 221 处文案，但**没有一条带动作按钮** |
| ② 上下游 | 每个功能页的空态 | 说明「这一步的输入从哪来」「产出给谁用」+ 一跳直达 | 27 处跳转文案，**全部散落、无统一组件** |
| ③ 傍身 | 会话内 | 记忆命中徽标 / 技能使用中 / 产物已归档 三个轻提示 | 技能已有（`skill-usage`），其余没有 |

实现口径：新增一个共享组件 `features/shared/EmptyState`（标题 + 一句解释 + 主按钮 + 可选次按钮），**所有空态改用它**——⛔ 不许每个页面再手写一套 div。

## 四、实施顺序

**P0（先做这三件，一周内可验收）**
1. 空态组件统一（`EmptyState`）+ 首批 8 个高频页接上（会话空态、产物档案、知识库、任务监控、群聊、产物卡、画布、技能市场）
2. 会话 ↔ 产物双向跳转（主轴 1 的第 2、3 条）
3. 记忆命中徽标（主轴 2 的第 1 条）

**P1**
4. 任务触发来源 + 排期互跳（主轴 3）
5. 群内产物卡 + 群资料卡「本群产物」（主轴 4）
6. 四处未接线点的处置：`polling` 接任务监控、`event-broadcast` 接回合播报、`memory-ui` 接记忆页、`graph` 明确「删还是接」

**P2**
7. 产物中心（主轴 5）
8. 「用 X 继续改」的跨工具续作

## 五、风险与不做的事

- ⛔ **不新增全局 store**：联动靠已存在的数据（产物档案 / 记忆 / 任务表）+ 事件，不引入第二份状态（项目纪律，历史上两处各算一份必漂）。
- ⛔ **不把联动逻辑塞进既有域**：需要新列表/新入口的一律独立板块（如 `artifact-hub`）。
- ⛔ **不做"聪明自动"**：自动归档、自动召回都要**可见、可关、可回退**，并在守卫里钉住开关。
- ⚠️ 未接线那四处**先判后动**：`graph` 若确认是半成品，删掉比接线更诚实（少一个"看起来有但用不了"的功能）。

## 六、判据怎么写进守卫（防回归）

- 空态统一：`grep` 全仓不得再出现自己拼的 `className="*-empty"`（棘轮：现状 N 处只减不增）。
- 双向跳转：产物行必须含 `openThread` 调用点断言；会话文件卡必须含 `artifact:add` 通道断言。
- 记忆徽标：徽标数字必须来自主进程返回的 `injectedCount`，⛔ 负向断言禁止前端自己 `filter` 计算。
- 触发来源：任务卡必须渲染 `trigger` 字段；排期 id 必须可点。
