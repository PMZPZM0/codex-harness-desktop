> 用途：对照 `docs/IMAGE-LAB.md` / `docs/IMAGE-TOOL-SPLIT.md` 的实现做**人工验收**。
> 下面每条都是**可以直接粘进 Codex 会话**的原话，附「预期现象」与判据。
>
> 对应提交：`fdfa7c4`（工具独立 + IPC 拆分）；守卫：`scripts/guards/12b-image-lab.mjs`（23 条）。
> ⛔ **测试顺序是有讲究的**：A 组（编辑族）**零配置、立刻能跑**；B 组（生图）要先配密钥。

## 0 验收前置

### ① 构建（已由本轮改动的作者跑过，重启应用即可）

本轮改了**渲染层与主进程**，你的实例跑 `dist`：

```bash
export CODEBUDDY_SAFE_DELETE_ENABLED=0
npm run build        # 已执行：build:electron + build:vite 均通过
```

判据：账号菜单 →「检查更新」页的**构建指纹**是今天的新值。⛔ 别用"我的实例应该是最新的"推断。

### ② 新建会话（或对老会话 resume 一次）

工具面只在 `thread/start` / `thread/resume` 注册。

**判据（先问这一句）**：

> 你现在有哪些图像相关工具？它们是独立的工具，还是某个工具的参数？

**预期**：回答里出现 **四个独立工具名** `image_generate` / `image_edit` / `image_info` / `image_view`，
并说明它们是**各自独立的工具**（不是 `harness_tools` 的参数）。若模型说"要通过 harness_tools 调"，
说明工具面是旧的（老会话没 resume 或没构建）。

## A 组 · 零配置（先测这组，不需要任何密钥）

> 这组只用 `image_edit` / `image_info` / `image_view`，**本地 jimp，零凭证**。
> 先准备一张图：随手把任意 png/jpg 丢进**当前会话工作目录**；或者直接跳过，用下面 A0 让 Codex 自己造。

### A0 · 先证明"没配生图也能干活"

> 用 image_info 看一下当前工作目录里有哪些图片文件，挑一张报出它的尺寸、格式、有没有透明通道。

**预期**：报出真实数据（如 `.../test.png：1024×1024，png，xxKB`），**不弹浮层**（这是纯读取）。
若这里就报"生图插件未配置"——那是 bug（编辑族不该读插件凭证）。

### A1 · 几何（crop → resize → rotate）

> 把工作目录里的 `<文件名>` 先裁剪 512x512（从左上角），再缩放到宽 800，最后顺时针转 90 度，另存为新文件。

**预期**：浮层**先亮源图**（让你看清改的是哪张）→ 换成产物 → **约 1 秒后自动收起**。
返回 `已编辑 1 张，产出：<路径>（800×512，png，xxKB）`。**原图仍在、未被覆盖**。

### A2 · 色调

> 把 `<文件名>` 调亮一点、对比度加一点，然后自动色阶，另存。

**预期**：产物肉眼比原图亮、层次更分明。覆盖 `brightness` / `contrast` / `normalize`。

### A3 · 风格化四连

> 把 `<文件名>` 分别做成四个版本：灰度、棕褐色、反相、四色阶海报，文件名带后缀区分。

**预期**：四个文件，风格各异。覆盖 `greyscale` / `sepia` / `invert` / `posterize`。

### A4 · 马赛克 / 模糊

> 把 `<文件名>` 打上马赛克（块大小 12）另存；再出一版高斯模糊（半径 8）。

**预期**：马赛克版能看出方块；模糊版整体虚化。覆盖 `pixelate` / `gaussian`。

### A5 · 翻转 / 透明 / 格式

> 把 `<文件名>` 水平翻转、整体透明度设成 50%，输出 png；再转一版 jpeg、质量 60。

**预期**：翻转+半透明版（用 image_info 复查应显示"带透明通道"）；jpeg 版体积明显小于原 png。
覆盖 `flip` / `opacity` / `format` / `quality`。

### A6 · 叠加 + 文字

> 把工作目录里两张图叠一下：把第二张缩到 10% 当水印贴到第一张右下角，再在左上角写一行英文 `SAMPLE`。

**预期**：右下有小水印、左上有 `SAMPLE`。覆盖 `resize`(造水印) / `composite` / `text`。
⛔ 已知限制：`text` **只支持英文数字**，写中文会是空白（见 D6）。

### A7 · 批量

> 把工作目录里所有 png 都缩到 512 宽，各自另存。

**预期**：一次调用处理多张（`paths` 数组），返回「已编辑 N 张」并逐行列路径。

### A8 · 预览浮层（人看，不自动收）

> 用 image_view 打开刚才那张图给我看看。

**预期**：浮层弹出显示该图，**停住不自动关** —— 故意等 10 秒，仍在 = 通过。

## B 组 · 生图（需要密钥，配好再测）

### B0 · 先配密钥（一次性）

1. 打开中转站后台（如 `api.pptoken.cc`）→ **令牌** 页 → 新建一个 `sk-` 开头的 API Key。
   ⛔ 登录态的 token 不能当 Key（实测返回 `401 INVALID_API_KEY`）。
2. 应用内：**设置 → 插件 → 内置插件 → 「生图插件」卡**，填三格：
   **API 地址**（`https://api.pptoken.cc`）、**密钥**（`sk-…`）、**模型**（`gpt-image-1` / `dall-e-3` 之类，按该站文档），保存。

### B1 · 基础生图

> 用 image_generate 画一只戴墨镜的柴犬，1024x1024。

**预期**：浮层弹出（生成中）→ 换成产物 → **自动收起**；返回「已生成 1/1 张：」+ 一个**本地路径**。
若报「生图插件还没配置：到「设置 → 插件 → 内置插件」填 API 地址、密钥与模型」—— 说明 B0 没做完。

### B2 · 多张并发

> 用 image_generate 画一只橘猫坐在窗台上，要 3 张不同构图的。

**预期**：一次返回 3 个本地路径（并发生成）。

### B3 · 复核生图与修图互不影响

> 把系统里的生图插件配置清空（或临时改错密钥），然后：先让我看看工作目录里的 `<文件名>`，再把它缩到 400 宽。

**预期**：**两件事都照常成功** —— 这证明 `image_edit` / `image_info` / `image_view` 完全不吃生图凭证。

## C 组 · 交互流程（本轮新增：小改动先问）

### C1 · 应当触发询问

> （先跑 B1 生成一张图，接着）把它的墨镜改成红色。

**预期**：Codex **先弹出选项卡**问「修图（保留这张，只改局部）」/「重新生成」，**不直接动手**。

### C2 · 不应当询问（明确指令）

> 把刚才那张图裁成正方形的。

**预期**：**直接**调 `image_edit`（`crop`），不提问。

> 重新生成一张，换成一只猫。

**预期**：**直接**调 `image_generate`，不提问。

### C3 · 语义改动应被挡回

> 把它的墨镜改成红色 —— 直接用修图做，别重新生成。

**预期**：说明**这属于语义修改、修图做不到**（会换主体/内容），建议重画；⛔ **不能**硬拼 ops 后报"改好了"。

## D 组 · 负向边界（"能正常运行"的真正判据）

> 期望失败。只要不崩、不静默通过，就算对。

| 编号 | 提示词 | 预期结果 |
|---|---|---|
| D1 | 用 image_edit 处理 `<文件名>`，`ops` 里塞一个 `{"op":"hue-shift"}` | 明确报错「不认识的编辑操作：hue-shift」——⛔ **绝不静默跳过** |
| D2 | 用 image_edit 处理 `C:\Windows\notepad.exe` | 拒绝（不在可信目录 / 扩展名不在白名单） |
| D3 | 用 image_edit 处理桌面上的一个 `.txt` | 拒绝（非图片扩展名） |
| D4 | 用 image_info 读 `D:\no-such-file.png` | 报错「文件不存在」类文案，不崩 |
| D5 | 用 image_edit 把图 resize 到 `width: 999999` | 报错**或**产出但不卡死（卡死才算失败） |
| D6 | 用 image_edit 在图上写中文 `测试` | 能正常产出（该处空白）；⛔ **不能报错、不能崩** —— 已声明的限制 |

**D1/D2 是最关键的**：这正是守卫 `12b-image-lab.mjs` 做过变异测试的两处（去掉"未知 op 报错"、
去掉路径闸都会被抓红）。

## E 组 · 浮层协议

| 编号 | 操作 | 预期 |
|---|---|---|
| E1 | `image_generate` | 弹（生成中）→ 换产物 → **约 1 秒后自动收起** |
| E2 | `image_edit` | **先亮源图** → 换产物 → 自动收起 |
| E3 | `image_view` | 弹出后**不自动收**，等你自己关 |
| E4 | 故意让 `image_edit` 失败（跑 D1） | 浮层显示**错误态**再收起；应用不崩、会话能继续 |
| E5 | 编辑过程中连点关闭 | 能正常关，不残留半个浮层 |

判据：E1/E2 的"自动收起"要**看得出短暂停留**（约 900ms），不能"啪一下没了"。

## 失败了怎么定位

| 症状 | 先查这里 |
|---|---|
| 工具名根本调不出来 | 没 build / 老会话没 resume（§0①②） |
| 模型说"要通过 harness_tools 调 image_edit" | 工具面是旧的 ⇒ resume 或新建会话 |
| 编辑族也报"生图插件未配置" | **是 bug** —— 四条通道应各自独立（`image-lab:edit` 不读插件）；跑 `node scripts/guards/12b-image-lab.mjs` 应 23/23 |
| 编辑报 `Cannot find module 'jimp'` | 依赖没装 / 打包漏了 jimp（`npm i jimp@^1.6.1`） |
| 报 `Unsupported MIME type: undefined` | 输出格式推导异常，查 `image-lab.ts` 的 `EXT_TO_FORMAT` |
| 浮层不弹 / 不关 | 渲染层 `ImageLabBridge` 是否挂在 `AppView`；`image-lab:event` 推送是否发出 |
| 中文文字是空白 | **不是 bug**，jimp 内置位图字体仅 ASCII（已记入 `docs/IMAGE-LAB.md` 已知限制） |
| 该问却没问（C1） | 常驻规则在 `electron/developer-instructions.ts` 第 4 条；工具描述在 `part08/01-seg.tsx` 的 `imageToolDefs` |

一键回归：`node scripts/guards/12b-image-lab.mjs`（应 23/23）。
