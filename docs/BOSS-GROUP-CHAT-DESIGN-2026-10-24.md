# BOSS 会话 · 群聊形态设计（2026-10-24，**待确认，未实现**）

> 在侧栏「新会话 / 搜索任务」下方的功能入口菜单里新增 **「BOSS 会话」** 入口，点开进入**群聊视图**：
> boss 的会话窗口全程置顶在上，群成员的任务更新成流展示在下，可动态拉人/移人、置顶关注某条更新。
> 本文是**实现前的设计定稿**；已落地的账本内核（派活/审查/打回/预算）不重做，这里只做"群聊形态"这层皮。

---

## 0 与已有 P0 内核的关系

| 已有（不重做） | 本期新增 |
|---|---|
| 群账本（建群/派活/审查/打回/作者锁/升级） | **群聊视图**（boss 置顶 + 成员更新流） |
| 成员常驻会话（`(groupId, memberId) → threadId`） | **动态成员管理**（拉人/移人 + 状态同步） |
| 事件回投（成员事件 → boss 会话） | **置顶机制**（置顶某成员的更新，跨重启） |
| 预算/停滞扫描（宿主 tick） | **侧栏入口与群条目**（功能菜单 + 会话列表） |
| 设置页看板（账本只读 + 决定） | boss 工具面补 `group_add_member` / `group_remove_member` |

⛔ 真相源不变：`boss-groups.json` 唯一，群视图只读它 + 订阅事件广播；建群/派活/审查的唯一写入方仍是
boss 会话的工具（看板与群视图都不设第二写入方）。

## 1 会话结构（三条边，各归各位）

```
┌─ 侧栏 ──────────────────────────────────────────────┐
│  [新会话]                                            │
│  [搜索任务]                                          │
│  ▼ 功能入口（top 位置）                               │
│    ⚡ 定时任务  🖥 前端开发  …  👑 BOSS 会话  ← 新增     │
│  ─────────────────────────────────────────────────  │
│  会话列表：                                           │
│   📁 群「落地页上线」  ← 群条目（虚拟，非 thread）        │
│      ├ 👑 boss（真实会话，唯一可对话）                   │
│      ├ 写手（隐藏成员会话）                             │
│      └ 前端（隐藏成员会话）                             │
└─────────────────────────────────────────────────────┘
```

- **boss thread**：真实引擎会话（一条 thread 一个 agent 的约束不动）。用户对 boss 说话、boss 调工具、
  群事件回投——全部发生在这里。
- **成员 thread**：隐藏常驻会话（复用现有 `(groupId, memberId) → threadId` 映射），不进群视图正文，点「看轨迹」弹独立窗口。
- **群条目（新）**：侧栏里的一个**虚拟节点**（不是 thread）。数据来自 `boss-groups.json`，
  渲染规则挂进现有会话聚簇（`src/lib/thread-source.mjs` 的来源分类体系，新增来源 `boss-group`）。
  成员会话按现有"被调度会话缩进挂在发起方下面"的机制，挂在群条目下。

## 2 群视图（点开群条目 / 点 BOSS 会话入口进入）

```
┌────────────────────────────────────────────────────────┐
│ 👑 boss 会话窗（全程置顶，固定高度可拖）          [折叠▾] [➕拉人] [➖移人] │
│ ┌────────────────────────────────────────────────────┐ │
│ │ [boss 对话流：用户消息 / boss 回复 / 群事件卡]            │ │
│ │ [输入框]                                             │ │
│ └────────────────────────────────────────────────────┘ │
│ 📌 置顶更新（0~3 条，横排卡片）                            │
│ ┌──────────────┐ ┌──────────────┐                       │
│ │ 写手 · 三屏完成 │ │ 前端 · 2/4 步  │                       │
│ └──────────────┘ └──────────────┘                       │
│ ──────────────────────────────────────────────────── │
│ 群成员更新流（独立滚动）                                    │
│  14:02 写手  已交活「首页文案」（尝试 2/3）→ 审查中          │
│  13:58 前端  正在做 · 第 2/4 步「布局」 · 12 秒前有进展       │
│  13:51 boss  打回「首页文案」：缺 CTA（写手已锁，换文案二组）   │
│  …                                                    │
└────────────────────────────────────────────────────────┘
```

- **boss 置顶（需求 3①）**：群视图是上下两区布局——上区固定（不随下区滚动），下区独立滚动。
  上区渲染的就是 boss 那条真实 thread 的对话（复用现有会话渲染），可拖高度、可折叠成一条标题。
- **成员更新流（需求 3②）**：来源 = 群事件（`events[]`）+ 成员运行态广播（`boss-group` 事件，
  复用 `delegate-run`/`team-run` 的 delta 通道）。每条 = 成员头像 + 名字 + 一句话 + 时间；
  正在跑的成员有**实时行**（"正在做 · 第 n 步 · N 秒前有进展"），完成即变成"已交活"卡。
- **置顶更新（需求 3②）**：每条成员更新卡有「置顶」动作，置顶后固定显示在 boss 区正下方的
  横排卡片带（最多 3 条，超出挤掉最旧），存进 `group.pinnedEventIds`（宿主落盘，跨重启）。
  置顶是**视图层收藏**，不影响任务状态。

## 3 成员管理（需求 2）

| 动作 | 通道 | 语义（规则在 state.ts，守卫真跑） |
|---|---|---|
| 拉人 | boss 工具 `group_add_member`（群视图也有 ➕ 按钮，**同一通道**） | 新建成员档案 → 下一次派活时建会话；成员 ≤6 不变 |
| 移人 | boss 工具 `group_remove_member` / 群视图 ➖ | **会话保留**（轨迹不丢），成员标 `removed`：不再接新活，从成员行隐到「已移除」分组 |
| 移人时在跑 | 二选一（默认 A） | **A 等它交活**：结果照常回投、照常审查，之后不再派活；**B 立即停**：stop 该成员回合 + 任务按"失败"落账，boss 收事件决定重派 |

**状态同步**：成员增删/状态变化都走现有 `boss-group` 广播 → 群视图、看板、办公室三处同帧刷新；
`boss-groups.json` 是唯一真相源（120ms 合并写已有）。移除者未交活的任务按现有**作者锁/换人**逻辑走
（移除者视为锁死，`pickReassignee` 天然跳过）。

## 4 消息流转（需求 4）

```
成员 turn 增量 ──▶ 群视图实时行（正在输出 N 字）        ← delta 广播（复用 team-run 通道）
      │
      ▼ turn 完成
   交活事件 ──▶ ①群事件流（更新卡）  ②回投 boss（[群事件]，boss 能接着指挥）
      │
      ▼ 独立评审（宿主驱动）
   通过 → done 卡；打回 → 打回卡 + 换人重派 + 回投 boss
```

- **boss 汇总**：boss 被唤醒的三个点不变（拆解 / 打回决策 / 重规划）；日常进度由宿主 tick 供给
  （停滞 / 预算 / 转后台），群视图的"实时行"不需要 boss 花一次模型调用。
- **持续跟进**：用户在 boss 窗随时插话（"前端那边到哪了"→ boss 调 `group_status`）；群视图的
  实时行让**用户不用问也能看到**。
