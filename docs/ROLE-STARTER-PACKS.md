# 角色起步包（Starter Packs）方案（2026-11-18）

> 用户口径：「新手进来一眼就知道我们这个产品的优势——设计师能直接装哪些工具、开发者能联动哪些功能、
> 自媒体博主能直接用哪些专家」。⇒ 不是"功能清单"，是**按人分的起步路径**。
>
> 与 `FEATURE-LINKAGE-PLAN.md` 的关系：那份解决"功能之间连不起来"，这份解决"人进来不知道从哪下手"。
> 两者共用同一个目标：**让已有能力被看见、被串起来**。

## 二、三个角色包（首发）

每个包 = **一句话优势** + **装什么** + **找谁** + **怎么串** + **第一个任务**。
⛔ 全部引用上面已存在的 id，**不新造能力**。

### A. 开发者 ·「一个能直接改你仓库的开发小组」

- **一句话**：不是"又一个 AI 编辑器"——你给它仓库，它拆活、写码、自查、交回结论。
- **装**：`engine` · `ponytail`（写代码模式）· `bundled-tool`（Git/Node/Python）· `cli-agents`（可选）· `computer-use`（可选）
- **找谁**：洞明（代码审查，单人）· 承枢团（软件交付 4 人：产品/架构/开发/测试）
- **技能**：`code-review-graph`、`dongming-code-review`、`ponytail*` 系列
- **怎么串**：终端 → 会话（读仓库）→ 代码审查（洞明）→ 群聊派活（承枢团）→ 产物归档（改动清单 / 报告）
- **第一个任务**（预填）：「读这个仓库，给我一张模块图，并列出 3 个最该先修的问题（附文件和行号）」

### B. 设计师 ·「草图 → 出图 → 组件 → 交付 一条链」

- **一句话**：不用在 5 个工具之间拷文件——草图进来，落地页、配图、组件清单一起出去。
- **装**：`image-lab` · `computer-use` · `bundled-tool`（图片/视频处理）· `markitdown`（可选，读设计规范）
- **找谁**：执矩团（产品设计 4 人：研究/决策/流程/视觉）· 画意（电商生图）· 呈象（演示）· 鲁班（3D，可选）
- **技能**：`frontend-ui-design`、组件库（`component-library`）、设计库（`design-library`）
- **怎么串**：草图/AI 画布（`ui-sketch`）→ 图像实验室出图（`image-lab`）→ 组件库沉淀 → 群聊让执矩团出落地稿 → 产物归档
- **第一个任务**：「按这张草图生成 3 版落地页，输出组件清单和每版的取舍理由」

### C. 自媒体博主 ·「选题 → 成稿 → 成图 → 排期 → 复盘 一条龙」

- **一句话**：一个工作台管全流程，专家团分工干活——不是你一个人从头写到尾。
- **装**：`media-desk`（自媒体工作台）· `image-lab` · `bundled-tool`（FFmpeg 等）· `computer-use`（采集，可选）
- **找谁**：文枢团（内容 4 人）· 剪承团（视频 4 人）· 知微（流量预测）· 拔节团（增长，可选）
- **怎么串**：灵感采集 → 工作台选题 → 成稿（文枢团）/ 成片（剪承团）→ 配图（image-lab）→ 排期（`settings-schedule`）→ 复盘（观澜团数据）
- **第一个任务**：「按我的账号定位（一句话），出 7 天选题 + 3 条成稿开头，并排进本周排期」

### 备选包（第二批）

- **研究/分析**：观澜团 + `kb-embedding` + `markitdown` + 知识库；任务是「把这些 PDF 建成知识库并出一份对比表」
- **办公/汇报**：呈象（演示）+ `markitdown` + 产物档案；任务是「把这些材料做成 10 页汇报」

## 三、交互设计（三步之内看到效果）

1. **首次进入**：`profile-onboarding` 之后追加一屏「你主要用它做什么？」——三张大卡（开发 / 设计 / 自媒体）+「其它」；可多选。
2. **生成起步清单**：首页顶部出现一张卡，列出该包的 4~6 项，每项带状态与按钮：

```
你的起步清单 · 开发者                    完成 3/6
[✓] 写代码模式 (ponytail)         已装
[ ] CLI 智能体                     [安装]
[✓] 代码审查专家 · 洞明            [开会话]
[ ] 软件交付团 · 承枢 + 4 人        [建群]
[ ] 第一个任务                     [开始]
```

3. **每项都能直达**：`安装` → 复用运行时安装通道；`开会话` → `openThread` + 预填；`建群` → 复用专家团创建（自动带上团成员）；`开始` → 新建会话并预填该包的第一个任务。
4. **完成态**：全部完成后卡片收成一行「开发者起步 · 已完成 ✓」，可点开重做；⛔ 不反复弹窗。

## 四、实现落点（不新增能力，只做装配）

| 层 | 落点 | 说明 |
|---|---|---|
| 数据（唯一真相源） | `electron/features/starter-packs/packs.ts` | 声明式：`{ id, name, tagline, components[], teams[], experts[], skills[], chain[], firstTask }`，全部引用既有 id |
| 主进程 | `electron/features/starter-packs/ipc.ts` | 三通道：`starter-packs:list`（清单+本机状态）/ `apply-item`（装组件 / 建群 / 装技能）/ `status`（逐项校验） |
| 渲染 | `src/features/starter-packs/` | 起步清单卡 + 角色选择屏；入口两个（首次引导末尾、侧栏常驻一行） |
| 复用 | 现有通道 | 组件安装走 `runtime:*`；建群走团队创建；开会话走 `openThread` + 预填；⛔ 不新造安装器 |
| 引导 | `profile-onboarding` | 追加一屏；答案存 localStorage（可改） |

## 五、判据（什么样算做对了）

1. **装配可校验**：`apply-item` 之后逐项复查真实状态（组件版本存在 / 团队存在于 `expert-teams.json` / 技能目录存在），全部通过才显示 ✓ —— ⛔ 不许"点了就显示完成"。
2. **id 不许编**：守卫校验 `packs.ts` 里每个 component/team/skill id 都能在 registry / teams / skills 里找到（负向断言：编一个假 id 必须红）。
3. **新手 90 秒内出第一个结果**：从选角色到第一条会话产出 ≤ 90 秒（自动化验收：点角色 → 装 1 项 → 点第一个任务 → 断言会话已带预填文本）。
4. **三个包各自可独立完成**：不依赖另一个包的安装结果。

## 六、与联动方案的分工

| 文档 | 解决 |
|---|---|
| `FEATURE-LINKAGE-PLAN.md` | 功能之间**连不起来**（跨页跳转、空态动作、记忆可见） |
| 本文 | 人进来**不知道用什么**（角色 → 装配 → 第一个任务） |
