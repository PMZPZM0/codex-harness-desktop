## 一、三个作用域（这份记忆**谁能读到**）

| 作用域 | 含义 | 覆盖 | 隔离边界 |
|---|---|---|---|
| **cross-project** 跨项目一致 | 换项目也读到**同一份** | 仅 `USER.md` 用户档案 | 无隔离 —— 全项目共用一份（存应用数据目录） |
| **project** 项目维度共享 | 本项目**全体会话与智能体**共享 | `project/MEMORY.md` 宪法 · `lessons/*.md` 纪律 · `project/BACKGROUND.md` 背景 · `logs/*.md` 日志 · `rollups/*.md` 卷宗 · `archive/*.md` 冷存档 | **项目根目录** —— 别的项目读不到 |
| **session** 按会话独立 | 只有这一路会话（或这一个团）读得到 | `memory.json` 碎片池 + fabric 命名空间条目 + 角色记忆 | **会话 id / 团队 id** —— 别的会话读不到 |

**一句话记法**：*用户档案跨项目一致，项目规则与工作纪要按项目共享，其余按会话独立。*

## 二、各文件明细

| 文件 | 名称 | 作用域 | 存储范围 | 共享边界 | 隔离原则 | 注入档 |
|---|---|---|---|---|---|---|
| `USER.md` | 用户档案 | 跨项目一致 | 应用数据目录（**全项目唯一一份**） | 所有项目、所有会话 | 不随项目切换而变 —— 这就是"跨项目一致"的实现方式 | resident |
| `project/MEMORY.md` | 项目宪法 | 项目共享 | 项目 `.codex-harness/memory/` 下，每项目一份 | 本项目全体会话与智能体 | 其它项目读不到 | resident |
| `lessons/*.md` | 纪律与记忆 | 项目共享 | 一个分类一个文件（纠错 / 坑 / 约定 / 偏好） | 同上 | 同上 | **first**（排最前） |
| `project/BACKGROUND.md` | 项目背景 | 项目共享 | 每项目一份 | 同上 | 同上 | resident |
| `logs/*.md` | 每日日志 | 项目共享 | 一天一份 | 同上 | 同上 | **last**（超预算先丢） |
| `rollups/*.md` | 月度卷宗 | 项目共享 | 一月一卷 | 本项目（按需查阅） | 其它项目读不到 | never |
| `archive/*.md` | 冷存档 | 项目共享 | 每项目一个归档目录 | 本项目（可回溯） | 其它项目读不到；⛔ 不进注入 | never |
| `memory.json` | 碎片池 | **按会话独立** | 条目带来源会话 | 写入它的那个会话 | 别的会话看不到来源不是自己的条目 | never |

### 会话级条目（不在内置记忆文件里，同属"按会话独立"）

| 命名空间 | 谁共享 | 说明 |
|---|---|---|
| `private__<threadId>` | 一个会话 | 主会话 / 子智能体 / 专家各一份，**互不可见** |
| `team__<teamId>` | 一个专家团 | 团内成员互通，**团外读不到** |
| `project__…` | 项目 | 与项目级同域，但以**条目**形态存在（可检索） |

## 三、优先级顺序（注入时谁先谁后）

```
[Harness 常驻记忆]
 ① lessons 纪律    ← 排最前：坑与纠错比背景更容易被反复踩，被截断的代价最大
 ② USER.md 用户档案  ┐
 ③ project/MEMORY.md ├ 常驻（各自预算独立：user 8000 / project 24000 / background 12000 / lessons 16000）
 ④ BACKGROUND 背景   ┘
 ⑤ logs 日志       ← 排最后：超预算时**按天从最旧丢**（⛔ 不按字符砍尾）
[常驻记忆结束]
   rollups / archive / memory.json   ← 不进注入（需要时靠检索 / 召回）
```

**总闸**：常驻四部分之和（60 000）+ 日志段（30 000）= **90 000**（基准 ×1）。
容量倍率（×1/2/4/8/10/16）**同比放大各段与 total**，`logDays`（回灌几天）不参与放大。
⛔ 这个自洽式（四段之和 + logs = total）是守卫【104】按倍率逐档验算的对象 —— 改档位必须同步改它。

## 四、文件之间：引用 / 继承 / 同步

```
USER.md（应用数据目录 · 全项目一份）
   │ 只读注入（所有会话都读到）
   ▼
┌────────────── 项目维度共享（本项目全体会话）──────────────┐
│                                                          │
│  project/BACKGROUND.md ──升格（稳定下来）──► project/MEMORY.md │
│         ▲                                      ▲          │
│         │                                      │ 精炼结论  │
│  logs/*.md ──蒸馏──► rollups/*.md ──────────────┘          │
│         │                  │                              │
│         │                  └─原文移位─► archive/*.md（终态·可回溯）│
│         │                                                 │
│  lessons/*.md ◄── 捕获链（纠错 > 坑 > 偏好 > 约定）          │
│         └──升级为技能──► 技能库（可复用，脱离记忆预算）        │
└──────────────────────────────────────────────────────────┘
                           ▲
                           │ 成型后归入
┌──────────── 按会话独立（session）────────────┐
│  memory.json 碎片池 ── TTL 淘汰（记录进 pruned.jsonl） │
│  fabric 条目（private__ / team__ / project__）          │
└────────────────────────────────────────────────────────┘
```

- **引用**：上层**只读**引用下层产物 —— `project/MEMORY.md` 引用背景与卷宗的结论，注入时所有会话都读得到常驻四段。
- **继承**：`logs → rollups → project/MEMORY.md`（日志蒸馏成卷宗，卷宗精炼进宪法）、`BACKGROUND → MEMORY.md`（背景稳定后升格）。
  ⛔ 继承是**蒸馏**不是复制：原文进 `archive/` 留底，不进注入。
- **同步**：只在**同文件内**压缩（合并同主题、删过时）；跨文件只走上面两条"蒸馏升格"路径。
  ⛔ 没有"`project/MEMORY.md` 回写 `USER.md`"这种反向同步 —— 用户档案只由用户改（跨项目一致的前提）。

## 六、架构评审与演进（2026-10-10，11-20 复述）

### 6.1 被评审的草图与结论

用户草图是一维堆叠：`共享池（项目规则 / 用户档案 / 工作纪要）` → `已生效技能、插件展示`
→ 三个并列会话（普通 / 专家 / 专家团，各自"独立的完整分层记忆"+"按日期 年/月/日逐级分类"）
→ `子选项（被调度会话代理）` 同构。

**结论：方向正确，但把"分层机制"复制到了每个会话。**

| 草图元素 | 判断 | 依据 |
|---|---|---|
| 共享池 vs 独立记忆的二分 | ✅ 正确 | 就是本规则的 `cross-project`+`project` vs `session` |
| 按日期 年/月/日 逐级分类 | ✅ 正确（但属**项目级**） | 日志按天 + 卷宗按月；⛔ 不是每会话各存一份 |
| 「每个会话各存一套完整分层记忆」 | ⛔ **不采纳** | 项目记忆是**全项目一套**；会话级只存**条目**（碎片池 + fabric）。每会话各一套 ⇒ 宪法/纪律出现 N 份副本，必然漂移 |
| 「已生效技能、插件展示」与记忆并列 | ⛔ **移出记忆架构** | 技能/插件是**能力面**；与记忆只有一条关系：纪律攒够 → **升级为技能**（出边，见 6.3） |
| 子选项（被调度会话代理）挂在"普通会话"下 | ⛔ 层级不对 | 它是**派生执行体**，派出者可能是主会话 / 专家 / 团 ⇒ 改按 `originThreadId`（派出者）+ `depth`（嵌套层）表示 |

### 6.2 采纳并已落地的改进

1. **二维化**：作用域（横）× 文件（纵）—— 见 §一 / §二
2. **共享池拆两层**：跨项目（仅 `USER.md`）/ 项目级（其余六类文件）
3. **项目记忆唯一一份**；会话级只存条目；会话视角靠**读时按来源会话切分**（`originThreadId`）
4. **纪律 → 技能库**画成出边（记忆中心 → 规则 →「出边：记忆 → 能力」）
5. 每条边标明引用 / 继承 / 同步与**是否进注入**（§二 表的 `inject` 列）
6. **被调度会话标注派出者**与嵌套层（记忆中心 → 会话记忆 → 被调度会话，展开可见）
7. **落地映射**：§五 表 —— 图上每一项都能指到实现

### 6.3 记忆与能力的关系（唯一的出边）

```
lessons 纪律 ──满水位前先升级──► 技能库（全局 $CODEX_HOME/skills · 项目级 <cwd>/.codex/skills）
                                  ↑ 脱离常驻注入预算，变成可复用能力
纪律原文 ──升级完再压缩──► 同文件内压缩
```

⛔ 技能 / 插件清单**不放在记忆架构里**（它们是能力面）—— 只在记忆侧保留这一条出边，
说明"记忆攒够之后去哪"。反向不成立：技能不会回流成记忆。
