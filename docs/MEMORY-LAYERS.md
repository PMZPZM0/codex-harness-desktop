# 记忆分层管理规则（Memory Layers）

> 唯一真相源（结构化）：`src/lib/memory-scope-rules.mjs`
> 层表与预算（实现）：`electron/memory-layers.ts`（`MEMORY_PYRAMID` / `MEMORY_BUDGET`）
> 会话级条目（实现）：`electron/memory-fabric.ts`（`namespaceOf(scope, ownerId)`）
> 守卫：`11l-memory-fabric`（层 id 一致 / scope 与注入档分类）、`10-memory-audit`【104】（预算自洽）
>
> ⛔ 三处**分工固定**：规则表描述"怎么分"，层表描述"存在哪/谁写/去哪"，fabric 描述"会话级怎么隔离"。
> 改一处必须同轮核对另外两处（守卫会把漂移打红）。

## 一、三个作用域（这份记忆**谁能读到**）

| 作用域 | 含义 | 覆盖 | 隔离边界 |
|---|---|---|---|
| **cross-project** 跨项目一致 | 换项目也读到**同一份** | 仅 **L0 用户档案** | 无隔离 —— 全项目共用一份（存应用数据目录） |
| **project** 项目维度共享 | 本项目**全体会话与智能体**共享 | **L1 宪法 · L2 纪律 · L3 背景 · L4 日志 · L5 卷宗 · L6 冷存档** | **项目根目录** —— 别的项目读不到 |
| **session** 按会话独立 | 只有这一路会话（或这一个团）读得到 | **L7 碎片池** + fabric 命名空间条目 + 角色记忆 | **会话 id / 团队 id** —— 别的会话读不到 |

**一句话记法**：*用户档案跨项目一致，项目规则与工作纪要按项目共享，其余按会话独立。*

## 二、八层明细

| 层 | 名称 | 作用域 | 存储范围 | 共享边界 | 隔离原则 | 注入档 |
|---|---|---|---|---|---|---|
| **L0** | 用户档案 | 跨项目一致 | `USER.md`（应用数据目录，**全项目唯一一份**） | 所有项目、所有会话 | 不随项目切换而变 —— 这就是"跨项目一致"的实现方式 | resident |
| **L1** | 项目宪法 | 项目共享 | `project/MEMORY.md` | 本项目全体会话与智能体 | 其它项目读不到 | resident |
| **L2** | 纪律与记忆 | 项目共享 | `lessons/<分类>.md`（一个分类一个文件） | 同上 | 同上 | **first**（排最前） |
| **L3** | 项目背景 | 项目共享 | `project/BACKGROUND.md` | 同上 | 同上 | resident |
| **L4** | 每日日志 | 项目共享 | `logs/YYYY-MM-DD.md` | 同上 | 同上 | **last**（超预算先丢） |
| **L5** | 月度卷宗 | 项目共享 | `rollup/YYYY-MM.md` | 本项目（按需查阅） | 其它项目读不到 | never |
| **L6** | 冷存档 | 项目共享 | `archive/*.md` | 本项目（可回溯） | 其它项目读不到；⛔ 不进注入 | never |
| **L7** | 碎片池 | **按会话独立** | `memory.json`（条目带来源会话） | 写入它的那个会话 | 别的会话看不到来源不是自己的条目 | never |

### 会话级条目（不在金字塔文件里，同属"按会话独立"）

| 命名空间 | 谁共享 | 说明 |
|---|---|---|
| `private__<threadId>` | 一个会话 | 主会话 / 子智能体 / 专家各一份，**互不可见** |
| `team__<teamId>` | 一个专家团 | 团内成员互通，**团外读不到** |
| `project__…` | 项目 | 与金字塔项目级同域，但以**条目**形态存在（可检索） |

## 三、优先级顺序（注入时谁先谁后）

```
[Harness 常驻记忆]
 ① L2 纪律        ← 排最前：坑与纠错比背景更容易被反复踩，被截断的代价最大
 ② L0 用户档案    ┐
 ③ L1 项目宪法    ├ 常驻（各层预算独立：user 8000 / project 24000 / background 12000 / lessons 16000）
 ④ L3 项目背景    ┘
 ⑤ L4 日志        ← 排最后：超预算时**按天从最旧丢**（⛔ 不按字符砍尾）
[常驻记忆结束]
   L5 / L6 / L7   ← 不进注入（需要时靠检索 / 召回）
```

**总闸**：常驻四层之和（60 000）+ 日志段（30 000）= **90 000**（基准 ×1）。
容量倍率（×1/2/4/8/10/16）**同比放大各层与 total**，`logDays`（回灌几天）不参与放大。
⛔ 这个自洽式（四层之和 + logs = total）是守卫【104】按倍率逐档验算的对象 —— 改档位必须同步改它。

## 四、层与层之间：引用 / 继承 / 同步

```
       ┌──────────────────────── 跨项目一致 ─────────────────────────┐
       │  L0 用户档案（USER.md · 应用数据目录 · 全项目一份）            │
       └───────────────────────────────┬────────────────────────────┘
                                       │ 只读注入（所有会话都读到）
                                       ▼
   ┌────────────────────── 项目维度共享（本项目全体会话）──────────────┐
   │                                                                │
   │   L3 项目背景 ──升格（稳定下来）──► L1 项目宪法                  │
   │        ▲                              ▲                        │
   │        │                              │ 精炼结论                │
   │   L4 每日日志 ──蒸馏──► L5 月度卷宗 ───┘                        │
   │        │                    │                                  │
   │        │                    └─原文移位─► L6 冷存档（终态·可回溯）  │
   │        │                                                       │
   │   L2 纪律 ◄── 捕获链（纠错 > 坑 > 偏好 > 约定）                 │
   │        └──升级为技能──► 技能库（可复用，脱离记忆预算）           │
   └────────────────────────────────────────────────────────────────┘
                                       ▲
                                       │ 成型后归入
   ┌──────────────────── 按会话独立（session）──────────────────────┐
   │  L7 碎片池（memory.json）── TTL 淘汰（记录进 pruned.jsonl）      │
   │  fabric 条目（private__ / team__ / project__）                  │
   └────────────────────────────────────────────────────────────────┘
```

- **引用**：上层**只读**引用下层产物 —— L1 引用 L3/L5 的结论，注入时所有会话都读得到 L0-L4。
- **继承**：`L4 → L5 → L1`（日志蒸馏成卷宗，卷宗精炼进宪法）、`L3 → L1`（背景稳定后升格）。
  ⛔ 继承是**蒸馏**不是复制：原文进 L6 冷存档留底，不进注入。
- **同步**：只在**同层**压缩（合并同主题、删过时）；跨层只走上面两条"蒸馏升格"路径。
  ⛔ 没有"L1 回写 L0"这种反向同步 —— 用户档案只由用户改（跨项目一致的前提）。

## 六、架构评审与演进（2026-10-10）

### 6.1 被评审的草图与结论

用户草图是一维堆叠：`共享池（项目规则 / 用户档案 / 工作纪要）` → `已生效技能、插件展示`
→ 三个并列会话（普通 / 专家 / 专家团，各自"独立金字塔记忆"+"按日期 年/月/日逐级分类"）
→ `子选项（被调度会话代理）` 同构。

**结论：方向正确，但把"分层机制"复制到了每个会话。**

| 草图元素 | 判断 | 依据 |
|---|---|---|
| 共享池 vs 独立记忆的二分 | ✅ 正确 | 就是本规则的 `cross-project`+`project` vs `session` |
| 按日期 年/月/日 逐级分类 | ✅ 正确（但属**项目级**） | L4 按天 + L5 按月；⛔ 不是每会话各存一份 |
| 「独立金字塔记忆」×4 | ⛔ **不采纳** | 金字塔（L0–L7）是**分层机制**、全项目一套；会话级只存**条目**（L7 + fabric）。每会话各一套 ⇒ L1/L2 出现 N 份副本，必然漂移 |
| 「已生效技能、插件展示」与记忆并列 | ⛔ **移出记忆架构** | 技能/插件是**能力面**；与记忆只有一条关系：L2 攒够 → **升级为技能**（出边，见 6.3） |
| 子选项（被调度会话代理）挂在"普通会话"下 | ⛔ 层级不对 | 它是**派生执行体**，派出者可能是主会话 / 专家 / 团 ⇒ 改按 `originThreadId`（派出者）+ `depth`（嵌套层）表示 |

### 6.2 采纳并已落地的改进

1. **二维化**：作用域（横）× 分层（纵）—— 见 §一 / §二
2. **共享池拆两层**：跨项目（仅 L0）/ 项目级（L1–L6）
3. **金字塔唯一一份**；会话级只存条目；会话视角靠**读时按来源会话切分**（`originThreadId`）
4. **`L2 → 技能库` 画成出边**（记忆中心 → 分层规则 →「出边：记忆 → 能力」）
5. 每条边标明引用 / 继承 / 同步与**是否进注入**（§二 表的 `inject` 列）
6. **被调度会话标注派出者**与嵌套层（记忆中心 → 会话记忆 → 被调度会话，展开可见）
7. **落地映射**：§五 表 —— 图上每一项都能指到实现

### 6.3 记忆与能力的关系（唯一的出边）

```
L2 纪律与记忆 ──满水位前先升级──► 技能库（全局 $CODEX_HOME/skills · 项目级 <cwd>/.codex/skills）
                                     ↑ 脱离常驻注入预算，变成可复用能力
L2 原文 ──升级完再压缩──► 同层压缩
```

⛔ 技能 / 插件清单**不放在记忆架构里**（它们是能力面）—— 只在记忆侧保留这一条出边，
说明"记忆攒够之后去哪"。反向不成立：技能不会回流成记忆。
