# WorkBuddy 更新日志对照分析（5.6.0 / 2026-09-19 为最新）

> 输入：`https://www.codebuddy.cn/docs/workbuddy/Changelog`（45 个版本条目，2026-05-29 ～ 2026-09-19）。
> 本文只做一件事：从那份日志里挑出**对一个「本地 Electron 宿主 + Codex 引擎」形态的 harness 真正有用**的
> 条目，逐条与我们当前实现对照（结论都附代码位置或 grep 方法），最后给出可落地建议。
> ⛔ 不照抄与形态不符的部分（跨设备同步 / 积分订阅 / 企业 Teams 项目 / 灵感做同款 / 行业 Buddy）——
> 我们没有云端账号体系，那些条目的前提在我们这里不成立。

---

## 一、结论先行

1. **那份日志 90% 是 bug 修复列表，能迁移的"新特性"其实不到 15 条**；真正有价值的是它**反复修同一类问题**
   所暴露的痛点地图（滚动/历史补齐、上下文压缩、队列语义、输入框光标与草稿、权限弹窗被流式覆盖）。
2. 我们**已经在同类问题上领先或等价**的有 7 项（尤其"运行中发消息不许打断上一轮""切回会话补齐离开期间内容"
   "工具调用去重""环境自检"）——日志里对应的是补丁式修复，我们是结构性保证。
3. 我们**真缺**的，集中在三类：**可观测性（构建指纹 / 交付物面板 / 切换与压缩的时间线锚点）**、
   **输入体验细节（Ctrl+Enter、听写不打断手打、每轮注入当前时间）**、**长期没做的形态（Worktree 并行任务）**。

## 三、建议清单（按可落地程度排序）

### P0 —— 半到一个会话就能做完，收益立刻可见

**P0-1 把「构建指纹」透出到界面（防"跑的是旧构建"）**
- 现状：侧栏只有 `当前版本 v…`。
- 改法：在版本行旁加「构建时间 + `dist/assets/*.js` 主 chunk 名/hash 前 6 位」（`app:engine-info` 已有同类信息，补一条 IPC 或复用即可），并给「复制诊断信息」按钮。
- 判据：上一轮真实事故——用户跑的实例不是最新构建，我**无法自证**，只能靠"请你重启一次"。有了指纹，一眼可对。
- 风险：极低（只加只读信息）。

**P0-2 支持 Ctrl/Cmd+Enter 换行（可保留 Shift+Enter）**
- 现状：`part09/01-seg.tsx` —— `Enter && !shiftKey ⇒ 发送`。
- 改法：提交判据加 `!event.ctrlKey && !event.metaKey`；如需可配置，走现有设置注册表加一行。
- 判据：新用例「Ctrl+Enter 后输入框仍保留内容、未产生新回合」。

**P0-3 语音听写不打断手动编辑**
- 现状：`part01/01-session-drafts-voice.tsx` 用 `setPrompt(base + 字幕)` 整段覆盖。
- 改法：记录听写**起点与上一次写入的长度**，回填时只替换该区间，保留用户同时打的内容（把"用户手打"并入 base）。
- 判据：真机用例「听写中手动先打 3 个字 → 字幕到达 → 手打的字仍在」。

**P0-4 每轮注入当前时间**
- 现状：`electron/` 无时间注入。
- 改法：在每轮上下文（或 `developer-instructions` 的会话段）加一行「当前时间：YYYY-MM-DD HH:mm（周X）」。
- 判据：向模型问"今天是几号/昨天算哪天答"不再瞎猜；且**必须是每轮注入**（长会话跨天才有意义）。

### P1 —— 一个迭代内做，属于"把已经做对的东西变得看得见"

**P1-5 时间线锚点：模型/供应商切换分隔线**（压缩那条**我们已有**，见下方更正）
- 依据：WorkBuddy 5.1.0/5.1.1 有模型切换分隔线；我们已有"缓存命中率骤降时解释原因"的 `Status.tsx`，缺的是**对话里的锚点**。
- 判据：切换模型后新回合前出现分隔线（含新模型名）。
- ⚠️ **09-23 更正（写这份报告时的误判）**：上下文压缩分隔线**我们早就有了** ——
  `01-timeline.tsx` 的 `compact-divider`（带 running/success/error 三态、可关闭的常驻卡）
  以及时间线里 `item.type === "contextCompaction"` 的分隔项。当初只 grep 了 `model-switch` 就下结论，
  属"没查全就断言缺失"。
- ⛔ **模型切换分隔线不能靠"引擎 sideband 事件"**（`06/02-seg/02-model-thread-settings.tsx` 的注释
  声称存在，实际没有）：要么在 `turn/started` 时把当时的模型标签记进 per-turn 映射再比对相邻回合，
  要么接受"只在用户主动切换的那一刻插一条"。

**P1-6 交付物面板（对标 `present_files`）**
- 现状：有预览面板，无「交付物」概念。
- 改法：引擎侧暴露「宣告交付物」的出口（工具或约定标记），宿主把它收集成侧栏/右侧的产物列表，只显示**最终交付**、隐藏中间文件，点击联动预览。
- 判据：一次任务产出 3 个文件 + 20 条中间写入 ⇒ 产物栏只列 3 条。

**P1-7 错误横幅的「一键自查」**
- 现状：`app:doctor` / 重启台账都在，但用户看不到入口。
- 判据：错误条上点「自查」→ 出「引擎进程 / CODEX_HOME / 端口 / 最近一次重启原因」结论，可复制。

**P1-8 闲置能力提醒**
- 改法：统计技能/连接器最近一次被使用的时间，超阈值给一条可关闭的提示 + 一键停用。
- 说明：与我们已有 `memory-hygiene` / `self-review`（技能侧）同族，属于"卫生提示"而非新机制。

### P2 —— 值得排期，但要么工程量大、要么优先级低

- **P2-9 Worktree 任务**（5.4.0）：`每个会话一个 worktree` ⇒ 多会话并行改同一仓库互不干扰。这正是本项目长期痛点（两个仓库 + 并行实例 + 只能靠"只 add 自己的文件"纪律兜住）。工程量：中高（工作区分配、分支/合并策略、清理）。
- **P2-10 消息级删除 / 按消息分享**：目前只有整会话删除与回合 fork。
- **P2-11 MCP 整份配置视图**：保留我们更细的 `deny/ask/allow`，补一个"整份可编辑 + 保存即生效"的入口（注意：我们的配置改动大多需要引擎重启/推迟重启，这条要有"何时生效"的明确提示）。
- **P2-12 沙箱/审批拦截原因可视化**：把"为什么被拦"（命中哪条规则）讲清楚。

## 四、明确**不抄**的部分（形态不符，抄了是负担）

- 跨设备/多端会话与配置同步、移动端连接电脑、锁屏远程 —— 我们是单机 harness，没有账号与云端。
- 积分/订阅/夜间折扣/Token Plan —— 无计费体系。
- 企业 Teams / 项目看板 / 网盘 / 审批流 —— 无组织形态。
- 灵感做同款、行业 Buddy、创意设计（图片/视频/3D）—— 与"编码 harness"定位无关。
- 弱网/休眠唤醒/企业代理的一大批修复 —— 我们的失败面在**本地引擎**（spawn / RPC / rollout / 沙箱），
  对应的是我们的【55】【91】【96】那类守卫，而不是网络重试。
