# 去误报协议

> 收敛自 alibaba/open-code-review 的 `review_filter_task_*` 提示词（Apache-2.0）。
> 这是整套审查方法论里**最值钱的一环**：审查的产出质量不取决于找到多少问题，而取决于**留下的每一条是否站得住**。

## 第一原则：默认全部放行

你（审查者）手上有完整代码库与上下文工具；事后复核的人**只有 diff**。所以"我看着不对"远不足以删掉一条意见。

两类错误的代价**不对等**：

- **留下一条错意见** —— 审阅者花几秒钟读一遍，划掉。
- **删掉一条对意见** —— 一个真实缺陷被静默销毁，它永远不会被人看到，也没人知道它曾被提出。

所以：**证据不到"证明"的程度，就放行。**

以下说法**都不构成删除理由**：

- "看起来可疑"
- "我无法验证"
- "价值不高"
- "被指的代码我看着没问题"
- "换作我不会提这条"
- "我不同意它的建议" / "我觉着这样写也可以"
- "我确认不了" —— 无法验证 ≠ 不正确
- "它引用错了行号 / 代码片段抄得不精确" —— 判断它的**主张**是否成立，不要judge它的引用
- "它说得有点糙" —— 只要核心主张成立就保留

## 只有两种依据可以删除

### 依据 A：意见指向的代码**不在它声称的那个文件的 diff 里**

这条意见描述的那个符号、语句或结构，在它自己 `path` 指向的文件里**根本找不到**。判据**只对该文件成立**——同一个结构出现在同组的兄弟文件里**不能救它**。典型形态：

- 它讨论某个函数的实现体，而那个文件只有声明或引用
- 它讨论宿主语言逻辑，而那个文件是查询/构建/标记/配置文件，压根没有此类逻辑
- 它声称某段代码被删除、或某处做了错误处理，但该文件的 diff 里没有这种变化

### 依据 B：diff 里**有一行字面**与意见的核心主张直接矛盾

- 说某标识符未被使用，而 diff 显示它在用
- 说某个检查/断言/分支缺失，而 diff 里有
- 说某值是硬编码的，而 diff 显示它来自变量
- 说某物被声明两次/遮蔽了外层同名变量，而 diff 里只有一处声明
- 陈述的条件或类型关系，被 diff 的原文直接反驳

⛔ **矛盾必须能从 diff 原文一眼读出，不能靠推理链得出。** 需要两步以上推理才能推出的"矛盾"＝没有矛盾 → 放行。

## 保护性主题：一律不删

以下主题**先于正确性判断**直接豁免——哪怕你很确信这条意见是错的，也**放行**：

| 主题 | 说明 |
|---|---|
| **内存安全** | 分配大小、缓冲区长度、索引越界、off-by-one、use-after-free、空指针解引用 |
| **并发** | 锁与锁模式、原子操作、数据竞争、未被遵守的同步前提 |
| **链接与声明一致性** | `static` 与否、声明与定义不符、缺 `extern` |
| **行为/兼容性变更** | 旧代码产生的消息/字段/状态码/默认值，新代码不再产生；错误路径改变；计数器更新时机被挪动 |
| **函数接受却从不使用的参数** | |

这些是"删错代价最高、而你的自信最不可靠"的类别——包括你对自己"语言/编译器/运行时不会像它说的那样表现"的自信。**在保护性主题上，你没有自信的资格。**

## 复核顺序（每步命中即停，不要回头用后面的步骤推翻）

1. **保护性主题豁免** —— 命中上表 → **放行，停止**（不评估对错）。
2. **价值豁免** —— 属于风格/格式/命名/空行/注释措辞/可读性，且**陈述属实** → **放行，停止**（价值低不是你的事，过滤价值不是你的职责）。
3. **依据 A** —— 描述的代码不在其 subject 文件的 diff 里 → 删除。
4. **依据 B** —— 有**一行** diff 原文直接反驳其核心主张（无需推理链）→ 删除。
5. **兜底** —— 放行。

> 第 4 步前，把同组**每个**文件都搜一遍意见描述的东西，不要只搜它引用的那个片段。**引错行但描述的东西确实存在 = 这条意见是对的，保留。**

## 对审查者的应用方式

审查时你既是提出者也是复核者。落笔每条意见前，自己走一遍上面五步：

- 有没有踩到"不构成删除理由"的自我说服？（"我觉着没问题"不是理由）
- 我能不能指出**具体哪一行**证明它错？指不出 → 保留。
- 它属于保护性主题吗？（内存安全/并发/声明一致性/行为变更/未用参数）→ **保留**，别挑战自己的不确定判断。
- 我说不出**触发条件** → 降级为"疑似（条件：…）"并说明需要什么信息才能确认，**不要当成缺陷报**。

## 两处容易混淆的口径（务必分清）

**① 复核别人的意见时**：不按"价值"过滤。一条风格意见只要**陈述属实**就保留——低价值不等于不正确，判断价值不是复核者的职责。

**② 你自己写最终报告时**：`low` 档只保留**确实有价值**的（能防止误解、能避免真实维护成本）。纯风格偏好、与项目约定无关的个人口味 —— **直接不写进报告**，也不要写成"以下小问题我略过了"再列一遍（那等于把噪声换个包装又塞回给用户）。
